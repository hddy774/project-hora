## 시장과 주주 경영

- **분야별 회사 5개:** 기존 10개를 보존하고 20개를 추가합니다. [회사 구성표](docs/COMPANIES-v1.3.0.csv)의 사업·수요·뉴스 민감도와 비용·배당 정책을 사용합니다. 새 시장과 새 회사는 자사주 50%/은행 50%로 시작하고 투자자는 현금으로 실제 은행 물량을 매수합니다. 기존 저장의 보유 주식은 보존합니다.
- **가치 창출과 현금 순환:** 기업이 실물 경제에 상품·서비스를 판매하고 비용·임금·설비 투자·은행 이자·법인세를 실제 계정 간 송금합니다. 정부 재정과 거래소 수수료도 예산 내에서 경제에 돌아옵니다. 주가를 매월 강제로 올리지 않습니다.
- **실제 배당:** 기업 현금에서 주주에게 배당을 지급하고 배당세·배당락을 반영합니다. 공매도자는 대여자에게 대체배당을 지급하며 부족액은 부채로 남습니다. 수익률은 배당을 포함하고 임금·소비와 같은 외부 유출입을 제외합니다. 매매 이익은 시즌 손익통산·손실 이월·환급을 적용합니다.
- **현실 주식 개념:** 시가총액, 발행/상장/유동 주식, 창업자 지분, 자사주, 액면가, 배당수익률, 월 EPS와 12개월 PER·BPS·PBR을 표시합니다. 12개월 미만 PER은 연 환산 추정으로 표시합니다. 적자 PER과 자본잠식 PBR은 계산 불가로 표시합니다.
- **기업행동:** 액면분할·주식 병합·주식 교환 합병, 기본 IPO·유상증자·자사주 매입/소각을 지원합니다. 보유·원가·대여·공매도·예약을 함께 조정하고 단주를 현금 정산합니다. IPO와 증자는 실제 납입, 자사주는 기업 재원으로 처리합니다. 가격 지수는 상장·증자·합병의 수량 변화 효과를 조정합니다. 과거 통계는 당시 가격과 주식 수를 유지합니다.
- **경제를 읽는 AI:** 모든 기관이 능력에 따라 가치·뉴스·추세·역추세·단타·초단타·분산·위험 관리를 혼합합니다. 기업 이익·배당과 왕복 비용을 판단에 연결하고, 하락장에는 현금·비중·부채·공매도 헤지를 관리합니다. 개인은 가격 흐름·관측 거래량에만 반응하고 가치/재무/배당을 분석하지 않습니다.

- **주주 의결:** 월별 72시간 안건 공개 후 AI 주주가 실보유 지분으로 성장/가치/방어, 설비/비용/유동성, 재투자/자사주/배당 정책을 결정합니다. 자사주와 대여 청구권의 이중 의결을 제외하고 결과를 월말 경영에 반영합니다. 기업은 여유 현금으로 기본 자사주 목표 65%를 추구합니다.
- **투자 기간과 현금 목표:** 초단기 1시간~1일 미만, 단기 1일~10일 미만, 장기 10일 이상을 계획·실제 보유 기간으로 나눕니다. 장기는 20일·30일 이상 유지할 수 있고 중요한 뉴스·위험은 즉시 재검토합니다. 평가 총자산의 5~30% 현금 목표는 실제 주문으로 접근하며 예약·담보·수수료를 보호합니다. 공급 부족과 새 시장 출발에서는 실제 비중이 목표를 벗어날 수 있습니다.
- **시장 안정 은행:** 현금 완충과 실제 재고·대여 예약을 지키며 양방향 호가를 제출합니다. 과열에는 공급, 하락에는 제한된 매수를 사용합니다.
- **파산과 새 세대:** 자본잠식·운영 불능·자금 소진을 정산하고 기업 식별자/투자자 세대를 교체합니다. 출자는 실제 경제 자금에서 지급하고 미회수 채권·옛 재무·손실·이름을 보존합니다. 새 회사/투자자의 출자금을 투자 이익으로 더하지 않습니다.

## 통계와 관찰 화면

하단 화면은 **시장 / 자산 / 랭킹 / 인물 / 통계 / 시즌 / 뉴스**입니다. 회사 상세에서 재무제표 5종의 표·그래프·원형표, 주식 수와 재무비율, 과거 결산과 배당/분할/합병 기록을 봅니다. 기초·합병 변경 재무의 예상 손익과 실제 월말 결산을 구분합니다.

기관 랭킹은 수익률·순수익·순자산·현금·거래량·거래금액을 사용합니다. 투자 방식으로 분류하지 않습니다. **현재 시즌·전체·전일·5일·10일·30일·90일·1년·직접 지정 기간**을 제공합니다. 자산/현금 랭킹과 구성 원형표는 현재 잔액, 나머지는 선택 기간의 실제 시작/끝을 사용합니다.

기본 통계는 반복 그래프/표를 줄여 총수익 지수·시가총액·기관/개인 투자 손익 그래프를 선택해 표시합니다. 임금·소비·재출자를 제외하고 이전 세대 손실을 포함하는 손익을 비교합니다. 시장/분야 누적 거래량과 거래대금은 기업 교체 후에도 줄지 않습니다. 긴 기간은 주요 지표의 극값을 포함하여 제한된 지점으로 조회하며 원본 기록은 삭제하지 않습니다. 기록이 없는 구간은 연결하지 않습니다. 회사/분야의 과거 시가총액은 현재 주식 수로 다시 계산하지 않습니다.

대표의 10개 능력은 각각 50점에서 시작하며 시즌 포인트로 성장합니다. 상대 수익률의 1/2/3/5/10/20/30/40/50/100위 구간에서1~10포인트와 신용 보상을 받습니다. 51~100위도1포인트를 받습니다. S/A/B/C/D 직원의 수·역할과 실제 채용비·급여를 반영하고 대표 50%/조직 50%로 기관 능력을 합성합니다. 대표 프로필에는 거래량·거래금액·수익률을 기록합니다. 대표 성향, 기관 공매도, 정책별 세금·수수료·금리·규제·보조금, AAA~C 9등급의 대출(자기자산 100~30%, 저신용 고금리), 대표 간 공동 작전·적발/실패 벌금은 유지합니다. **`자산 → 대표·은행`**의 기관·능력/직원/시즌 보상/투자 기간 탭, `통계 → 정부·은행`, `뉴스 → 대표 상호작용`에서 확인합니다.

200명의 개인 지갑은 운영 법인·정부·은행의 자금과 별도입니다. 인물 탭에서 직무별10개 능력·보수·후원·개인 벌금·프로필을 보고 그림을 눌러 확대합니다. 랭킹은 종합/투자자/경영자/정치인/금융인 분야별 상위3명을 표시합니다.

투자사는 분야 애널리스트·집행 트레이더·포트폴리오·위험·준법·재무·거시·퀀트8직무 직원을 고용합니다. 대표가 수석 분석가로6업종 기밀 리포트를 만들고, 기간·상하한 가격·위험 성향과 종목 예산을 갖는 투자 계획을 실행합니다. 다른 기관 AI는 내부자료를 읽지 못합니다. 관찰자는 선택 투자사의 소유자 관점으로 봅니다.

경영자는 실제 예산으로 사업을 착수·추진·납품하고 성과를 월 결산에 반영합니다. 자사주·은행·개미를 포함한 발행 지분의 상위3대 보유 투자사만 내부 사업 진행을 봅니다. 신규 뉴스에는 실제 인물과 원인 활동 기록이 있습니다. 정부와 은행 수장은10~30일마다 선거로 교체되고, 모든 새 정책·후원 법률은200명의 표결로 결정합니다. 양당은 각25명이며 시즌 종합 순위로 다음 시즌1~10표를 받습니다. 통계에는 개미 재무 옆에 기관 재무를 제공합니다.

## 시간과 파일 보관

Android 8.0 이상 ARM64 기기와 x86_64 에뮬레이터를 지원합니다. 서버·계정·API 키·인터넷 권한 없이 실행합니다.

| 배속 | 게임 1시간 | 게임 1일 | 30일 시즌 |
|---|---:|---:|---:|
| 1× | 5초 | 120초 | 60분 |
| 2× | 2.5초 | 60초 | 30분 |
| 5× | 1초 | 24초 | 12분 |
| 20× | 0.25초 | 6초 | 3분 |
| 50× | 0.1초 | 2.4초 | 72초 |
| 100× | 0.05초 | 1.2초 | 36초 |

휴장 없이 하루 24시간 거래합니다. 시즌은 30일이며 자산과 성적이 이어집니다. 앱을 벗어나면 저장하고 일시정지합니다. 닫힌 실제 시간은 자동 진행하지 않습니다. 고배속의 실제 처리량은 기기 성능에 따라 달라집니다. 틱별 작업 시간과 최대 따라잡기 시간을 제한해 화면 작업을 분산하고, 미처리 대기 시간은 저장합니다. 완료한 게임 시간과 그 통계는 버리지 않습니다.

앱 전용 **`history-v5.sqlite`**에 모든 완료 게임 시간의 시장·회사·100개 기관 기록을 보관합니다. 현재 복원 상태·통계·기업행동·결산·시즌·주총·파산을 같은 WAL 트랜잭션으로 확정합니다. DB/ZIP 형식 5를 확장하고 상태 JSON은 8입니다. 기관 성장·직원·보유 기간·보상과 실행 규칙도 저장합니다. 개미의 사용하지 않는 개별 그래프·랭킹 복사본은 저장하지 않습니다. 반복되는 숫자는 열별로 한 번, 비어 있지 않은 보유·원가·예약은 희소 좌표로 저장하며 기존 행 형식도 읽습니다. 시장 상태가 달라지면 약 1초 간격으로 백그라운드에서 저장용 분리 복사본을 준비하고 JSON 직렬화·파일 쓰기는 단일 백그라운드 작업자가 처리합니다. 변화가 없는 자동 저장은 생략하며 일시정지·내보내기는 현재 진행을 저장합니다. 기록 대기가 커지거나 쓰기가 실패하면 진행을 일시정지하며 미확정 기록을 버리지 않습니다. 강제 종료 시 마지막 확정 이후의 진행과 기록은 함께 되돌아갈 수 있습니다.

자동 정상 백업, 손상 원본 보존, 체크섬 검증과 복구를 제공합니다. 기존 `market-v4.json`/v3/v2와 남은 시즌 파일은 원본을 보존하며 이전합니다. 구버전 일별 기록은 일별로 보관하고, 없던 시간·지표는 만들어 채우지 않습니다. v5 DB/ZIP을 열 때 확정 기록을 새 JSON으로 재기록하지 않아 통계 체크섬과 새 시간 저장을 이어갑니다. 새 회사의 공모는 기존 투자자에게 무료 주식을 주지 않습니다.

`통계` 아래의 **전체 기록 내보내기**는 사용자 선택 위치에 DB·체크섬 manifest·시장 CSV를 ZIP으로 저장합니다. 가져오기는 크기·구성·해시·앱 ID·확정 시간·회계를 검사하고 현재 기록을 먼저 보존합니다. 새 시장을 시작해도 이전 시장 기록을 자동 삭제하지 않습니다. 이전 시장으로 직접 전환하는 목록은 후속 기능이며 별도 내보낸 파일로 복원할 수 있습니다.

## 회계 기준과 개발

- 현금: **투자사·개미 + 인물 개인 지갑 + 기업 + 은행 + 정부 + 거래소 + 실물 경제 = 초기 시스템 현금**. 가격 상승은 현금 생성으로 기록하지 않습니다.
- 주식: **참가자 보유 + 은행 재고 + 창업자 지분 + 자사주 = 발행 주식**. 공매도 상환 의무는 별도 부채입니다.
- 시가총액은 가격 × (발행 주식 − 자사주), 유동 주식은 여기에 창업자 지분을 제외합니다.
- 투자자/기업의 재무상태·손익·현금흐름·자본변동을 대조합니다. 원형표는 양수 구성, 흐름 원형표는 절댓값이며 음수는 표와 그래프에서 확인합니다.
- 소프트웨어 검증은 수익을 보장하지 않습니다. 경기·뉴스·정책에 따라 손실·배당 중단·회복과 하락 시즌이 발생합니다.

`.github/workflows/checks.yml`은 엔진·회계·저장·그림과 Android Release 빌드를 검사하고 가속 에뮬레이터에서 실제 구형 기록·추가 인물/그림·100배속 재개를 대조합니다. `.github/workflows/release.yml`은 **병합된 v1.7.0 태그**로 APK 생성 → 서명 → 앱 ID/버전/인증서 검증 → APK 하나 업로드 → 다운로드 재검증 → 최신 릴리스 공개를 수행합니다. 공개 릴리스를 덮어쓰지 않습니다.

main에 새 앱 버전이 병합되면 Actions가 해당 병합 커밋의 버전 태그를 만들고 자동 배포합니다. 같은 버전 태그가 이미 있으면 다시 배포하지 않습니다. 사용자의 기존 키 없는 배포 요청에 따라 이 경로는 `generate_signing_key=true`와 같은 새 일회용 키 방식을 사용합니다. 생성 키·비밀번호는 저장소/아티팩트에 포함하지 않고 종료 시 제거합니다. 릴리스 본문에는 APK 체크섬·공개 인증서 지문·빌드 소스를, Actions 내부 아티팩트에는 검증 로그와 `SIGNING-INFO.txt`를 기록합니다. 키가 재사용되지 않으므로 다음 새 키 배포도 재설치가 필요합니다. 수동 재시도는 병합된 `tag=v1.7.0`과 `generate_signing_key=true`로 실행하며, 업로드 중단 시 `signed_run_id`로 이미 검증한 서명 APK 아티팩트를 복구할 수 있습니다.
