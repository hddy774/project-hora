# 선로만상록

두 반선 시조에서 시작해 인물·가족·가문·종문·왕조·경제가 자라나는 선협 생태계 시뮬레이션입니다. 플레이어는 세계의 모든 실제 정보를 관찰하거나, 인물에 빙의하거나 새 인물을 만들어 세계 안에서 행동합니다.

> **0.2.1 통합 기획 / 2026-10-30**
>
> 현재는 **게임 엔진 없이 C#으로 개발**합니다. Android에 적합한 성능·메모리·저장 구조를 설계하고, 이후 Unity에 연결할 수 있도록 핵심과 플랫폼 경계를 분리합니다. Unity 프로젝트·IL2CPP·Burst 도입은 향후 전환 단계입니다.
>
> 아래 새 시스템은 개발 목표입니다. 기존 Windows 구현과 새 기획의 구현·검증 상태를 구분합니다.

공법·특성·자원 이름과 윤회 세부 조건은 새 설계 제안입니다. 확률·기간·계수는 근거와 실험으로 보정하며 기존 정본이나 완료 코드로 취급하지 않습니다.

각 경로는 강점·부담·공법/자원·다음 경지의 연결을 가지며 이름만으로 품질·승리·비승을 보장하지 않습니다. AI는 부족한 정보를 조사하고 다단계 준비·실패 원인 교정·협상/돌봄 인계를 실제 시간·권한·예약으로 처리하도록 설계합니다. 재해·통로 폐쇄·영맥 변화·필수품 독점에 따른 생태계 적응과 실패도 기획합니다.

## 관찰 모드와 플레이 모드

- **관찰 모드:** 잠재 자질·비밀·AI 판단·실물 원장·계보·전생까지 모든 실제 게임 정보를 조회합니다.
- **플레이 모드:** 조작 인물이 실제로 아는 정보와 권한만 사용합니다. 이동·탐색·수행·제작·거래·관계·가족·정치·전투는 AI와 같은 규칙을 따릅니다.

검색·정렬·개수·그래프도 권한 필터 후 계산합니다. 관찰에서 플레이로 전환해도 관찰 정보를 인물의 기억으로 자동 복사하지 않습니다. 빙의는 기본적으로 기존 인물의 신원·관계·재산을 보존한 조작권 전환입니다.

## 기술 기반과 리팩토링

현재 우선순위는 **엔진 없는 C# 기준 구현 → 계측 → 알고리즘/자료 배치 개선 → 필요한 계산만 최적화**입니다.

- Core/Simulation은 UI·파일 경로·OS·Unity API에 의존하지 않습니다.
- 안정 ID·정수 시간·명시적 난수·단일 쓰기 권위를 유지하고, 명령과 불변 조회를 분리합니다.
- 확장 구획 SoA·사건 스케줄·지역/관계/시장 인덱스·공유 정의·희소 상태·지연 조회로 동적 인구와 콘텐츠를 처리합니다.
- 기존 WPF·Windows 전용 SQLite는 외곽 어댑터로 분리합니다. 현재 `net10.0` 코드의 공용 API/언어를 조사해 향후 Unity 호환 경계를 준비합니다.
- SIMD·병렬 배치·선택적 C++/Rust 커널은 스칼라 C# 정답과 전체 비용을 비교합니다. 네이티브 도입 자체를 목표로 삼지 않습니다.
- Android의 메모리·중단/재개·강제 종료·checkpoint 복구·발열/배터리를 고려합니다. 실제 Android/Unity 빌드·성능 통과는 아직 확인하지 않았습니다.

C#도 JIT/AOT로 기계어가 됩니다. [Microsoft SIMD](https://learn.microsoft.com/en-us/dotnet/standard/simd)와 [Native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/), [BenchmarkDotNet](https://github.com/dotnet/BenchmarkDotNet), ECS·직렬화 후보를 연구합니다. Android Native AOT의 실험적 상태도 구분합니다.

향후 Unity 전환 때 [IL2CPP](https://docs.unity3d.com/6000.0/Documentation/Manual/IL2CPP.html), [Burst](https://docs.unity3d.com/Packages/com.unity.burst@1.8/manual/index.html)·Job System·필요 시 Entities를 별도로 검증합니다. 현재 Unity 의존성을 추가하지 않습니다.

기존 인물별 indexed 행동 스케줄과 장기 수행 계획을 재사용·확장하며, 새 범용 계획기나 스케줄러로의 일괄 교체를 전제로 삼지 않습니다. 리팩토링 전 원본 fixture·명령열·상태 hash·비용 기준선을 먼저 확보합니다. 이후 확장 실험에서는 예열과 측정 세계를 분리하고, 버퍼 수명·취소 사건 누적·실패한 계산 배치·낡은 조회 응답을 검증합니다. 계산은 임시 결과를 확인한 뒤 한 번만 적용하며, 플레이 UI는 관측 시점·표시 세대·알려진 물품 속성을 사용합니다.

연구는 **가설 → 기준선 → 최소 실험 → 정확성/성능 → 채택·수정·기각 → 근거 보존**으로 지속합니다. 출처·버전·라이선스·기기/런타임·실험 SHA·한계를 남기고, PC 수치를 Android 성능으로 대신하지 않습니다.

## 기존 구현과 저장

현재 저장소에는 .NET 10/WPF 기반 Windows 코드와 기존 수행·전투·시장·본명법보·생애/윤회·관찰·SQLite 저장 코드가 있습니다. 문서 수정 전 코드 기준은 `main@9b0fda8`의 `VERSION 0.0.22`, 통합 전 UI 브랜치는 `8031bb3`의 `0.0.27`입니다. 이번 문서 갱신은 기능 구현·새 테스트 성공·VERSION 변경을 뜻하지 않습니다.

기존의 ‘10,000명 고정 시작·관찰 전용·전원 랭킹 1위·모바일 제외’는 0.2.1 목표에서 개편합니다. 10,000명은 성장 후 성능 시험 규모이며 시작 인원이나 강제 인구 상한이 아닙니다.

이전 저장의 연속 플레이는 필수 지원 대상이 아닙니다. 이전 파일을 보존하고 호환 여부를 표시하며, 새 0.2.1 자체 저장·복원·중단 복구는 검증합니다.

기존 Windows 저장/로그 경로:

- 저장: `%LocalAppData%\ChroniclesOfMyriadImmortalPaths\saves\<slot-id>\world.db`
- 로그: `%LocalAppData%\ChroniclesOfMyriadImmortalPaths\logs`

## 기존 Windows 코드 빌드

다음은 현재 WPF 코드의 명령입니다. Unity·Android 빌드 명령이 아닙니다.

```powershell
dotnet build Chronicles.slnx -c Release
dotnet run --project src/Chronicles.Desktop/Chronicles.Desktop.csproj
dotnet run --project tests/Chronicles.Tests/Chronicles.Tests.csproj -c Release
```

기존 `로컬_빌드_및_실행.cmd`와 [로컬 점검 절차](docs/LOCAL_TESTING.md)는 Windows 실행 기록을 참고하세요.
