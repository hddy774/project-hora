# ALPHA EXCHANGE · 알파 익스체인지

## 실행과 시간

Android 8.0 이상 ARM64 기기와 x86_64 에뮬레이터를 지원합니다. APK는 그래픽과 C# 런타임을 포함하며 서버·계정·API 키·인터넷 권한이 필요 없습니다. 외부 생성형 AI나 실제 시세를 사용하지 않습니다.

하단 화면은 **시장 / 자산 / 기관 / 통계 / 시즌 / 뉴스**입니다. 배속 버튼을 누르면 1→2→5→20→50→100 순서로 바뀝니다.

| 배속 | 게임 1시간 | 게임 1일 | 30일 시즌 |
|---|---:|---:|---:|
| 1× | 5초 | 120초 | 60분 |
| 2× | 2.5초 | 60초 | 30분 |
| 5× | 1초 | 24초 | 12분 |
| 20× | 0.25초 | 6초 | 3분 |
| 50× | 0.1초 | 2.4초 | 72초 |
| 100× | 0.05초 | 1.2초 | 36초 |

하루 24시간, 휴장 없이 거래합니다. 앱을 벗어나면 저장하고 일시정지하며 닫힌 동안 진행하지 않습니다. 15초 간격, 시즌 전환, 일시정지 때 자동 저장합니다. 기기 성능에 따라 고배속 화면 처리 시간이 달라질 수 있습니다.

## 시장과 회계

기관의 초기 자기자산은 1,000만 원, 개인은 10만 원이며 현금과 주식으로 구성됩니다. 개인은 독립 장부를 가지고 매시간 300~800명이 순환 참여합니다. 개인별 순위는 제공하지 않습니다.

가격·시간 우선 지정가 매칭, 부분 체결, 주문 예약, 취소·만료를 사용합니다. 실제 상대 주문과 체결할 때만 가격이 변하며 먼저 대기한 주문의 가격으로 체결합니다. 기관의 호가는 시간 시작 가격을 기준으로 계산하여 한 시간 안의 연쇄 증폭을 줄입니다. 매수는 올림, 매도는 내림 호가를 사용하며 1,000원 미만에서는 1원 단위로 회복 가능한 호가를 냅니다.

은행은 종목별 500주의 대여 재고와 10억 원, 정부는 1억 원으로 시작합니다. 이는 참가자 초기 자산과 별개인 시스템 초기 자원입니다. 공매도 체결 시 은행 재고에서 매수자에게 주식이 이동하고, 상환 시 은행으로 돌아옵니다. **참가자 보유 주식 + 은행 주식 재고 = 발행 주식 수**가 유지됩니다. 공매도자는 별도의 주식 상환 부채를 가집니다.

**참가자 현금 + 은행 현금 + 정부 현금 + 거래소 수수료 = 초기 시스템 현금**을 유지합니다. 대출·상환, 이자, 세금, 보조금, 벌금은 계정 사이 이동입니다. 양쪽 체결 수수료는 원 단위 올림입니다. 양의 실현 매매 이익에 세금을 부과하며 공매도 이익은 상환 시 과세합니다. 이자 미납은 대출 부채, 벌금 미납은 벌금 부채에 반영합니다. 기관 보조금은 보유 주식 평가액과 정책 비율, 정부 가용 현금에 따라 지급됩니다.

기관 재무상태표의 자산은 현금+주식, 부채는 공매도+대출+미납 벌금입니다. 실현/평가손익에서 수수료·세금·이자·대여료·벌금을 빼고 보조금을 더한 손익과 현금흐름을 각각 대조합니다. 기업 결산은 기업 자체의 영업 장부이며 기업 배당을 참가자에게 지급하는 기능은 이번 범위에 포함하지 않습니다.

원형표는 양수 구성만 표시하고, 현금흐름/자본변동의 원형표는 절댓값 규모를 표시합니다. 음수 흐름과 실제 손익은 표·막대 그래프에서 확인합니다.

## 시즌·기록·저장 이전

30일마다 성적을 기록하고 자산과 시장을 다음 시즌으로 이어갑니다. 기업 결산은 종료 시즌의 뉴스를 반영하고 새 정책은 다음 시즌에 적용합니다. 기본 시즌 순위는 시즌 시작 자기자산 대비 수익률입니다.

현재 상태는 `market-v4.json`에 원자적으로 저장하고 직전 정상본을 `.bak`에 보관합니다. `market-v3.json`과 `season-v2.json` 원본은 남기며 기관 ID·현금·기존 보유 주식·장부·시즌 성적을 이전합니다. 새 종목의 대여 재고, 능력, 정책, 기업 재무를 초기화합니다. 구버전에 기록이 없던 기관별 거래량/거래금액과 시장 비교 그래프는 이전 시점부터 기록합니다. 기존 시즌 수익률의 시작 자산은 유지합니다.

완료 시즌의 100개 순위·일별 통계·기업 결산·정책은 `seasons/<시장 ID>/season-XXXXXXXX.json`에 보관합니다. 화면 메모리는 가격/자산 120시간, 일별 통계 121개, 체결 160개, 뉴스 40개, 대표 작전 80개, 최근 결산/정책/기관 성적 12개로 제한합니다. 오래된 시즌은 파일에서 조회합니다. 전체 통계의 누적 기준은 계속 유지되며 전체 그래프는 최근 120일만 표시합니다. 부족한 비교 기록은 실제 시작/끝과 안내를 표시합니다.

## 그래픽과 개발

대표는 여성 70명·남성 30명, 서로 다른 그림 100개입니다. `src/AlphaExchange.Android/Assets/portraits/`의 PNG 아틀라스 10장과 manifest를 사용합니다. [아트 설명](art/ART-DIRECTION-v1.1.0.txt).

[개발 계획](docs/PLAN-v1.2.0.md) · [검증 결과](VERIFICATION.txt)

```text
src/AlphaExchange.Core/       호가·회계·혼합 AI·경제·시즌·통계·저장
src/AlphaExchange.Android/    네이티브 화면·그래프·인물·터치
tests/AlphaExchange.Checks/  체결·회계·신용·공매도·AI·16시즌·이전 검사
.github/workflows/checks.yml  엔진·그림 검사와 Android Release 컴파일
```

.NET SDK 9.0.318, Android workload, JDK 17, Android Platform 35 / Build Tools 35.0.0이 필요합니다. 최소 API 26, 호환성 대상 API 34를 유지합니다.

```bash
dotnet workload install android --skip-manifest-update
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk-17
./build.sh
python3 scripts/check-artwork.py
```

엔진 검증은 `dotnet run --project tests/AlphaExchange.Checks -c Release`로 실행합니다. 기본 로컬 APK는 개발 서명입니다. 기존 배포 앱에 덮어쓰기하려면 같은 배포 키로 서명해야 합니다. 키·비밀번호와 빌드 출력은 저장소·소스 ZIP에 포함하지 않습니다.

## GitHub Actions APK 생성과 배포

`.github/workflows/release.yml`은 병합된 `v1.2.0` 같은 기능 태그로 엔진/그림 검사 → Release APK 생성 → 기존 키 서명 → 인증서/앱 ID 검사 → APK·소스·체크섬 업로드 → 다운로드 재검증 → 최신 릴리스 공개를 실행합니다. Actions 화면에서 기존 태그로 수동 재실행할 수도 있습니다.

저장소 Actions Secrets에 `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`를 등록합니다. 서명 인증서 SHA-256은 기존 v1.1.0과 같아야 합니다. 키가 없거나 인증서가 다르면 배포 단계가 실패하며, 만들어진 unsigned APK와 정확한 태그의 소스 ZIP은 실행의 빌드 Artifact에 남습니다. 비밀번호와 키는 로그·저장소·릴리스에 포함하지 않습니다.
