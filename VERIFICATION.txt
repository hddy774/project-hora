GITHUB ACTIONS APK BUILD AND RELEASE
.github/workflows/release.yml builds from a merged v*.minor.0 tag, reruns core
and artwork checks, uploads an unsigned APK/source artifact, signs with the
selected key, verifies that key's certificate and the app identity,
creates a draft release, uploads APK/source/checksums, downloads and checks every
asset, then publishes it as the latest release. The actual workflow run includes
CORE-CHECKS.txt, ARTWORK-CHECKS.txt, APK-VERIFICATION.txt, APK-BADGING.txt and
SIGNING-INFO.txt. The signed APK/source/reports are also kept in an Actions
artifact for recovery; no key or password is included.

The original-key mode requires ANDROID_KEYSTORE_BASE64,
ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS and ANDROID_KEY_PASSWORD
(documented legacy aliases also work). Its expected certificate SHA-256,
verified against downloaded v1.1.0 APK, is:
9fd5aa86793e26beec38948dfae79d1981581f8e54abe0047025a863cc64f722
The first release attempt (37177788666) built successfully but stopped because
all signing settings were empty. The user subsequently explicitly requested
deployment without the existing key. This v1.2.0 uses the manual workflow input
generate_signing_key=true: a fresh RSA-2048 key is generated in the runner temp
directory, used to sign the APK and deleted on exit. The certificate reported in
SIGNING-INFO.txt is compared with the APK certificate. The actual latest run's
checks and signing report are attached to the release.

This new identity cannot update v1.1.0 in place. Uninstalling the old application
can delete local saves. The generated key cannot be reused for another build.
The default mode still requires the original certificate and stops publication
if signing settings are missing or mismatched. The local development signature
is separate and is not used for the GitHub release.
Local signing smoke check: generated mode signed the unsigned Release APK,
matched the exported certificate to apksigner output, retained app ID/version
and ARM64/x86_64 support, and removed both temporary key/certificate files.
Default mode with missing signing settings failed before signing as expected.
Signing keys/passwords and build outputs are excluded from source and main.
