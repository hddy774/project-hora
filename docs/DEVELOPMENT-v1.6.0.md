## 개발 기준

- 기관의 현금 **목표**를 평가 총자산 대비 최소 5%~최대 30%로 설정한다. 매수 예약·공매도 담보·수수료·채무를 따로 보호한다. 신규 전액 현금 출발, 주가 급변, 유동성 부족 때 실제 비중이 목표 밖일 수 있으며 가짜 체결/현금 이전으로 비중을 맞추지 않는다.
- 초단기는 1시간~1일 미만, 단기는 1일~10일 미만, 장기는 10일 이상이다. 경계 24시간/240시간은 각각 단기/장기로 분류한다. 투자 기간에 따라 재평가·회전 비용·가치/뉴스/추세 가중치를 조절한다. 장기는 20일·30일 이상 보유할 수 있고 만기 강제 매도는 없다. 중요한 뉴스·위험·전략 변경은 기간과 관계없이 다시 판단한다.
- 대표의 초기 “전체 50점”은 별도 답변이 없어 10개 능력치 각각 50점으로 동일 시작했다. 관찰 시뮬레이터의 AI 대표가 시즌 포인트를 판단하여 배분하며 플레이어 매매/수동 스킬 조작은 추가하지 않는다.
- 시즌 수익률의 상대 순위를 기준으로 50/40/30/20/10/5/3/2/1위 보상 단계에서 하나를 적용한다. 능력치 포인트와 신용 평가 보너스를 지급하고 지급 내역을 시즌 기록에 남긴다. 거래량만 늘려 보상을 얻도록 하지 않는다. 점수 상한·동률·재출자/파산 세대·재시작 중복 지급을 검증한다.
- 대표 10개 능력과 직원/조직 운영을 각각 약 50%로 합성해 기관 10개 실행 능력을 만들고 실제 주문·뉴스·위험·기간 판단에 사용한다. S/A/B/C/D 직원은 수·등급·역할에 따라 효과가 달라지고 실제 비용으로 고용·급여를 지급한다. 단일 S급 직원의 기본 능력은 대표의 초기 능력보다 낮고 조직 효과에는 인원 증가의 한계 효용을 적용한다.
- 투자 규칙·능력 가중치·보상 표·직원 등급/역할/비용·은행 유동성·화면 갱신 주기는 버전이 있는 오프라인 JSON 규칙 스크립트로 분리한다. C#은 검증과 실행 엔진을 맡고 파일의 값으로 조정한다. 저장에는 실행 규칙 버전을 보존하며 잘못된 규칙/저장 값을 조용히 무시하지 않는다.
- 호가는 실제 미체결 주문만 표시한다. 은행은 가능한 범위에서 양방향 잔량을 보충하며 소유/대여 예약·현금 완충을 넘지 않는다. 제공 가능한 주식이나 자금이 없으면 이유를 표시한다. 거래 정지/자원 부족 상태에 가짜 잔량을 그리지 않는다.
- 성능은 같은 상태/환경의 전후 비용과 새 규칙으로 달라진 매매 경로를 구분해 기록한다. 캐시를 도입할 때 주문 취소·직원·보상·기업행동·불러오기 후 무효화를 확인한다. Linux 처리량을 실기기 FPS 개선으로 표현하지 않는다.

## 금융 자료와 개선 기록

확인한 원문·접근일·게임 적용과 현실/게임 규칙 차이는 `FINANCE-RESEARCH-v1.6.0.md`에 기록한다. 1시간/1일/10일 경계, 보상 포인트와 직원 등급은 사용자 요청에 따른 게임 규칙이다. 실제 금융에서 투자 기간·수수료·호가 스프레드·분산·유동성·리밸런싱을 고려하는 원칙을 판단에 반영한다.
