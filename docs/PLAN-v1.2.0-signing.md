# v1.2.0 배포 — 기존 키 없이 자동 서명

사용자가 기존 서명키 없이 진행하도록 요청했다. Android는 설치에 서명이 필요하므로 GitHub Actions에서 새 일회용 키를 생성해 APK를 서명한다. 이는 이번 배포에 대한 기존 서명 유지 규칙의 명시적 예외이며 앱 ID와 게임 구현은 유지한다. v1.1.0에 덮어쓸 수 없고 기존 앱 삭제 시 로컬 저장이 삭제될 수 있음을 안내한다.

1. 이 계획과 Draft PR을 먼저 등록한다.
2. 수동 Actions 실행에 `generate_signing_key` 옵션을 추가한다. 기본값은 false로 기존 서명 배포를 유지하며, 이번 실행은 true로 지정한다. 생성한 키와 암호는 runner 임시 경로/메모리에서만 사용하고 소스·캐시·Artifact·릴리스에 넣지 않는다. 키는 실행 종료 시 제거하므로 다른 실행에서 같은 서명을 재현할 수 없다.
3. 생성 인증서와 APK 인증서 일치, 앱 ID/버전, 소스 커밋, APK SHA-256을 검사한다. 릴리스에 공개 인증서 지문과 서명 방식, 설치 주의를 첨부한다.
4. 워크플로 구문 검사와 PR CI 통과 후 병합한다. 아직 공개하지 않은 v1.2.0 태그만 새 병합 커밋으로 갱신해 소스 ZIP에 최종 배포 설정/문서를 포함한다. 태그 이벤트는 기존 키 모드이므로 자동 키 모드로 수동 실행하고, 같은 태그의 공개된 릴리스는 덮어쓰지 않는다.
5. GitHub Actions에서 APK 생성·서명·릴리스 업로드·다운로드 SHA-256 검증을 수행한 뒤 최신 릴리스로 공개한다. 공개 상태와 다운로드 가능한 APK를 확인한다.

실행 중간 실패 시 서명된 검사 Artifact를 남겨 같은 APK를 재사용할 수 있도록 한다. 재실행할 때도 공개 릴리스를 교체하지 않으며 새 서명을 사용자에게 숨기지 않는다.

## 공개 단계 복구

Actions 실행 37179111713에서 엔진/그림 검사, APK 빌드, 자동 서명, 인증서/앱 ID/체크섬 검증과 signed-release Artifact 보관이 성공했다. 공개 단계에서 초안 릴리스를 REST의 태그 조회로 확인해 404가 발생했다. 초안 상태는 `gh release view --json isDraft`로 확인하도록 수정한다.

`signed_run_id` 수동 입력으로 보관한 서명 APK/소스/검사 파일을 재사용한다. 이전 워크플로 소스가 main에 병합됐는지, 보관 소스 ZIP의 커밋과 서명 정보가 현재 릴리스 태그와 일치하는지, 모든 파일의 SHA-256과 APK 인증서/앱 ID/버전을 검사한 뒤 업로드한다. v1.2.0 태그는 이미 검증된 APK의 커밋 804208e에 유지하며 새 키나 APK를 만들지 않는다.
