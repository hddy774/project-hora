# v1.3.0 시장 시스템 개선 계획

이번 PR은 현재 시장의 축소 원인을 기록하고 다음 구현의 설계·검증 기준을 정한다. 현재 앱 동작을 변경하거나 릴리스를 배포하는 PR은 아니다. 후속 구현은 이 계획을 기준으로 진행한다.

## 목표

1. 기업의 생산·이익·투자·배당이 투자자와 실물경제의 자금 흐름으로 이어지는 시장을 만든다. 주가를 강제로 올리는 보정 대신 성장·불황·회복이 모두 가능한 모델을 설계한다.
2. 현재 6개 분야마다 회사 5개를 배치해 기본 상장 구성을 30개로 확장한다. 기존 10개 회사·투자자 자산을 보존하고 신규 20개 회사의 사업 특성을 구분한다.
3. 발행주식·유통주식·자사주·시가총액·배당·EPS/PER/PBR·액면분할·주식병합·기업합병을 회계와 가격·차트·공매도에 일관되게 적용한다.
4. 통계를 매 게임 시간 파일에 영구 기록하고 과거 시즌까지 이어서 조회한다. 제한된 메모리 버퍼와 영구 보관 정책을 구분하며, 기록을 버리는 저장 병합은 금지한다.
5. 원인 분석, 회사 구성표, 상세 설계, 단계별 구현 과제, 완료 조건과 재현 가능한 분석 자료를 같은 Draft PR에 정리한다.

## 필수 검증 기준

### 시장·회계

1. 현금 보존은 기업·거래소·실물경제 계정까지 확장한다. 가격 평가 변화는 현금 유입으로 처리하지 않는다. 모든 세금·이자·배당·보조금·벌금의 송금 계정과 수취 계정이 일치한다.
2. 재무 5종과 투자자 순자산/손익/현금흐름이 같은 장부에서 산출된다. 생산·외상·감가상각·재투자·손실을 구분하고 현금 부족 시 지급을 제한한다.
3. 통제된 양의 생산/수요 시나리오에서 실제 이익과 배당을 얻을 수 있고 장기 총수익에 반영된다. 침체 시 손실, 감액, 배당 중단과 회복이 가능하다. 모든 시드/모든 시즌의 주가 상승을 성공 조건으로 삼지 않는다.
4. 뉴스·정책 스트림을 통제한 여러 시드의 36시즌 실험에서 가격/총수익, 현금 분포, 체결률·스프레드, 낙폭과 계정별 유출을 보고한다. 비용 제거만으로 성공했다고 판단하지 않는다.
5. 기관 능력 차이는 공개 정보의 해석·분산·비용·위험 관리에서 검증한다. 단일 투자 방식 고정, 미래 정보 이용, 무조건 매수/매도, 무제한 공매도·차입은 허용하지 않는다.

### 회사·주식 수

1. 카탈로그는 고유 ID/심벌 30개, 분야 6개 각각 5개이며 기존 10개의 ID·이름·분야 매핑을 보존한다. 금융 회사와 시스템 은행을 구분한다.
2. 전체 초기 포트폴리오 예산 안에서 배분하고 모든 참가자의 현금/예약/가용액이 유효하다. 신규 회사 편입은 기존 참가자 자산을 삭제하거나 무료로 늘리지 않는다.
3. 모든 발행·자사주·유통가능 수량이 정의에 맞고 실물 소유 수량과 일치한다. 공매도 채무를 발행주식 수에 이중 합산하지 않는다.
4. 분할/병합은 총 원가·지분·평가액을 보존한다. 원 단위/단주 반올림 차이는 정산표에 공개하고 전체 현금과 권리를 대조한다. 합병의 교환만으로 재평가 이익을 만들지 않는다.
5. 기업행동 때 활성 주문·예약·대여·공매도·담보·신용·과거 비교가 모두 일관된다. 반복 분할 수량 overflow와 중단 후 재적용을 검사한다.

### 통계·저장

1. 같은 RunId의 확정된 시간 구간은 누락/중복 없이 저장된다. 120시간/121일/시즌 경계를 넘어 전체 조회가 이어진다. 과거 가격과 당시 주식 수를 보관한다.
2. 모든 배속에서 `AdvanceHour` 수와 생성 기록 수가 같다. 자동 저장 병합은 상태 스냅샷만 병합하고 중간 시간 레코드를 버리지 않는다.
3. 체크포인트와 통계의 확정 시간이 같으며 강제 종료 주입 검사에서 이전 또는 새 트랜잭션 상태로 복구한다. 손상/용량 부족은 원본 보존과 명확한 오류로 처리한다.
4. v4/시즌 파일 이전은 남은 일별 기록을 가져오고 실제 커버리지를 표시한다. 재이전·백업 복구·새 게임 RunId 분리·내보내기/별도 설치 가져오기를 검사한다.
5. 최소 5년 분량 저장/조회와 30개 종목·10,100참가자·공매도·기업행동을 결합한 부하를 측정한다. 전체 원본을 메모리에 올리지 않고 원본 보관을 지속한다.

### 성능·배포

100배속의 게임 시간 간격은 50ms다. 엔진·불변 상태 캡처·통계 기록 생성 비용과 비동기 I/O 지연을 분리해 측정하고 큐가 계속 커지지 않는지 검사한다. 기존 10개 회사의 성능 수치를 새 30개 회사/SQLite 구현의 검증으로 재사용하지 않는다. 실제 Android 기기에서 FPS·메모리·파일 용량/커밋 지연을 추가 측정한다.

후속 구현은 v1.3.0 기능 버전으로 배포한다. 기존 앱 ID와 저장 이전을 유지한다. 현재 v1.2.0의 서명키가 일회용이므로 업데이트 호환성을 보장하지 않는다. 사용자의 기존 키 없는 배포 지시를 유지하되, APK 재설치가 필요한 배포 전에 기록 내보내기와 복원을 확인하고 삭제 시 데이터 손실을 명시한다.

GitHub Actions의 엔진/회계·그림 검사와 Android Release 빌드, 서명·다운로드 검증을 통과한 구현만 후속 PR에서 병합/릴리스한다. 이 계획 PR은 병합하거나 새 APK를 배포하지 않고 Draft로 남긴다.

## 이 PR에서 확인한 것

- 현재 엔진의 5개 기본 시드와 수수료 0 비교를 각각 36시즌 실행했다. 222개 시작/월말 현금·주식 보존 검사에 통과했다.
- 저장소 안의 재현 CLI를 컴파일·실행했다. 처음 조사한 CSV가 바이트 단위로 일치했고 요약의 모든 재무 수치는 실행 시간을 제외하고 일치했다.
- 회사 CSV의 6×5 구성·기존 10개 매핑·고유 ID/심벌, 문서 내부 링크와 원자료 검사를 통과했다. [검증 기록](analysis/v1.3.0/README.md)을 보관한다.
- GitHub Actions는 현재 앱의 검사/빌드 결과다. 아직 구현하지 않은 v1.3.0 회계·SQLite·기업행동·30개 회사 기능이 검증됐다는 의미가 아니다.
