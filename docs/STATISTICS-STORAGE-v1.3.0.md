# 통계 파일 저장과 연속 기록 설계

상태: 구현 전 제안. 사용자 요구는 통계를 파일에 저장해 시즌 전환, 메모리 기록 제한, 앱 재시작 이후에도 같은 시장의 기록이 이어지도록 하는 것이다.

## 현재 상태와 먼저 복구할 기록

v1.2.0은 `market-v4.json`과 `.bak`에 현재 상태를 저장한다. 완료 시즌의 순위·일별 통계·기업 보고서는 `seasons/<RunId>/season-XXXXXXXX.json`에 이미 보관한다. 현재 상태의 차트 메모리는 120게임 시간, 일별 통계는 121개로 제한되며 전체 그래프는 이 최근 기록만 사용한다.

따라서 완료 시즌 일별 기록이 모두 삭제된 문제로 진단하지 않는다. 첫 작업은 시즌 파일과 현재 일별 기록을 합쳐 전체 기간 조회를 연결하는 것이다. 구버전에서 이미 버린 시간별 가격이나 기록이 없던 회사/기관 지표는 복원할 수 없다. 각 구간의 실제 해상도와 부족 범위를 표시하고 임의의 중간 값을 채우지 않는다.

## 저장 파일과 식별자

최종 저장은 앱 전용 디렉터리의 `history-v5.sqlite` 파일을 사용한다. SQLite는 네트워크 없이 로컬 파일에 기록한다. Android와 코어 테스트에서 사용할 수 있는 제공자·네이티브 패키지·라이선스·백업 지원을 확인한 뒤 의존성을 고정한다. 런타임 다운로드는 하지 않는다.

`RunId`는 새 게임마다 새로 만들고, `Hour`는 시즌별 시간이 아닌 시작부터의 절대 완료 게임 시간이다. 시즌·날짜·시각은 `Hour`에서 계산한다. 재시작이나 시즌 변경으로 0으로 초기화하지 않는다. 종목은 영구 `SecurityId`, 기관은 기존 고정 ID로 식별한다.

| 테이블 | 키 / 내용 | 기록 시점 |
|---|---|---|
| Runs | RunId, 시작일, 엔진/스키마 버전, 마지막 확정 시간, 보관/커버리지 정보 | 게임 생성·확정 |
| MarketHours | RunId+Hour, 시총·가격/총수익 지수·거래량/대금·순자산·현금·부채·계정별 유입/유출 | 완료 게임 시간마다 |
| StockHours | RunId+Hour+SecurityId, 원본 체결/평가 가격·거래량/대금·발행/발행 중/유통가능 수량 | 완료 게임 시간마다 |
| InstitutionHours | RunId+Hour+InstitutionId, 자산·현금·순수익·거래량/대금·부채·배당/비용 누계 | 기관 100개, 시간마다 |
| Daily / Seasons | 시장·기관·개인 집계, 시작/끝 기준과 완료 여부 | 하루/시즌 경계 |
| Reports / Policies / CorporateEvents | SecurityId/시즌 또는 EventId, 재무 5종·정책·기업행동·정산 결과 | 결산/사건마다 |
| Checkpoints | RunId, Hour, 완전한 복원 상태, 버전, 검증 해시 | 해당 시간의 통계와 같은 트랜잭션 |
| Coverage | RunId, 지표, 시작/끝 Hour, hourly/daily/season 해상도, 실제 공백 | 이전·복구·자료 확인 |

개인 10,000명의 시간별 상세 통계를 전부 복제하지 않는다. 개인 집계와 현재 개인 장부는 유지하고, 개인별 장기 이력은 별도 기능으로 둔다. 시간별 총 30개 종목·100개 기관과 시장 집계가 기본 보관 범위다. 누적 수치의 기간 차이는 같은 기준 시점의 자료를 사용한다.

## 기록과 복원 상태를 함께 확정

`AdvanceHour()`의 각 완료 지점에서 불변 통계 레코드를 만든다. 한 화면 프레임에 게임 20시간을 실행해도 20개를 모두 수집한다. UI 갱신·일별 요약·자동 저장 주기와 기록 생성 주기를 분리한다. 분할·배당·합병이 있으면 처리 순서를 정하고 사건 반영 뒤의 스냅샷에 표시한다.

파일 I/O는 단일 작성자가 맡는다. 대기 통계는 전부 큐에 남기며 최신 상태 스냅샷만 병합할 수 있다. 다음 저장은 가장 최근 스냅샷 H와 이전 확정 시간 이후 H까지의 모든 기록을 같이 사용한다. H를 넘는 기록은 다음 저장에 남긴다.

```text
시뮬레이션: ... H-2 기록 → H-1 기록 → H 기록 → 복원 상태 H 캡처
파일 작성자: BEGIN
            이전 확정 이후 ~ H의 시장/종목/기관/사건 기록 INSERT
            체크포인트 H 저장
            Runs.LastCommittedHour = H
            COMMIT
시뮬레이션: 확정 응답을 받은 H 이하 큐 항목만 제거
```

WAL과 내구성 설정을 사용하고 확정 시간·통계·복원 상태를 같은 SQLite 트랜잭션으로 커밋한다. 로그상 성공은 실제 커밋 이후만 표시한다. 시간 기본키/사건 ID는 중복을 막고, 동일 키에 다른 데이터가 들어오면 무시하거나 덮어쓰지 않고 오류로 취급한다. 통계 파일만 앞서가고 시장은 과거 JSON에서 시작하는 두 파일 간 불일치를 피한다.

정상 종료·일시정지·시즌 전환·새 게임 전에는 최종 시간을 캡처하고 flush한다. 정상 재시작은 마지막 확정 상태와 그 시간의 통계를 함께 읽는다. 비정상 종료가 커밋 중 발생하면 이전 확정 시간 또는 완전히 확정된 새 시간 중 하나로 복구한다. 반만 적용된 시간이나 두 번 실행한 기업행동은 없어야 한다.

게임 시간이 이어진다는 것은 복원된 시장 진행과 기록에 내부 공백이 없다는 뜻이다. 갑작스러운 프로세스 종료 때 미확정 메모리 꼬리까지 항상 보존한다고 약속하지 않는다. 마지막 확정 이후의 시장 진행과 통계는 함께 되돌아가고, 파일에 남은 과거 기록은 보존한다. 화면에는 저장 상태/마지막 확정 시각을 보여준다. 앱이 닫힌 실제 시간은 게임 진행으로 자동 생성하지 않는다.

일반 배치 커밋은 실시간 1초를 목표로 하고 강제 중단 시 미확정 꼬리는 최대 15초 이내를 완료 기준으로 삼는다. 100배속에서 1초는 게임 20시간, 15초는 300시간이므로 실시간과 게임 시간 지연을 모두 측정한다. 큰 복원 상태의 반복 직렬화·WAL 비용을 측정하고 필요하면 검증된 상태 델타 저장으로 최적화한다. 확정 시간의 복원 가능성 검증 없이 통계만 먼저 커밋하는 최적화는 금지한다.

## 조회와 보관

메모리는 최근 화면 데이터와 제한된 페이지 캐시만 유지한다. 파일의 원본 기록은 게임이 유지되는 동안 기간 제한 없이 보관한다. 120시간/120일 제한을 파일 삭제 정책으로 적용하지 않는다. 새 게임도 이전 RunId를 자동 삭제하지 않으며 삭제는 명시적인 기록 관리 동작으로 분리한다.

전체·특정 시즌·10일·5일·전일·임의 날짜의 조회는 `(RunId, Hour)`와 회사/기관 ID 인덱스로 범위를 읽는다. 시작 지점이 저장 간격 중간이면 실제 이용 가능한 기준 시점을 표시한다. 구버전의 일별 자료만 있는 곳에서 정확한 시간 기준값인 것처럼 표시하지 않는다.

화면 폭보다 기록이 많으면 조회 시에만 요약한다. 선 그래프는 버킷별 첫값/최솟값/최댓값/끝값을 보존하고 확대하면 원본 해상도로 다시 읽는다. 거래량/대금은 합계, 현금·순자산은 시점 잔액, 재무 지표는 결산 값을 사용한다. 평균으로 거래량을 표시하지 않는다. 기업행동·급락 이벤트와 실제 공백 경계를 남긴다.

원본 가격, 분할 조정 가격, 배당 포함 총수익 지수를 구분한다. 수정 계수를 별도 이벤트로 저장하며 원본 기록을 파괴적으로 덮어쓰지 않는다. 각 시점의 주식 수·상장 회사 집합으로 당시 시총을 읽는다. 현재 주식 수나 회사 목록으로 과거 값을 재계산하지 않는다.

완료 시즌 페이지와 전체 통계, 회사 재무 그래프, 기간별 기관 랭킹은 같은 조회 계층을 사용한다. 기존 시즌 파일의 경계 기록과 현재 기록이 겹치면 동일 시간·동일 데이터만 하나로 합친다. 서로 다른 값은 오류/이전 보고서에 남긴다.

## 디스크 부족과 파일 손상

저장 대기 큐에 상한과 파일 상태를 둔다. 파일이 늦어져 대기 한도를 넘으면 배속을 낮추거나 시뮬레이션을 일시정지하고 저장을 기다린다. 통계를 버리거나 사용자에게 성공으로 표시하지 않는다.

용량 부족·쓰기 실패는 원본을 유지하고 진행을 중지한다. UI에서 용량, 마지막 확정 시간, 다시 시도/내보내기를 제공한다. 시작 때 파일 무결성과 체크포인트/기록 시간을 검사하고 정상 백업에서 복구할 수 있게 한다. 손상된 파일을 삭제하고 새 게임으로 조용히 대체하지 않는다.

백업은 SQLite 지원 백업 API 또는 정합성 있는 읽기 스냅샷으로 작성한다. 실행 중 DB 본체만 복사하면 WAL의 확정 기록이 빠질 수 있으므로 그렇게 하지 않는다. 회전 백업 수는 제한할 수 있지만 원본 역사 기록을 기간 기준으로 삭제하는 설정은 기본으로 두지 않는다.

## v4 파일 이전

1. 원본 `market-v4.json`/`.bak` 및 모든 시즌 파일을 읽기 전용으로 보존한다. 정상 저장과 RunId를 고르고 중복·손상·다른 RunId 파일을 분리한다.
2. 별도 임시 DB에 기초 상태, 최근 시간별 버퍼, 현재/완료 시즌 일별 기록, 기업 보고서·정책·순위를 가져온다. 기록별 실제 해상도와 이용 가능한 지표를 Coverage에 등록한다.
3. 전체 일별 시간 순서·중복·경계, 현금·주식·기관 자산 보존, 회사 ID 매핑, 체크포인트 시간을 검사한다. 기존에는 없는 필드의 0과 `미기록`을 구분한다.
4. 정상 확인 뒤 새 저장을 원자적으로 활성화한다. 중단/실패 시 원본으로 돌아가며 같은 이전을 재실행해도 중복되지 않는다.
5. 이전 보고서에서 시작/끝·일별/시간별 범위·누락 파일을 보여준다. 더 오래된 v3/v2 자료도 실제 남은 내용만 이전한다.

## 기기 밖 백업과 APK 재설치

앱 전용 파일은 종료·재시작에는 남지만 앱 삭제/데이터 지우기에는 남지 않는다. 이번 v1.2.0의 일회용 서명키는 삭제되어 다음 빌드와 동일 서명 업데이트를 보장할 수 없다. 통계 연속성 기능에는 앱 전용 파일과 별개로 사용자가 선택한 위치에 내보내기/가져오기를 제공한다.

Android Storage Access Framework로 저장 게임·통계 DB의 정합성 있는 백업, 버전·RunId·확정 시간·체크섬 manifest를 ZIP으로 내보낸다. 표/그래프 분석용 CSV도 별도 제공한다. 광범위한 저장소 권한이나 인터넷 권한을 요구하지 않는다.

가져오기는 임시 위치에서 버전·무결성·경로/크기 제한·RunId·시간·회계 불변식을 검사한 뒤 적용한다. ZIP 경로 탈출과 과도한 압축 해제를 차단한다. 현재 저장을 먼저 백업하고 다른 RunId 기록을 자동 혼합하지 않는다. 내보내기를 구현하기 전의 앱에서 삭제된 기록은 새 기능으로 복구할 수 없음을 안내한다.
