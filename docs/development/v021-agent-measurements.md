# 최종 AI 측정 수집기 — 실행 전 준비

`AgentMeasurements.cs`는 L03/L07의 실제 AI 행동과 비용을 수집하는 별도 테스트 하네스다. 기본 기능 검사에서 자동 실행하지 않으며 제품 AI 규칙·원장·Notion을 수정하지 않는다. 이 문서는 측정 결과나 수용 완료 증거가 아니다. 기능 마감 후 루트가 최종 측정 단계 전환을 알린 다음 실행한다.

`Program.cs`는 기존 기능 검사가 성공하고 `--agent-metrics`를 명시한 경우에만 수집기를 호출한다. `--agent-metrics-plan`도 필수다. 다른 성능/성장/안정성 옵션과 함께 실행하지 않고 결과를 별도 파일에 저장한다.

## 입력과 비교 범위

| 비교 | 실제 준비와 측정 | 구분할 한계 |
| --- | --- | --- |
| 고정14축 | 기존 `AgentPlanningDispositionScenario`와 같은14축50 기준에서 한 축만 `axisDelta`만큼 바꾼다. 무료 종이/먹을 추가하지 않는다. 첫 실제 결정의 전체 후보 점수와 축별 차이, 이후 행동/목표 분포를 보존한다. | 점수가 변해도 선택 행동은 같을 수 있다. 선택 변화나 다양성이 없는 결과를 삭제하지 않는다. |
| 생산 목표·예산 | 기존 `AgentPlanningProductionScenario`의 명시적 paper 목표와 같은 형태의 tool 목표를 예산별로 진행한다. 실제 탐색→유한 원천 채집→소비 제작→결과 확인 영수증을 기록한다. | 계획의 초기 목표만 선언하며 결과·재료·지식·숙련을 지급하지 않는다. 예산/기간 안에 미완수한 결과도 그대로 남긴다. |
| 기본 생태계 | 실제 두 시조·종문0 창세에서 AI 예산 외의 기본 생활·출생·재해 법칙을 유지한다. 모든 실제 인물의 결정과 점유를 수집한다. | 고정 조건과 분리하며 인구를 강제 증식하거나 합성 주민을 넣지 않는다. |
| 믿음 교정 | 자기 인물이 실제 유료 탐색으로 목재를 관측한 뒤, 다른 실제 인물이 공개 탐색/채집으로 그 원천을 소진한다. 관측 주장은 편집하지 않는다. 기존 낡은 주장을 사용한 실제 실패와 재관측까지 수집한다. | 설정한 준비 기간 안에 실제 소진을 못하면 준비 오류로 남긴다. 원천 잔량·실패 기억을 수동 주입하거나 성공할 때까지 초기조건을 다시 뽑지 않는다. |
| 협력 | 기존 `AgentPlanningCooperationScenario`처럼 현재 자금이 있는 시조가 공개 대여10을 실행한다. 실제 AI 채무 상환·지불 원장을 기록한다. | 협력 성향은 명시 초기조건이다. 상환 결과를 강제하거나 동의·돈·노동을 만들어 주지 않는다. 전수 협력의 기존 기능 검사를 대체하지 않는다. |
| 정보 동등성 | 기존 `AgentPlanningInformationFairnessScenario`를 축소해 공개 생성한 먼 외부 인물과 다른 시조 사이의 기존 자금17 분배만 다른 두 세계를 만든다. 자기 인물과 자기 원천 관측 전체는 동일해야 한다. 월마다 실제 자기 결정/정보를 비교한다. | 추가 실물이나 숨은 지식을 지급하지 않는다. 다른 종류의 모든 숨은 상태에 대한 일반 증명으로 확대하지 않는다. |
| 저장 재현 | 각 비교의 동일 초기 세계를 따로 복원한다. 지정 주기마다 복제본을 메모리 codec으로 다시 저장/복원하고 남은 매월 전체 해시를 비교한다. | 메모리 codec 회귀다. 실제 파일·호스트 중단 감사나 최종 D02 전체 합격으로 바꾸지 않는다. |

고정 조건은 기존 `AgentPlanningFixture.Fresh`처럼 출생·식량 소비·재해·오독을 비활성화하고 한 동료를 명시된 장기 경계 상태로 둔다. 자기 초기 자금을 동료에게 재분배하되 총액을 보존한다. 이것은 선택을 분리하는 초기조건이며 생태계 전체나 필연적 성공을 뜻하지 않는다. 실제 초기 법칙·해시·공개 준비 명령·완료 출처를 각 결과에 저장한다.

## 수집 값

- `rawLatencySamples`: 실제 `AdvanceTo` 월 경계의 Stopwatch tick·현재 스레드 할당·새 결정 수·실제 탐색량과 당시 예산. 조회/복원/보고서 직렬화와 복제 비교는 계측 구간 밖이다. 이는 순수 AI 추론 시간이 아니며 비용 지표인 `DecisionRecord.Expansions`와 함께 읽는다.
- `axisCausalComparisons`, `decisions`, 행동/목표 분포와 최대 행동 비중:14축 입력의 실제 점수 인과·행동 다양성·지배를 고정 조건과 실제 생태계로 나눈다. 최적 전략 점수나 임의 가중 합산을 만들지 않는다.
- `goalReceipts`, `jobs`, `actualInventoryEvents`, `actualPayments`, `completedKnowledge`: 실제 유료 단계·소비·완료/실패·출력·협력의 ID와 출처. 선언한 목표의 영수증이 있어야 `goalCompletedWithinHorizon`이 참이다. `firstTargetCosts`는 그 첫 완수 시점까지의 품목별 실제 소비·행동 점유·작업 ID를 따로 남겨 이후 활동과 구분한다.
- 품목별 소비/출력과 실제 월 구간별 행동 점유: 다른 재화 단위를 합쳐 가치 효율을 가장하지 않는다. 생태계 물질 변화는 세계 전체 값이며 자기 공정 소비와 구분한다.
- `failures`, `beliefCorrection`: 실제 실패 종류/출처와 잘못된 원천 관측을 다시 고친 날짜/지연. 미교정 결과는 null로 남긴다.
- 예산 한도 도달 횟수와 실제 대기 이유에 예산/이월이 명시된 결정, 최대 연속 대기, 실제 예약 공정이 없는 정체 후보: 유한 기간의 관측이다. 오래 걸리는 정상 작업이나 무한 교착을 단정하지 않는다.
- 모든 월의 해시와 저장 재현/정보 동등성 비교. 비교 실패를 수집 결과에 보존하고 오류 수를 올리며, 부분 보고서는 케이스마다 원자적으로 교체한다.

예열은 측정 원본과 독립된 복제 세계에서만 실행한다. seed·horizon·예산·반복·예열·정체 기준·저장 주기·준비 상한은 실행 전에 계획 파일에 고정한다. 원시 지연은 runtime/OS/아키텍처/CPU 수·Stopwatch 주파수·제품/수집기 버전과 함께 기록한다. 두 빌드의 소스 SHA가 계획 `sourceCommit`과 다르면 실행을 거부한다.

## 최종 측정 때 사용할 계획 예시

다음 값은 계획 예시이며 아직 실행하지 않았다. `sourceCommit`에는 실제 깨끗한 실행 checkout의40자리 SHA를 쓰고 그 소스로 빌드한다. 결과를 비교할 때 seed·예산·horizon·반복 조건을 바꾼 실행을 같은 표본으로 합치지 않는다.

```json
{
  "sourceCommit": "실행 checkout의 실제40자리SHA",
  "seeds": [42, 73, 149],
  "horizonMonths": 240,
  "repetitions": 3,
  "warmupMonths": 2,
  "planningBudgets": [1, 8, 64],
  "beliefBudget": 64,
  "axisDelta": 1,
  "stagnationMonths": 12,
  "replayEveryMonths": 12,
  "preparationLimitMonths": 120
}
```

최종 단계의 실행 형식은 다음과 같다. 하네스 준비 중에는 이 명령을 실행하지 않는다.

```text
dotnet run --project tests/Chronicles.Game.Tests -c Release --no-build -- --agent-metrics <결과.json> --agent-metrics-plan <고정계획.json>
```

결과가 생성되어도 L03/L07의 수용 상태는 자동 변경하지 않는다. 실제 분포·완수/미완수·효율·교정·정체·예산·재현·정보 동등성 결과와 한계를 검토한 뒤 원장 담당자가 따로 판단한다.
