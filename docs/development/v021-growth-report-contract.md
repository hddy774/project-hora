# Z04 성장 관측 보고서의 소스 계약

이 변경은 최신 통합 `97ba603`(Life #146 포함) 위의 **harness 소스 준비**다. 실제 성장·성능·장기 실행·프로파일링 결과가 아니며, 이 작업에서 측정을 실행하지 않는다. 원장 상태나 게임 법칙·통화·성능 fixture 조건을 바꾸지 않는다.

`--growth <report.json>`은 기존과 같이 세 seed(42/98/2026), 6,000개월(500년), 세 비교 조건을 사용한다. a는 사용자 선택을 반영한 실제 제품 기본값이고, b는 혈연 제한과 240개월의 명시적 성년 인간 두 명 편입, c는 혈연 제한·외부 편입 없음이다. b의 편입은 실제 공개 `create` JSON 명령이며 Mortal·자산/통화/기예/지식 0을 확인한다. 다른 기본 법칙을 완화하거나 강제로 출산·성장·조직 생성을 수행하지 않는다.

선택 인수 `--growth-scenario a|b|c`, `--growth-seed 42|98|2026`으로 조건 또는 seed, 둘 다를 지정할 수 있다. 생략하면 여전히 전체 9개다. `requestedCases`는 실제 선택 범위이며 `requested_complete`는 그 범위를 완주했는지만 표시한다. 전부 9개를 실행한 `complete`와 다르다. 단일 case가 끝나면 `status: requested-completed`, `requested_complete: true`, `complete: false`이므로 기본 프리셋/전체 비교 완료로 오인하지 않는다. 환경과 함께 실제 commit·제품 소스 fingerprint를 기록한다.

## 분담 원본의 검증·통합

`python3 scripts/aggregate-v021-growth.py <완료 원본들...> --output <별도 통합 파일> [--source <실행 commit>]`는 세계나 측정을 실행하지 않는다. 같은 clean Release 실행 commit·제품 fingerprint와 horizon/간격/성립·시간 계약을 가진 서로 다른 9개 `(scenario, seed)` 완료 원본만 수용한다. `requested_complete`가 아닌 진행/실패 원본, 중복·누락 key, 빈/누락/중복 관측행, 다른 코어/기간, 선택 완주를 전체 완주로 재명명한 원본을 거절한다.

법칙 검증은 실행 commit의 `Laws.cs` literal registry를 git 객체에서 읽어 a의 실제 기본값과 b/c의 **유일한** `birth.kinship=0` 차이, 잠정 계수 metadata까지 대조한다. 새로운 registry 표현식을 추측해 해석하지 않고 거절한다. 외부인·인구·구간 출생/사망·성립 시각과 원본 요약도 확인하며, 실측 값의 진위를 세계 재실행으로 증명하는 도구는 아니다.

원본 byte와 SHA256·환경·key 목록을 통합 파일에 연결하고 입력은 수정하지 않는다. 기존 정의로 최소/중앙/최대·정확/구간/미성립 분포를 재계산한다. 누락 seed나 미성립을 0으로 대입하지 않는다. 입력 프로세스 경과 시간 합계는 병렬 작업의 전체 wall time이나 장치 속도로 주장하지 않는다. `--self-test`는 인공 JSON의 계약 검사만 수행하며 실제 성장 근거를 생성하지 않는다.

## 진행과 표본

초기 0개월과 이후 120개월마다 실제 checkpoint와 불변식을 확인한다. 인구·전체 보존 인물·살아 있는/누적 생물학적 시조 후손·누적/생존 최대 세대·금단 이상·범인·무인·실제 가계·가문·종문·왕조·무영토 왕조·활동 시설·누적/구간 출생·사망·명시 편입 수를 기록한다. 금단 이상에는 두 시조가 포함되므로 **후손 금단 이상**도 별도로 기록한다. Realm.Mortal과 무예>0은 겹칠 수 있으며 무예 없는 범인도 구분한다.

후손과 세대는 실제 생물학 부모 DAG에서 계산한다. 편입 성인은 세대 0이며 가짜 출생으로 세지 않는다. 같은 영혼의 과거 신원을 생물학 혈연으로 복사하지 않는다. 세대별 첫/마지막 출생 월, 실제 부모의 출생 당시 연령 범위, 이전 세대 첫 출생과의 간격을 보고한다. 시조의 시작 연령은 선언된 초기조건이며 관측한 과거 출생으로 주장하지 않는다.

각 표본 및 case 종료 직후 JSON을 원자적으로 교체하며 콘솔에 조건/seed/월/목표·인구·후손·세대·금단·조직·출생/사망·실제 경과 시간을 출력한다. `status: partial`과 진행 중 case, `failed`와 오류, `completed`를 구분한다. 네트워크/게시/원장 갱신은 수행하지 않는다. `complete`는 9개 유한 관측이 끝났다는 뜻이며, 기본 프리셋의 균형·무한 생존을 통과시켰다는 뜻이 아니다.

## 성립 시각의 정확도

| 결과 | 근거와 정확도 |
| --- | --- |
| 첫 실제 후손 출생 | 보존된 인물의 실제 `Born`과 생물학 부모 DAG. |
| 첫 후손 금단 형성 | 실제 육신의 `Cultivation.Formations` 중 GoldenCore `Month`. 현재 경지나 출력 문구로 시각을 역산하지 않는다. 사망/상위 경지 이후에도 원형 형성 기록을 사용한다. |
| 추가 가문·종문 | 실제 `Group.Founded`; 해산된 조직도 보존 원장에서 읽는다. 가문의 최초 생성일을 왕조 승격일로 쓰지 않는다. |
| 첫 왕조 | 전용 승격 시각이 없으므로 이전 표본 월 초과~현재 표본 월 이하의 구간. 영토 주장은 통치보다 앞서 있을 수 있어 claim 날짜를 승격일로 추정하지 않는다. |
| 첫 시장·공방·취락 활동 | `Ecology.Facilities.Founded`가 비활동 상태에서도 최초 시각을 보존한다. 노점 시장·노천 공방·교역 취락의 실제 활동 표식이며 독립 도시 조직이나 무료 시설 용량으로 해석하지 않는다. 개폐 변경 이력은 제한되므로 재개업 횟수는 재구성하지 않는다. |

실제 운영자·재원·지식·권리·노동·원천을 요구하는 현재 성립 조건을 보고서에 명시한다. 시각이 확인된 경우와 관측 구간만 있는 경우, 완료한 기간 내 미성립과 아직 진행 중인 경우를 구분한다. 미성립을 0개월 성립으로 넣지 않는다.

## 범위·시간·한계

조건별 동일 월의 seed 간 최소/중앙/최대, 실제 관측 seed 수, 완료 seed, 성립/관측 구간/미성립 건수를 출력한다. 누락되거나 아직 실행하지 않은 seed를 0으로 채우지 않는다. 3개 seed의 결과는 확률이나 통계적 신뢰구간이 아니다. 사용한 모든 법칙과 registry의 실제 잠정 계수·근거를 출력하며 민감도 sweep을 수행한 것으로 주장하지 않는다.

`simulationMs`는 `AdvanceTo`만의 실제 시간 합계다. `commandMs`는 명시 편입의 공개 명령·snapshot/검증 작업이며, `caseElapsedMs`는 창세·투영·앞선 보고서 쓰기까지 포함한다. 총시간은 각 보고서 쓰기 직전까지이므로 마지막 직렬화/쓰기 비용은 값 밖이다.

10초/년의 1배속 달력 모델과 500년→5,000초 환산은 실제 측정 시간이 아니다. 현재 UI의 이상적인 833ms/월 cadence(500년→4,998초)도 별도 표시하며 busy/backpressure·대화창 정지·타이머 지연·기기 성능을 보증하지 않는다. 10/25/50/100배 환산도 계산값이며 실제 배속 통과로 표시하지 않는다.

기존의 clean Release 측정 환경 함수를 재사용해 실제 source commit·CPU/가용 메모리·런타임/OS·전원/열 미측정 한계를 기록한다. 저장/재개 장기 검사는 별도 stability harness에 있으므로 이 성장 관측에 추가 저장 루프를 넣지 않는다. 실제 Z04/T04 수용은 기능 완료 뒤 최종 측정과 해석 근거로 판단한다.
