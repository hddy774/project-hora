이 문서는 기존 `--sensitivity` 수집기를 세 독립 시드 작업으로 실행하는 워크플로 계약이다. 제품·하네스·계획/보고서 schema·기존 검증기는 변경하지 않는다. **현재는 실행할 법칙·두 값·관찰창·시간 상한을 채택하지 않았고 실제 민감도 실행도 0회다.** 같은 소스의 기본 기준선9개가 실제로 완주하고 원문 검증을 마친 뒤 계획을 확정한다.

## 고정 측정 소스와 입력 소스

측정 소스는 `7ce66943b539420c9dc1e3fa8a611daae58020ff`, 제품 지문은 `4e228e7ba34e538fd1a69abf05934d8162b2a65559ed4ffd50a73b00a8ba2304`다. #197의 원격 기준선과 같은 SDK10.0.403·실제 런타임.NET10.0.14를 사용한다. 후속 PGO 설정이나 다른 제품 소스를 이 기준선에 섞지 않는다. 기존926 관측은 별도 보조 자료이며 최종7ce 기준선/민감도로 합산하지 않는다.

워크플로·계획·입력 문서의 SHA는 측정 SHA와 별도로 기록한다. 준비 작업은 해당 문서 소스를 체크아웃해 입력을 `RUNNER_TEMP`에 복사하고 하나의 불변 입력 아티팩트로 고정한다. 세 측정 작업은 그 입력을 먼저 내려받은 다음 **정확한7ce를 체크아웃**한다. 입력·빌드·로그·환경·출력은 모두 체크아웃 밖에 두므로 문서/워크플로 커밋을 측정 코드로 잘못 빌드하지 않는다.

## 기준선 원문과 portable 묶음

공식 원격 기준선 원문·ZIP·manifest·환경·출처는 UI 담당이 검증·보존한다. 공식 집계가 절대 `inputArtifacts[].path`를 가진 경우 그 JSON을 나중에 직접 고치지 않는다. 다음 순서로 별도 portable 파생본을 만든다.

1. 같은7ce의 실제 `a/b/c × 42/98/2026` 9원본을 byte 그대로 `raw/a-42.json` 등의 상대 경로에 복사한다. 각 원본의 SHA를 공식 수집 manifest와 비교한다.
2. 정확한7ce의 기존 `scripts/aggregate-v021-growth.py`에 이 상대 경로9개를 넘겨 **별도** `baseline.json`을 생성한다. `--source`도7ce 전체 SHA로 지정한다. 집계기의 소스/지문/법칙/기간/51표본/9개의 고유 키/원본 상태 검증을 그대로 따른다.
3. 공식 집계와 파생 집계를 구분해 보존한다. 두 집계의 cohort 행과9raw SHA가 같음을 확인하고, 파생본의 SHA를 따로 기록한다. 입력 경로·출처가 달라 집계 JSON의 SHA는 서로 다를 수 있다.
4. 그 뒤에만 `plan.json`의 `baselineReportPath`와 `baselineReportSha256`를 확정한다. 계획의 SHA도 마지막에 고정한다. 값이나 해시를 빈칸/0으로 채우지 않는다.

기본 묶음 위치는 `docs/evidence/0.2.1/growth-sensitivity/inputs/`다. 준비 작업은 `docs/evidence/0.2.1/` 안의 실제 파일 묶음만 받는다. 여기에는 기존 schema의 `plan.json`, 상대 경로 기준선 집계, 그 집계가 참조하는 실제9raw와 운영 상한 파일 `cli-wall-minutes.txt`가 있어야 한다. `bundle.sha256`는 CI가 만드는 이름이므로 입력 묶음에서 미리 사용하지 않는다. `plan.baselineReportPath`와 집계의 원본 경로는 묶음 안에서 해석되는 상대 경로여야 한다.

준비 작업의 경로/해시/완주 헤더 검사는 이동 계약을 확인한다. 권위 있는 세부 검증은 기존 `GrowthSensitivityContracts.Validate`가 측정 전에 다시 수행한다. 합성 예시·부분 기준선·누락/중복 원본·다른 소스·법칙 조작·불완전 이력을 실제9완주 증거로 채택하지 않는다.

## 계획과 실행 상한

계획은 기존 schema1 `seonro-growth-sensitivity-plan`만 사용한다. 같은7ce/지문/portable 기준선 SHA, **한 잠정 LawKey**, 서로 다른 비기본값2개, 실제 시드42/98/2026, 관찰창·간격·비교 근거를 명시한다. 범위/의존 조건·고정 정책 키 거절은 기존 법칙 registry/검증기를 그대로 따른다. 혈연허용 기본a·양친금단·외부인0을 유지한다. PC-TEMP 전수 sweep이나 새로운 성공조건은 추가하지 않는다.

관찰창과 법칙 값은 실제 기준선의 후손 출생·입문/경지·사망·금단 형성/부재 및 불확실 가정을 보고 선택한다. 관찰창 안의 실제 미도달·사망·부재와 창 바깥 검열을 구분하며, 기본9개 결과와 반사실6개를 별도로 보고한다.

CLI 벽시계 상한도 같은7ce 기본a의 시드별 실제 시간과 선택 관찰창을 확인한 뒤 근거를 문서화해 정한다. 반사실은 인구·행동량이 달라질 수 있어 기간 비례 계산을 보장 시간으로 취급하지 않는다. 아직 숫자를 채택하지 않았다.

- **전체9기준선·상한 근거를 확인한 뒤에만** 입력 묶음에 `cli-wall-minutes.txt`를 추가한다. 현재 파일이나 임의 숫자·0 기본값을 넣지 않는다. 형식은1~330의 순수 ASCII 정수 한 줄이며 마지막 LF/CRLF 한 번만 선택적으로 허용한다. 빈 파일·0·범위 초과·기호/소수/공백/BOM·비ASCII·여러 줄은 거절한다.
- PR 라벨 실행은 `METADATA_SHA` 체크아웃 뒤 이 파일을 읽는다. 수동 main 실행의 필수 `wall_minutes`도 보존하고, 버전 관리된 실제 채택 파일의 값과 일치하는지 확인한다.
- 준비 작업이 채택값·파일 SHA·문서 소스를 한 번 고정해 세 작업에 전달한다. 파일도 불변 입력 묶음/manifest에 들어가고, 실제 실행 출처에 그 SHA를 기록한다. 저장소 변수 설정 기능이나 만료된 로컬 gh 인증에 의존하지 않는다.
- CLI는1~330분, 작업 자체는360분 이내다. #197과 같은 표준 러너 서비스 한계 안에서 실패 원문 업로드 시간을 남기는 실행 경계이며, 게임의 성능/성장 수용 목표가 아니다. 상한을 넘기면 실패·partial을 보존한다. 기간/시드 축소, 자동 재시도, 실패 플래그 재작성으로 통과시키지 않는다.

## 명시적 실행과 완료 의미

PR 생성/동기화로 측정하지 않는다. 동일 저장소·소유자의 명시적 `0.2.1 민감도 실측 실행` 라벨만 받는다. 수동 실행은 main에 등록된 뒤 정확한 문서 SHA40·묶음 경로·실행 상한을 입력한다. 라벨/수동 실행 전에 기본9원본 검증·계획 확정이 먼저다. 현재 PR에는 채택한 계획이나 실행 라벨이 없다.

시드42/98/2026을 `max-parallel: 3`, `fail-fast: false`로 실행한다. 각 작업의 기존 CLI는 다음 인수만 쓴다.

```text
--filter INV-001/002/011
--sensitivity <고유 RUNNER_TEMP/out/sensitivity.json>
--sensitivity-plan <RUNNER_TEMP/inputs/plan.json>
--sensitivity-seed <42 또는98 또는2026>
```

`--report`는 기존 CLI의 입력 보호 guard가 거절하므로 전달하지 않는다. 각 시드는 계획의 두 값을 원래 순서대로 실행한다. 기본9성장 실행·창세·AI·게임 법칙 구현은 바꾸지 않는다.

기존 수집기의 실제4DLL `AssemblyInformationalVersion`/SHA와 source capture를 그대로 사용한다. 워크플로는 빌드 직후 DLL·런타임 설정을 보존하고, 실행 뒤 기존 보고서의 실제4DLL 메타데이터 및 전후 바이트 동일성을 확인한다. 새 C# 검사 프로그램이나 보고서 형식을 추가하지 않는다.

시드별 두 사례를 완주하면 원본은 `requested_complete=true`, `complete=false`다. 이를 전체6완주로 다시 쓰지 않는다. 수집 작업은 같은 계획 SHA·기준선 SHA·7ce 소스/지문과 서로 다른 `(값,시드)` 6키가 실제로 완료되고, 세 작업의 종료/로그/출처 검증까지 성공했을 때만 **관찰6/6 수집 확인**을 표시한다. 새 통합 JSON schema를 만들거나 원본을 재작성하지 않는다. 누락·부분·중복·혼합 소스/계획·시간초과·출처 오류는 수집 실패다.

성공은 고정한 관찰창의 수집 완주만 뜻한다. 특정 인구·모두 생존·금단 마감 시점·균형 보정 채택을 뜻하지 않는다. 실제 세계 시계의1배 환산과 실제 시뮬레이션 ms도 기존 보고서처럼 분리한다.

실패에도 원본 JSON/.pending/lock·로그·입력·네 DLL·런타임 설정·CPU/메모리/쿼터/디스크·실제 환경·파일 SHA·종료 코드를14일 아티팩트로 보존한다. 서로 다른 VM의 시간을 동일 머신의 성능 대조나 병렬 전체 벽시계 시간으로 합산하지 않는다. 원격 원문은 만료 전에 저장소 증거로 별도 보존한다.
