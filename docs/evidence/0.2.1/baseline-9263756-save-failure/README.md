# 9263756의 1만 명 저장 실패 원본

이 실행은 **기준선 수용 실패**다. 원래 두 명·100명·1,000명의 세 규모를 완료하고 10,000명 세계의 12개월 표본·최종 힙·불변식·조회를 진행했지만, 마지막 저장에서 JSON 단일 문자열 크기 제한으로 종료 코드 134를 관찰했다. `GameCodec`이 398,228,383자 상태 JSON을 봉투의 문자열 필드에 다시 넣는 단계에서 실패했다. 메모리 부족으로 판정하지 않는다.

- 실제 소스: `9263756b1d00b8696fddecacb077f55d95141f26`, 제품 지문 `7c61d0bb5cccdb079108d705bc042fa0080932c39667cf1d912e77ed1afcb634`.
- [원본 JSON](baseline.original.json)의 `complete: false`·완료 규모 3개와 실행 중 `save_encode`를 그대로 보존했다. [원본 로그](baseline.original.log)에 월별 표본과 예외 전체가 있다.
- [실제 어셈블리 출처](assemblies.original.json)의 네 DLL을 원래 경로에서 다시 해시해 일치함을 확인했다. [실패 관찰·파일 해시](failure-provenance.json)는 원본 밖의 별도 메타데이터다.
- 1만 명의 저장 크기·저장/읽기 비용·마지막 세계 해시가 보고된 것처럼 행을 합성하지 않는다. 이 부분 결과로 수치 예산이나 최종 게이트를 채우지 않는다.

기능 개발 뒤 시작한 측정이며, 같은 프로세스에서 창세 기능 선택 검사 1개를 먼저 실행했다. 1만 명의 제외된 예열 동안에만 5초 관리 스택 진단을 붙였고 월별 측정에는 붙이지 않았다. 단일 CPU0에 고정했지만 CPU1/2/3의 성장·행동 측정 및 잠시 CPU4의 기능 검사가 같은 4CPU 할당을 공유했다. Android 실기기·발열·배터리·별도 계획기 CPU 지연을 측정한 자료가 아니다.

[이슈 #191](https://github.com/hddy774/project-hora/issues/191)에서 대용량 봉투를 수정한다. 수정 후 새 소스의 전체 기능·실제 네 규모 저장/읽기 포함 기준선을 별도 실행해야 한다. 이 파일은 실패 이력으로 남는다.
