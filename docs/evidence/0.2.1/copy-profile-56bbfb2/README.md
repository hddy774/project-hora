# 56bbfb2 복사 비교와 N1000 병목 진단

앱 기본 재고 복사는 **JSON15를 유지**한다. 같은 소스의 N100 단일 순차 비교에서 형식화 복사(typed15)는 전이 시간이2.00% 늘고 할당량은0.37% 줄었다. 조회·저장은 나아졌고 복원은 느려졌다. 형식화 복사는 재검토 대상으로 남긴다. 이 문서 PR은 기존 원본을 보존·압축·정적으로 비교했으며 새 빌드·앱·검사·측정 실행은 없다.

실제 실행 소스는 `56bbfb2ff3cec2df79fa28234d61a03fe4a50e63`, 테스트 포함 제품 소스 지문은 `cf17eee7930cc754eda7558d0496f6929d10d64fb9352d0c42ff49a08704f9e3`이다. [실제 CLI·빌드·환경 출처](execution-provenance.json)에 명령 인자, 깨끗한 작업트리, 생성 AssemblyInfo4개와 실제 DLL4개의 소스 리비전·SHA256을 기록했다. DLL은 복사·로드·실행하지 않고 정적으로 읽었다.

N100 두 실행은 CPU0 고정으로 순차 진행했다. 각 프로세스가 창세 기능 `INV-001/002/011` 한 건을 먼저 통과한 뒤 별도 세계에서2개월 예열·12개월1회를 실행했다. 같은 호스트의 JIT·공유 캐시와 실행 순서 영향을 분리하는 역순·반복 실험은 하지 않았다. 온도·전원 상태는 측정하지 않았다.

초기·최종 상태 해시, 전체113개 법칙, 합성 초기조건, 실제 작업량, 저장 크기 및 인지 자료는 정확히 같았다. 초기 해시는 `cd381300e01e8c00d6ae9ac8bc53fea08c55eaa74eca013ab7feca6bc9dea8f2`, 최종은 `470f6d1d395873a7e2d5b14714360382b99f66dcb10b9c9a35407a6b926ea39c`다. 비용 원본은 인코딩된 저장 SHA나 바이트 배열을 기록하지 않아, 이 자료에서 확인한 저장 동등성은 상태 해시와 저장 크기까지다. 실제 바이트 배열의 동등 검사는 별도 [기능 삼자 근거](../inventory-oracle-final-integration/README.md)에 있다. JSON 경로의 투영 카운터는 예열2·측정13, 형식화 경로는 공통 투영·형식화 카운터 모두 예열2·측정13이었다. 실제 형식화 경로를 실행한 비교다.

하지만 이 N100의 현재 행동은 수행(Cultivate)100명, 완료 지식 활동1,090건이며 완료 실물 작업·추출·생산은0이다. 재고 후보 자체가 측정13회로 제한된다. 최종 소스는 실제1% 실습 자격의 수행 경로와 새 AI의 `foodUse=0→목표 식량0` 연결을 반영한다. 현재 작업량은 과거 `b0f3aec`의 실물 작업 포함 부하와 다르므로 두 자료를 섞어 속도 개선률을 만들 수 없다. 초기 인구100은 실제 시조2명과 명시 합성 진입자98명이며, 후손 성장 이력이나 기본 창세 인구100을 뜻하지 않는다.

N1000 JSON 실행은12개월을 완주했으나 **중간45초에 EventPipe 추적이 개입한 진단 자료**다. [원본](copy-56bbfb2-json1000.json)과 로그를 그대로 보존한다. 실제 전이88,708.8601ms·전체112.9094774s·할당43,940,609,640B·저장80,532,814B·최종 관리 힙129,103,064B를 기록했지만, 이 값을 최종 무계측 기준선이나 JSON/형식화 채택 비용 비교에 사용하지 않는다. 마지막 작업량은 수행400·대기596·이동3·탐사1명, 완료 지식 활동4,401건·완료 실물 작업0·추출3·생산0이다. 세 원본의 `complete:false`를 유지했고 형식화 N100의 `experimental_configuration:true`도 보존했다. 단일 규모의 호스트 보고서들이며 최종 성능 게이트·Android·Unity·과거100배 수용을 뜻하지 않는다.

추적은 N1000의 실제 측정 월1 부근에 붙었다. 수집 프로세스는45초 후 정상 종료했고, 샘플러 실행도 이후12개월까지 정상 종료했다. [분석 요약](profile-diagnosis.json)의 분모는 추적 중 실제 AdvanceTo로 분류된 **44,983.393ms 가중 스레드 시간**이다. 예열 Advance 표본은0이며, 여러 스레드를 합친 전체90,393.087ms 및 벽시간45초와 구분한다. GC 폴링·대기 스택을 포함한 관리 코드 샘플 시간으로, 커널의 실제 CPU 실행 시간(on-CPU)이나 이용률이 아니다.

호스트 cgroup은4 CPU 쿼터·16GiB 메모리 한계다. 문서화 시점의 허용 CPU 집합0–4는 쿼터4와 다르며, 실제 앱은 CPU0 하나에 고정되어 원본의 유효 CPU 수는1이다. .NET이 보고한 GC 가용12GiB도 cgroup 한계16GiB와 구분했다. [현재 환경 읽기](environment-current.original.json)는 측정 당시 이용률이 아니다. 정확한 실행·추적의 UTC 시작/종료는 별도 캡처하지 않았다. 실행 뒤 관측한 시계 두 건만 출처에 기록했고 파일 mtime/btime으로 실행 시각을 추정하지 않았다.

16,076,731B Speedscope와1,114,588B 가중 스택 JSON은 파일명 없는 `gzip`, `mtime=0`, 압축수준9로 보존했다. 반복 압축 byte 동일과 압축 해제 후 원본 전체 byte·SHA256 동일을 확인했다. [원본·압축 해시](artifact-manifest.json), 수정하지 않은 분석 스크립트와 수집 로그를 함께 둔다. 분석 스크립트의 `/workspace/scratch` 절대 경로도 원본 그대로다. 원본 재분석이 필요하면 스크립트 사본의 입력·출력 경로를 별도 작업 폴더로 바꿔 기존 원본을 보존한다.

12,490,406B EventPipe 원본은 로컬 `/workspace/scratch/profile-56bbfb2-json1000.nettrace`, SHA256 `6bfb7006e6ac6f492660a2dea8ab06e0339484f813ba9b81b3e82babae81461d`로 기록하고 첨부하지 않았다. 저장한 Speedscope의 관리 스택 재분석은 가능하지만, 이 저장소만으로 미첨부 EventPipe의 모든 이벤트와 변환을 재검증할 수는 없다. 저장소 파일 검증은 `python3 docs/evidence/0.2.1/copy-profile-56bbfb2/verify-evidence.py`로 수행하며, 앱이나 측정은 실행하지 않는다.
