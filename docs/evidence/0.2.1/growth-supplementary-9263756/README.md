# 보조926 성장 실행의 중단 원형

이 자료는 최종 기준선이 아닌 로컬 보조 관측의 원형 보존이다. 실제 소스는 `9263756b1d00b8696fddecacb077f55d95141f26`, 제품 지문은 `7c61d0bb5cccdb079108d705bc042fa0080932c39667cf1d912e77ed1afcb634`이다. 별도 소스7ce의 최종 원형9개는 [기준선 보존 자료](../growth-primary-7ce6694/README.md)와 PR211에 있다. 두 소스의 결과를 합쳐9완주로 만들지 않았다. 이 보존 작업에서 새 세계·성장·비용 측정을 실행하지 않았다.

## 두 중단 사건과 실제 종료

모든 원래 실행은 선택한 시드에서 a/b/c를 순차 관측하고, 각 조건6000개월/120개월 간격을 사용했다. 원형법칙과 기본a의 혈연허용·양친금단 조건을 바꾸지 않았다. b만240개월에 명시된 무자산 범인2명을 편입했다.

| 실행 | CPU·실제 PID | 보존된 완료 | 마지막 부분 관측 | 실제 종료 근거 |
|---|---|---:|---|---|
| 최초 시드42 | 1·114052 | 0 | a·4320월 | `/proc` 좀비 exit status9 → SIGKILL(-9), 발신 주체·원인 미확정 |
| 최초 시드98 | 2·114058 | 1(a) | b·1800월 | 같은 SIGKILL(-9), 발신 주체·원인 미확정 |
| 재실행1 시드42 | 1·120460 | 2(a/b) | c·840월 | 승인된 중복 정리 SIGTERM, supervisor 실제 wait=-15 |
| 재실행1 시드98 | 2·120473 | 3(a/b/c) | 없음 | 21:00:27.383325UTC 자연 종료, 실제 wait=0·signal0 |
| 대기 후 시드2026 | 3·132980 | 1(a) | b·3600월 | 승인된 중복 정리 SIGTERM, supervisor 실제 wait=-15 |

최초 두 프로세스는18:02~18:03UTC 무렵까지 원형을 갱신했다. 이후 좀비 상태와 신호9를 관측했고, 당시 cgroup `oom=0`, `oom_kill=0`이었다. 이것만으로 종료 발신 주체나 원인을 특정하지 않는다. 원래 부모는 사라졌거나 PPID1의 좀비였으므로 현재 관측자가 `wait`로 회수한 것처럼 쓰지 않는다. 상세 원문은 [최초 중단 기록](raw/growth-9263756-interruption-20261030T1810Z.json)과 [루트 독립 관측](raw/observed-measurement-interruption-20261030T1806Z.json)에 보존했다. 파일명 시각과 JSON의 실제 관측 시각은 별개다.

정확한 저장 재개 기능이 없어 동일926 소스/조건/시드를 새 경로에서 처음부터 재실행했다. 이전 a98을 재실행 결과에 붙이지 않았다. 재실행 계열의 **서로 다른 완료 코호트는6/9**다. 최초 a98은 같은 조건의 중복 관측이며7번째 완료로 더하지 않는다. 모든 원형 `complete=false`를 보존했다. 시드98의 `requested_complete=true`는 해당 시드 a/b/c3개 완료이고 전체9완료가 아니다. 나머지 두 요청은 `requested_complete=false`다.

7ce의 최종9원형/공식 집계가 독립 검증된 뒤 보조 실행을 정리했다. 시드98은 이미 자연 종료했으므로 신호를 보내지 않았다. 살아 있는 시드42와2026의 PID·cwd·명령·출력 경로를 다시 확인한 후 **21:03:38.873316/873337UTC** 각각 SIGTERM을 보냈다. supervisor가 실제 wait=-15와 종료 시각을 기록했다. 최종7ce·민감도·다른 프로세스에는 신호를 보내지 않았다. [실제 정리 기록](raw/growth-9263756-intentional-duplicate-stop-after-primary9-v2.json)에 비교·PID·신호·종료·전후 원형SHA가 있다.

## 비교 범위와 관측자 오류 보존

완료6코호트는 대응하는7ce 원형의 모든 비시간 코호트 필드·법칙·관측행·최종 해시와 일치했다. 부분 관측은 같은 월의 비시간 시계열 접두부·법칙·이미 성립한 기록만 대조했다. c42의840월, b2026의3600월 해시는6000월 해시와 비교할 수 없다. 이 유한 표본의 일치가 모든 입력이나 실행비용의 동등성을 증명하지 않는다.

첫 종료 전 검사에서 관측자가 부분 해시를6000월 해시와 잘못 비교해 guard가 실패했다. 이때 signal0이었다. [첫 실패 기록](raw/growth-9263756-intentional-duplicate-stop-after-primary9.json)과 [첫 검사 소스](operation/stop-supplementary-growth-926-after-primary9.py)를 그대로 보존했다. `GrowthScenarios.cs:74`가 각 표본마다 해시를 갱신하는 경계를 확인하고, [수정된 검사 소스](operation/stop-supplementary-growth-926-after-primary9-v2.py)로 같은 월에 가능한 사실만 비교한 뒤 종료했다. 원문 JSON을 사후 수정해 검사를 통과시키지 않았다.

최초 중단 관측 JSON의 `rawStatus="running"`는 당시 기록자의 부정확한 요약이다. 같은 파일의 SHA로 고정된 실제 원형 최상위 `status`는 `partial`, 진행 중인 코호트의 `status`는 `running`이다. 이 관측자 요약도 고쳐 쓰지 않았으며, 상태 판독은 실제 원형 필드를 따른다.

## 실행 환경과 재현 경계

CPU1/2/3 affinity와 `cpu.max=400000 100000`, 실제 명령·시작·종료·네 DLL의 SourceRevision/PE/해시 근거는 `raw/*-run.json`, `raw/*preparation.json`, `raw/*postquiet-assemblies.json`에 있다. CPU3은 AI108이19:21:29UTC 종료한 뒤19:24:10UTC 시드2026에 인계했다. 세계 권위에 벽시계 시각을 넣지 않았다.

동시 CPU0 비용 수집·CPU3 AI 수집 및17:48:59부터 별도CPU4 기능 검사, root quiet/PGO 진단 창과 실행 재배치는 별도 원형 metadata에 남아 있다. CPU4 종료는17:56:54UTC 완료 로그 관측 상한과17:57:15UTC exit확인으로 구분했다. 따라서 이 `caseElapsedMs`는 순수 CPU 성능·기기 속도·Android 성능으로 해석하지 않는다.

`manifest.json`은 원본 절대 경로·크기·SHA256·원래 수정시각과 저장소 복사 경로를 연결한다. `raw/`와 `operation/`은 원본 byte 동일 복사다. 생성물/DLL은 커밋하지 않았고 원형 보고서·로그·검사 소스·SHA 근거만 보존했다. `python3 operation/verify-archive.py`는 복사본과 기록된 SHA/상태/중단 경계만 읽는다. 제품 테스트·추가 성장 측정이 아니다.

상위 PR #84, 최종 기준선 보존 PR #211, 실제 민감도 추적 #212. 원장 수용·제품 기본법칙 변경·릴리스 승격의 근거로 이 보조 관측을 재명명하지 않는다.
