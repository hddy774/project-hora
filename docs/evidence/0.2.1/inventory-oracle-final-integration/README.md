# 성장 연결 보정과 세 복사 경로의 기능 회귀

최종 실행 소스는 `56bbfb2ff3cec2df79fa28234d61a03fe4a50e63`이다. 테스트를 포함한 제품 소스 지문은 `cf17eee7930cc754eda7558d0496f6929d10d64fb9352d0c42ff49a08704f9e3`이다. 루트의 독립된 깨끗한 작업트리 전체 기능 검사 **308/308**, 이 작업의 재고 **68/68**·환전 **9/9**·별도 삼자 대조 **1/1**이 모두 통과했다. 삼자 사례는 재고68에도 포함된다.

다음 원저자 소스를 ancestor로 합류했다. 통합 담당자는 원저자의 제품 수정 코드를 직접 바꾸지 않았다.

두 고정 입력의 전체 명령·재료·법칙·성향·저장 속행은 [fixed-inputs.json](fixed-inputs.json)과 고정 소스 사본에 기록했다. 수동 명령은 유지하고, 거래 입력은 명시 성향4·5=100과 비축3 경계에서 실제 식량7 중3 보유·4 분할 출품 및 구매 인도를 검사한다. 과거751의 즉시 생계 출품 전제를 현재 AI에 강제하지 않는다.

엄격 복사(strict) 원본은 `5fece454`에서 기존 상수 ec01/904c를 유지한 채 먼저 수집했다. 실제 명령·거부·월 경계·저장 재개를 모두 마친 뒤 고정 해시 비교에서만 실패한 원본을 `6b37abf`에 보존했다. 이후 `c6f5ba1`에서 수집된 두 해시를 고정 상수로 명시 재채택했다. 매 실행 actual에서 expected를 생성하거나 단언을 삭제하지 않는다. [수집 출처](strict-capture-provenance.json)와 [채택 패치](fixed-expected-readoption.patch)를 함께 보존했다.

최종 기능 사례는 전체 응답·상태 해시 행과 실제 저장 byte 배열을 직접 비교한다. 실제 경로 카운터는 수동 입력 엄격 `0/0`, JSON `34/0`, 형식화 `34/34`, 거래 입력은 `0/0`, `3/0`, `3/3`이다. 세 경로 모두 처음 보존한 엄격 원본의 전체 행·저장 길이·SHA256과도 일치한다. 처음 수집 이후 Game/Core/Hosting와 공통 fixture·전사 helper는 byte 동일하다. 민감도 전용 CLI 보호 조건은 이번 기능 명령에서 false이고, 두 입력의 실행 본문은 고정 상수·출처 주석 외에 바뀌지 않았다.

`068ecef` 전체305/308의 세 실패는 원문을 보존한 뒤 원인별로 마감했다. 동기화 순수 fixture는 원래 모든 의미 검사를 통과한 상태에서 새 `ai.ecologyFailureMonths=3` 키만 제거하면 옛 a703 해시를 정확히 재현했다. 두 전체 상태 JSON의 다른 모든 필드는 같았다. 이 근거를 먼저 보존한 뒤 고정 상수 한 값만781 해시로 정정했다. 나머지는 실제 전수 요청 출처를 검사하도록 낡은 접두사 기대를 정정한 #180과 손상 압축 오류 경계를 정규화한 #181이다. [원인 진단](sync-ttl-default/provenance.json), [앞선 전체 실패 원문](whole-functional-068ecef.original.json), [최종 전체 통과 원문](whole-functional-56bbfb2.original.json)을 구분했다.

과거751·169·975 단계의 상수·실패 원문·패치 해시는 [이전 근거 폴더](../inventory-oracle-policy-169/)에 그대로 있다. 옛751 전체 전사 원본이 없는 범위에서는 행별 일치를 주장하지 않는다. 최종 소스·패치·보고서·경로 카운터·직접 비교 범위는 [equivalence-provenance.json](equivalence-provenance.json)에 있다. 이 폴더는 기능 정확성 근거이며 비용·성장·네이티브·배포 결과는 별도 보고서에서 판정한다. 앱 기본 재고 경로는 JSON15이고 형식화 복사는 명시 검사에서 선택했다.
