# 재고 검증의 호출 범위 작업·원천·예약 인덱스

기준은 `3ba78ce8d6dd734ebf1ec1a1fb939db34e90d923`, 생산 변경은 `c9758dc1ced8cca1a09d7039db20eaf19f7edd79`다. 기존 N1000 진단에서 확인된 `InventoryValidation`의 원천마다 전체 작업을 순회하는 경로를 좁게 변경했다. 이번 작업은 기능 회귀만 실행했으며 성능·성장·장기 실행·프로파일링을 실행하지 않았다. 새 속도나 최신 전체 기능 합격을 주장하지 않는다.

`ValidationReadIndex`에 검증 한 번 동안만 쓰는 예약/노동/원천 ID 맵과 원래 작업 순서를 보존한 원천별 활성 작업, 예약별 진행 작업, 장비 수리 키를 추가했다. 기존 검증절·문구·단락 순서와 공개 API·clone·validator 호출 수·세계 지문은 유지한다.

원천 수량은 미리 합산하지 않는다. 각 원천의 기존 정의/유한 재고 검증 뒤에 해당 그룹만 원래 작업 순서로 `checked long` 합산한다. 진행 작업의 입력 목록도 원래 예약 검증이 해당 입력에 도달할 때만 읽어 뒤의 잘못된 목록이나 overflow가 앞선 오류를 가리지 않게 한다. 현재 `OutputQuantity`는 int이며 작은 참조에서2×int.MaxValue의 long 합산과 음수 수량의 기존 거부를 확인했다. source-sum overflow를 실제 실행했다고 과장하지 않는다.

| 기능 근거 | 결과 | 범위 |
| --- | ---: | --- |
| 변경 전 새 참조 | 3/3 | 제품 검증기3ba78ce를 변경하기 전에 응답·입력 해시·오류 순서를 수집하고59cfab5에 고정 |
| 변경 후 inventory 필터 | 46/46 | 기존43+새3, 기존 공개 transcript2개 및 검증 어댑터 지문 포함 |
| 변경 후 currency 필터 | 9/9 | 공개 채광/환전·단일 소비·저장/재전송·재원/권한 보존 |

새 참조는 같은 유한 원천의 동시 reserved/processing 작업, 진행 취소의 실제 원천 소비, 이미 소비되어 없는 재료의 예약 연결, 중복 예약/노동·잘못된 연결, 호출 사이 변경, 앞 원천/노동 오류와 뒤 입력/long 회계 overflow의 기존 순서를 다룬다. 검증 전후 입력 해시도 일치해야 한다.

재고46은59cfab5 작업 트리에 생산 변경을 적용한 상태에서 실행했다. 실행한 제품/검사 파일 바이트가c9758dc와 같은지 확인했으며 커밋 후 재실행으로 바꾸지 않았다. 화폐9는c9758dc 커밋 뒤 해당 소스로 빌드해 실행했다. 명령·파일 SHA-256·실제 검사 이름·고정 transcript는 [기계 판독 근거](inventory-validation-commitments.json)에 있다.

OwnedTransaction의 Sync/receipt 변경은 다른 담당자의 별도 작업이다. 이 변경은 두 생산 파일과 새 기능 참조에 한정하며 원장·Notion을 수정하지 않는다. 후속 실제 벤치는 루트가 통합 소스를 고정한 뒤 별도로 수행한다.
