# 개발 규격

이 문서는 앞으로의 개발·리뷰 기준이다. 유지보수와 확장성을 먼저 평가하고, 실제 Android 실행 비용과 저장 호환성을 함께 검증한다. 변경 이유와 검증 결과는 해당 계획·PR에 남긴다.

## 의존성과 위치

| 위치 | 책임 | 허용 의존성 |
|---|---|---|
| `src/AlphaExchange.Core/Domain` | 시장·투자자·회계·이벤트 환경의 상태와 값 계산 | BCL, Core 규칙·도메인 |
| `Core/Simulation` | 시간 진행, 주문, 기관 전략·기업 결산·랜덤 사건 | 도메인·규칙·보고; 저장은 `IHistoryQuery`와 기록 이벤트 경계 |
| `Core/Reporting` | 순위·통계·기간 관측 | 도메인·엔진, 기존 이력 조회 경계 |
| `Core/Persistence` | 체크포인트, SQLite, 이력 조회, 이관·복구 | Core; UI·Android 의존 금지 |
| `Core/Rules` | 버전이 있는 규칙·회사 카탈로그 | 도메인·BCL |
| `src/AlphaExchange.Client` | 플랫폼 공통 생명주기·저장 큐·표시 버퍼·캐시 | Core·BCL; Android 의존 금지 |
| `src/AlphaExchange.Android` | Activity, 입력·화면 이동, Canvas, Android 리소스·파일 선택 | Core·Client·Android |
| `tests/AlphaExchange.Checks` | 회계·시장·이관·저장·공통 모바일 회귀 검사 | Core·Client 프로젝트 참조 |
| `tools` / `scripts` | 측정·배포·자료 검증 도구 | 게임 실행 코드에서 역참조 금지 |
| `docs/guides`, `docs/plans`, `docs/releases` | 현행 규격·작업 계획·설치 안내 | 과거 조사·계획은 `docs/history`, 원자료는 `analysis`, `performance`, `verification` |

새 기능은 가장 가까운 기존 기능 폴더에 둔다. 새로운 게임은 `games/<id>/game.json`에 독립 앱 식별자와 빌드 경로를 등록한다. Core에 네트워크·UI 코드를 추가하지 않는다. 테스트에서 앱 소스 파일을 링크하여 다시 컴파일하지 않는다.

## 파일·타입·함수

- 파일 이름에 소유 타입 또는 기능을 드러낸다. `Models`, `Utils`, `Manager` 하나에 관련 없는 책임을 계속 추가하지 않는다. 직렬화되는 큰 상태 타입은 각각 한 파일에서 속성 순서를 유지한다. 함께 쓰이는 작은 열거형·값 타입은 기능별로 묶을 수 있다.
- `GameEngine`과 `GameStore`의 partial 파일은 같은 상태 소유자의 기능 구분이다. 다른 계층의 동작을 편의상 partial에 넣지 않는다. Android의 `GameView` partial은 렌더링·입력·생명주기 어댑터에 한정하고 공통 정책은 Client로 옮긴다.
- 함수는 하나의 작업을 수행한다. 긴 분기·SQL·자산 평가·회계 누적은 의미가 있는 이름의 작업으로 나눈다. 화면 이동은 `ScreenId`처럼 이름이 있는 타입을 사용한다. 계산식·순위 규칙을 UI에 복사하지 않는다.
- C#은 4칸 들여쓰기, 파일 범위 namespace, nullable을 사용한다. `.editorconfig`와 `Directory.Build.props`를 따른다. 변경하는 함수의 여러 단계와 분기는 줄을 나누어 읽을 수 있게 만든다.
- 실제 두 번째 사용처 또는 독립 수명·실행 경계가 없는 인터페이스, 공통 프레임워크, DI 계층, 빈 폴더, 의미 없는 전달 함수는 추가하지 않는다. 캐시·워커처럼 명확한 상태와 수명을 가진 구성 요소는 구체 타입으로 시작한다.

## Android 실행·메모리

- UI 스레드는 입력·화면 이동·그리기를 담당한다. 새 코드에서 `Task.Wait`, `.Result`, `GetAwaiter().GetResult()`, 상태 복사·압축·디스크 쓰기로 UI를 막지 않는다. 초기 로드, 새 시장 생성, 저장 준비·쓰기, 가져오기/내보내기는 백그라운드에서 수행한다.
- 엔진 상태는 `simulationGate` 아래에서 접근한다. 시뮬레이션 워커는 한 게임 분마다 잠금을 반환한다. 수락한 게임 시간·완료 이력·난수 호출을 최적화를 위해 버리거나 재배열하지 않는다.
- 저장 워커에는 고정된 `SaveSnapshot`만 전달한다. 살아 있는 엔진을 직렬화하지 않는다. 쓰기는 순서대로 실행하고 오래된 대기 캡처는 최신 캡처로 합칠 수 있다. 이력 원본은 모두 최신 캡처에 포함한다. 실패 시 정상 저장과 재시도할 캡처를 보존한다.
- Activity 종료·재생성·초기 로드·새 시장 전환은 공통 비동기 저장 장벽을 사용한다. 백그라운드 시간은 자동 시뮬레이션에 넣지 않는다. UI 콜백 안에서 저장 완료를 기다리지 않는다.
- 반복 그리기는 차트 버퍼·Path·Rect·Paint를 재사용한다. 차트 입력은 먼저 극값·경계·누락 구간을 보존하여 제한한다. 버퍼 한도는 2,048점이며 넘치는 입력을 조용히 잘라내지 않는다.
- 초상화는 실제 화면 밀도와 표시 영역으로 샘플 크기를 정한다. 확대 화면은 필요한 해상도를 유지한다. 현재 아틀라스 캐시는 최대 8개·6 MiB이다. 캐시 소유 바이트 수와 실제 프로세스 PSS는 다른 측정이다. Android 하드웨어 표시 목록이 사용 중일 수 있는 Bitmap을 강제로 recycle하지 않는다.
- 모든 캐시에 한도와 무효화 기준을 명시한다. 엔진·게임 분·거래·기업행동·호가 변경과 일시정지 중 설정 변경을 고려한다. RunId/상태 교체 후 다른 게임의 데이터를 재사용하지 않는다.
- 새 이력 화면은 긴 SQLite 조회를 `OnDraw`에 추가하지 않는다. 기존 화면의 최초 기간·시즌·재무 조회는 일부 동기 경로가 남아 있으므로 변경 시 비동기 전환과 로딩/실패 표시를 함께 검증한다. 반복 프레임에서는 같은 조회를 재실행하지 않는다.

## 호환성과 제거 기준

- 앱 ID와 배포 서명 지문을 유지한다. 저장 형식·스키마 변경은 별도 이관 또는 원본 보관 경계와 회귀 검사를 먼저 만든다. v1.10은 종목 구성 변경에 따라 이전 시장을 원래 파일에 보관하고 상태 9/SQLite 6에서 새 시장을 시작한다. 원본 DB·WAL·체크섬은 변경하지 않으며 사용자에게 전환과 내보내기 방법을 표시한다.
- 현금·주식·예약·대여·배당·세금·부채 보존, 소수점 평가의 decimal 반올림, 세대 교체의 순위 기준, 가격/시간 우선 체결을 유지한다. 성능 때문에 금융 계산을 부동소수점 근사로 바꾸지 않는다.
- 중복 계산, 중복 소스 컴파일, 사용하지 않는 설정·전달 계층·빈 구조는 제거한다. 제거 전 참조·빌드·실행 경로를 확인한다. 실제 이전 저장 이관, 오류 복구, 규칙 데이터, 라이선스·원본 검증 기록은 사용처가 확인되면 보존한다.
- 서명키·비밀번호·개인키·APK·빌드 결과는 개발/main에 넣지 않는다. APK는 GitHub Releases에 둔다. 직접 업로드가 불가능할 때만 임시 업로드 브랜치를 사용하고 검증 후 삭제한다.

## 시장·AI 개발 원칙

- 의사결정 AI는 기관 투자자와 추세를 따르는 개미에 한정한다. 제거된 경영자·정치인·금융인·직원 AI, 고용·선거·투표·사업 프로젝트를 새 기능의 편의 계층으로 다시 만들지 않는다.
- 회사 카탈로그는 5업종 × 3종목 = 15슬롯이다. 파산·합병 후 대체 상장은 같은 슬롯에 새 증권 ID를 부여하고 실제 자금으로 조달한다. 슬롯을 늘리거나 옛 종목의 장부를 다른 종목으로 바꾸지 않는다.
- 경영·정책·금융의 변화는 저장 가능한 시드 난수의 사건이다. 가격 신호는 이벤트 → 투자자의 주문 → 가격/시간 우선 체결 → 주가 순서로 전달한다. 배당락·분할 등의 회계상 조정은 별도 기업행동으로 기록한다.
- 기관 전략에 이익을 직접 지급하거나 상대방 자금을 임의로 차감하지 않는다. 모든 매매·공매도·대출에는 실제 자금·주식·대여·담보·예약 한도가 필요하다. 위험 청산과 신규 진입 가격 한도는 별도로 판단한다.
- 종목 계획은 하나의 포트폴리오 예산으로 계산하고, 대기 주문까지 합쳐 현금·종목·업종 한도를 검사한다. 재평가 빈도와 체결 빈도를 구분한다. ‘지능 몇 배’는 단정하지 않고 판단 기회·위험 위반·비용·손익의 측정값을 제시한다.
- 화면에 표시하는 회계·위험 계산의 원본은 Core Reporting이다. 금융 계산은 정확한 원 단위로 보관하고 축약은 표시에서만 수행한다. 신규 금액 보고는 축약/정확값 전환 또는 상세 확인을 제공한다.
- 삭제된 기능의 설정·모델·메뉴·이미지·테스트 전제를 함께 제거한다. 과거 버전 소스·검증 근거는 Git 이력과 역사 문서에 남긴다. 현행 테스트는 고정 슬롯·투자자 거래·현금 보존·보관본 원본 보존을 검증한다.

## 완료 조건

1. 작업 계획과 Draft PR을 먼저 만들고 단계별 체크 결과를 기록한다.
2. `python3 scripts/check-architecture.py`, 게임 카탈로그·서명·화면 좌표·아트워크 검사를 통과한다.
3. 변경 영역 회귀 검사와 전체 `python3 scripts/games.py check alpha-exchange`를 통과한다. 구조 변경은 Android Release 빌드까지 확인한다.
4. 성능 변경은 같은 체크포인트·시드·런타임·측정 순서로 기준/변경을 비교한다. 전체 상태 SHA-256, 체결 수, 난수 상태, 미처리 시간, 저장 이력 범위를 비교한다. 원자료와 기기/호스트 조건을 공개한다.
5. Android 생명주기, 화면·모달, 구형 원본 보관과 현행 저장 재개, 100배속·쓰기 병행을 네이티브 실행으로 검증한다. 호스트 미세 측정을 실제 기기의 FPS·배터리 결과로 표현하지 않는다.
6. 검증 후 PR을 반영하고 같은 배포키로 APK를 서명한다. 실제 인증서·버전·권한·ABI·공개 다운로드 파일 해시를 확인한다.
