## 의결과 경제 효과

안건은 매월 공개하고 72시간 후 마감합니다. 마감 시의 실보유 주식이 표의 가중치이며 자사주에는 의결권이 없습니다. 개인 표는 찬성/반대/기권으로 합산합니다. 은행은 안정·현금·부채·경기를, 기관은 능력과 성향을, 개인은 관측 가격 반응만 사용합니다. 유효 표가 전체의 1/3 이상, 찬성이 반대보다 많고 전체 의결권의 25% 이상이면 가결됩니다. 게임은 관찰형이며 AI 주주가 자동 투표합니다.

성장은 매출 1.10/운영비 1.06/기본 투자 35%, 가치는 1.02/0.97/20%, 방어는 0.93/0.85/10%를 적용합니다. 비용 효율은 운영비를 추가로 6% 줄이고, 설비 확장은 매출 3%/운영비 2%/투자 10%p를 늘립니다. 유동성 방침은 투자 절반·현금 완충·은행 상환을 적용합니다. 재투자는 투자 비중 +15%p/배당 최대 8%, 자사주는 최대 10% 배당과 여유 현금의 8% 매입, 배당 정책은 최대 45%를 지급합니다. 모든 지급은 보유 현금과 완충 한도를 따릅니다. 기본 자사주 목표는 65%이며 자사주 소각은 별도 기업행동입니다.

## 파산과 기록의 연속성

기관/개인은 일별 순자산이 0 이하이면 파산하며, 주식 없는 개인의 생활·거래 자금이 1,000원 이하이면 자금 소진으로 교체합니다. 새 투자자의 최초 24시간과 재출자 대기 상태는 반복 파산을 피합니다. 기업은 자본잠식 또는 적자와 운영 자금 부족이 3결산 이어지면 청산합니다.

기업 청산은 실제 실물 경제 자금으로 할인 자산 매각 → 은행/운영 채권 회수 → 남은 주주 분배 순서로 처리합니다. 공매도는 반환 의무를 정산하고, 현금 없는 세금/대체배당은 부채로 인식합니다. 투자자는 현금·현물 주식을 회수하고 미납 대출/공매도/벌금/세금을 별도 미회수로 기록합니다. 회수하지 못한 대여 주식을 새로 만들지 않습니다.

새 기관 1,000만원/개인 10만원은 실물 경제 자금으로 출자합니다. 새 기업은 은행이 1,000주를 납입하고 기업이 1,000주를 자기 보유하며, 설비 투자는 실제 송금합니다. 재원이 부족하면 대기합니다. 재출자는 이익으로 계산하지 않습니다. 기관/개인은 슬롯과 세대를, 기업은 새 식별자와 세대를 사용합니다. 과거 시즌의 이름/그림/세대와 실패 당시 재무제표를 보존합니다.

SQLite에 시간별 기록·상태·주총·파산·옛 회사 결산을 한 트랜잭션으로 확정합니다. 화면 캐시는 최근 64개 실패/제한된 주총만 유지하고 파일에는 전체 사건을 남깁니다. 파산 기록은 60개씩 과거 조회합니다. 기존 DB/ZIP 이름과 스키마 5의 테이블을 확장하며 상태는 버전 6입니다. 기존 저장 보유를 50:50으로 다시 나누지 않습니다. 이전 기록에 없는 새 투자 손익 지표는 없던 과거 값을 만들지 않습니다.

Android 업그레이드 실행에서 v5 통계를 새 필드가 있는 JSON으로 재저장하면 기존 체크섬과 충돌하는 문제를 확인했습니다. 연결 시 이미 확정된 시간/해상도를 조회해 다시 인코딩하지 않고 빠진 기록만 저장합니다. 기존 파일 12개 통계의 해시 보존과 39→45시간의 실제 연속 저장, 혼합 v5/v6 ZIP 가져오기 후 저장 회귀를 통과했습니다. 동일 키에 다른 내용이 들어오는 요청은 원자적으로 거부합니다.

## 후속 개선 후보

- 실제 주식 대차의 대여자 권리 회수, 주총 기준일/정족수/특별결의를 별도 모델로 확장.
- 실물 경제 수요·생산성·산업별 공급 제약, 재출자 대기 회사의 구조조정/회생안.
- 은행 자체 자본 적정성·유동성 스트레스와 정부의 예산 제한 구제 금융.
- 장기간 행위별 손익 분석과 기관의 거래 비용 대비 주문 빈도 조정. 수익을 강제로 보장하지 않는 다중 시드 평가.
- 물리 ARM64 기기에서 실제 100배속 처리량·프레임·RAM·저장 지연 측정. 이번 Linux CPU/소프트웨어 에뮬레이터 검증과 구분.
