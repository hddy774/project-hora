# v1.10.0 비용과 계획 재평가 측정

동일 Linux/.NET 9.0.20 Release, 4 vCPU 호스트에서 시드 20261004, 기관 100곳, 개미 10,000명, 기관별 10억·개미별 5천만·시총 1조를 맞췄다. 이전 버전은 `alpha-exchange/v1.9.0`, 현재 Core는 `a74d9a1`이다. 이전 측정 도구에서 초기 인구와 개미별 자금, RunId만 고정한 [패치](baseline-tool.patch)를 제공한다. 게임 규칙·종목 수·AI가 달라 이전 체크포인트를 새 버전에서 읽지 않는다. [전체 조건](conditions.json)을 함께 확인한다.

순서는 이전 → 현재 → 현재 반복 → 이전 반복이다. 동시에 다른 빌드·호스트 시뮬레이션을 실행하지 않았다. 저장·통계는 각 시장을 168시간 진행한 뒤 500ms 이상 워밍업하고 9회, 실제 쓰기는 5회 측정했다. 아래 시간 범위는 두 실행의 중앙값 범위이며 표본·최대값은 JSON/로그에 있다.

| 지표 | v1.9 조건 통제 | v1.10 | 해석 |
|---|---:|---:|---|
| 종목 수 | 30 | 15 | 요청에 따른 시장 축소 |
| 저장 준비 시간 | 11.10~13.27ms | 9.18~9.25ms | UI 밖에서 상태 분리 |
| 저장 준비 관리 할당 | 12,343,160B | 9,904,360B | 약 19.8% 감소 |
| 168시간 체크포인트 JSON | 5,298,075B | 4,485,675B | 약 15.3% 감소 |
| 직렬화 중앙값 | 68.13~93.84ms | 51.28~77.90ms | 변동·범위 겹침; 일정 배수 개선 주장 안 함 |
| 준비~압축~DB 쓰기 | 100.86~102.10ms | 97.89~99.60ms | 전체 쓰기 비용 포함 |
| 720시간 엔진 실행 | 2.72~3.06초 | 5.30~5.64초 | 더 빈번한 AI 판단으로 계산 비용 증가 |
| 계획 재평가 | 11,542회 | 173,789회 | 약 15.06배; 지능·수익률 배수가 아님 |
| 실제 체결 | 261,849회 | 379,734회 | 서로 다른 전략 결과 |
| 기록·저장 포함 43,200분 실행 | 8.19~9.60초 | 10.67~12.54초 | 모두 43,200분 완료, 대기 0, 이력 연속 |

두 현재 실행의 최종 전체 상태 SHA-256은 `385BB173E25EDEA4FDDFBE8606C4393B2C97FA6C0277423987969E7974DC6B31`, 난수 상태는 1206739988로 같다. 이전 버전 반복도 같은 해시·체결·난수 상태였다. 의도적인 규칙 변경 때문에 서로 다른 버전 사이의 상태 해시 일치는 요구하지 않는다.

합성 5년의 43,201개 시간별 원기록 조회/경계/누락/저장을 별도로 검증했다. `fiveYearRangeCold`는 캐시를 비운 조회, `fiveYearRangeCached`는 재조회다. 호스트 GC·파일시스템 변동이 있어 단일 조회 배수를 일반화하지 않는다. 별도 `--storage-load`의 백업·복원·경계 검증 원자료는 [저장 검사](../../verification/v1.10.0/storage-load.log)에 있다.

삭제된 인물의 10개 이미지 아틀라스를 제외해 APK는 이전 101.16MB에서 약 73.8MB로 약 27.1% 줄었다. APK 크기, 관리 힙 할당, 실제 Android PSS는 서로 다른 지표다. 실제 기기 FPS·배터리·수익률 개선이나 ‘지능 두 배’의 근거로 쓰지 않는다. 네이티브 실행 결과는 [Android 검증](../../verification/v1.10.0/README.md)에 기록한다.

재현: 각 버전에서 `tools/PerformanceAudit`를 Release로 빌드하고 생성된 DLL에 `label output.json --max`를 전달한다. 현행은 기본 인구가 10,000명이므로 `--max` 없이도 같은 시나리오다. 비교 시 이전 도구 패치를 적용하고 네 실행을 순서대로 실행한다. 도구는 실행 후 측정용 임시 DB를 지운다.
