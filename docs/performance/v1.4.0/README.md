# v1.4.0 성능 측정

같은 Linux VM/.NET 9 Release, 시드 20261004, 회사 30개·기관 100개·개인 10,000명, 동일한 측정 프로그램을 사용했다. 개선 전 엔진은 `06501b46e941ff3e1f979e19e59d3899e6fd3046`, 개선 후 엔진은 `c558578aa4493657f341037e36c5f6b2436f9acd`이다. [재현 프로그램](../../../tools/PerformanceAudit/README.md), [개선 전 원자료](baseline.json), [개선 후 원자료](optimized.json), [전체 비교 CSV](comparison.csv)를 보관한다.

각 항목을 워밍업하고 강제 수집한 뒤 9회(쓰기/범위/누락 검사 5회) 실행했다. 아래 값은 중앙값이며 원자료에는 모든 시간 표본과 최대값을 포함한다. UI 에뮬레이터는 채택한 측정 중 실행하지 않았다. 최초 개선 측정은 에뮬레이터 시작과 겹쳐 제외했으며, 최종 순자산 순회 변경 후 다시 측정한 결과를 기록했다.

저장 준비는 모든 변경 가능 상태를 분리 복사하고 인코딩을 지연한 비용이다. 실제 JSON 인코딩은 단일 백그라운드 작업자가 수행하고, 전체 쓰기에는 인코딩·압축·체크섬·JSON 전체 검증·트랜잭션을 포함한다. 순수 직렬화 계산과 전체 상태 복사/GC 비용은 남아 있고, 전체 쓰기 할당은 3.1% 증가했다. 연속 여부 검사도 시간이 15.2% 증가했으며 헤더 43,201개의 관리 객체 생성을 연속 구간 조회로 줄여 할당은 99.94% 감소했다. 모든 지표를 함께 기록하여 개선 폭의 범위를 구분한다.

합성 저장은 5×360일×24시간과 초기 기록, 총 **43,201행**, 개선 전후 모두 **91,627,520바이트**다. 표시 지점은 500개 이하이고 첫/마지막 기록 및 연속성을 확인했다. 경제를 5년 진행한 결과는 아니다.

별도 720시간 시뮬레이션의 실제 매칭은 전후 모두 **55,427건**이다. 시간 중앙값은 3.21→3.55ms, p95는 7.82→6.52ms, p99는 11.04→10.62ms다. 전체 시뮬레이션 중앙값은 10.6% 증가했고 p99는 3.8% 감소했다. 양쪽 모두 100배속의 시간당 50ms 예산 이내다. OS 스케줄링·GC·JIT의 변동이 있으며 단일 VM 측정으로 모든 기기의 처리량 향상을 보장하지 않는다.

숫자는 처리 시간과 현재 스레드의 누적 할당량이다. 프로세스의 상주/최대 RAM, 물리 Android의 FPS·메모리·저장 커밋 지연으로 해석하지 않는다. 지분 모델은 현재 회사 하나를 캐시하며, 기록 원본의 삭제나 저장 빈도에 따른 시간 기록 생략으로 얻은 개선은 없다.
