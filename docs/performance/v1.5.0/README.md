# v1.5.0 성능 측정

같은 Linux VM/.NET 9.0.20 Release/4 CPU, 회사 30개·기관 100개·개인 10,000명, 동일한 측정 프로그램을 사용했다. 개선 전 엔진은 `9ea98f3252a5418c6c76793944a957ed12c8a5c0`, 최종 엔진은 `b0d9395f809aa7eb3022d075c811e39341e10aba`다. [재현 프로그램](../../../tools/PerformanceAudit/README.md), [전 원자료](baseline.json), [후 원자료](optimized.json), [전체 비교 CSV](comparison.csv)를 보관한다.

집계/저장은 v1.4에서 시드 20261004로 168시간 진행해 만든 **같은 v5 JSON**을 읽었다. 입력은 21,426,282바이트, SHA-256 `b161e726bab28a2fa04ac6c9ac5164eceb3ef8f7e29df86cd14620408558a812`다. v1.5는 현금·가격·보유·회계를 보존하여 v6으로 이전한다. 측정과 별개인 엔진을 168시간 진행해 양쪽의 같은 경로를 워밍업하고, 각 항목을 한 번 실행한 뒤 GC 수집 후 9회(쓰기/범위/연속 검사 5회) 표본을 모았다. 에뮬레이터·빌드·로컬 검사·다른 측정은 동시에 실행하지 않았다.

| 항목 | 개선 전 | 개선 후 | 중앙값 변화 | 현재 스레드 할당 전 → 후 |
|---|---:|---:|---:|---:|
| 전체 재무 집계 | 1.82ms | 1.60ms | -12.5% | 6,008 → 6,056B |
| 저장 준비 (화면 스레드) | 26.78ms | 12.22ms | -54.4% | 24,324,424 → 11,928,304B |
| 단독 전체 JSON 인코딩 | 133.54ms | 79.47ms | -40.5% | 42,852,904 → 25,041,504B |
| 준비 포함 전체 쓰기 | 340.35ms | 137.86ms | -59.5% | 94,183,056 → 45,699,472B |
| 5년 전체 범위 조회 | 289.65ms | 286.95ms | -0.9% | 41,608,008 → 32,799,920B |
| 연속 기록 검사 | 108.51ms | 80.54ms | -25.8% | 5,936 → 5,792B |
| 마지막 시간 조회 | 0.85ms | 0.43ms | -49.4% | 111,984 → 93,584B |

저장 준비는 실제 인코딩/파일 완료와 분리한 깊은 복사 비용이다. v6에서 사용하지 않는 개인 UI DTO를 복사하지 않고, 0 배열을 SIMD 바이트 검사로 생략한다. 모든 인코딩 대상 변경 가능 배열·객체는 분리하며 원본 시간 기록은 생략하지 않는다. 비제로 비트(음의 0 포함)가 있는 배열은 소유 복사본을 유지한다. 개인의 실제 보유, 빈 공매도 배열·음의 0, 능력을 저장 준비 후 변경해도 고정 JSON이 변하지 않는 회귀를 통과했다.

같은 상태의 JSON은 **21,426,282→5,533,924바이트(−74.2%)**다. 쓰기 할당은 94,183,056→45,699,472바이트(−51.5%)이며 직렬화 할당은 41.6% 감소했다. 재무 집계의 할당은 새 손익 필드로 48바이트 증가했다. 단독 직렬화 최대 표본은 155.23→361.37ms로 증가했으므로 중앙값만으로 지연 상한 개선을 주장하지 않는다. GC/JIT/스케줄링 변동을 포함하는 모든 표본을 보관한다.

5년 항목은 360일/년의 합성 저장 **43,201행**이며 경제를 5년 실행한 결과가 아니다. 표시 지점은 500개 이하이고 경계/연속성을 확인했다. 범위 조회의 중앙 시간은 거의 같고(−0.9%) 할당은 21.2% 감소했다. 파일은 91,627,520→61,911,040바이트다. 두 버전의 신규 초기 지분/기관 보유와 스냅샷 필드가 달라 파일 감소 전체를 저장 코드의 압축 개선으로 해석하지 않는다. 마지막 시간 조회는 v1.4가 이미 저장한 마지막 점을 다시 대기열에 넣는 경로였고, v1.5는 디스크의 확정 점을 읽는다. v1.5는 확정 시간별 기록이 있는 날의 일별 복사본을 불필요하게 재큐잉하지 않아 연속 검사에서 전체 헤더 객체 생성 경로도 피한다.

별도의 신규 시장 720시간 매칭은 **55,427→124,400건**이다. 시간 중앙값 **4.18→2.29ms**, p95 **9.45→4.54ms**, p99 **14.21→7.12ms**다. 초기 지분·개인 AI·은행 매매·주총이 바뀌어 체결 경로가 다르므로 같은 거래를 처리한 코드 속도 비율로 해석하지 않는다. 양쪽 p99가 100배속 시간당 50ms 예산 이내다.

현재 스레드 누적 할당은 프로세스의 상주/최대 RAM이 아니다. Linux 처리 시간은 물리 Android FPS·실제 100배속·저장 커밋 지연이 아니다. 백그라운드 저장도 CPU/GC를 사용하고, 여전히 10,100명 복사와 전체 JSON 인코딩 비용이 남는다. 물리 ARM64 측정과 증분 상태 체크포인트는 후속 후보로 기록한다.

## 측정 중 발견과 수정

초기 예비 [전](pilot-baseline.json)/[후](pilot-optimized.json)는 입력 생성과 입력 읽기의 워밍업 경로가 달라 최종 전후 비교에서 제외했다. 같은 고정 입력과 워밍업을 맞춘 [스칼라 배열 검사 단계](scalar-optimized.json)는 준비 중앙값 49.83ms/11,928,304바이트였다. 최종 SIMD 검사는 12.22ms로 줄었으며 최종 버전과 비교 원자료를 위 표에 사용한다. 중간 성능 수치와 시간 최대값을 삭제하거나 유리한 표본만 고르지 않았다.

```sh
# v1.4 worktree에 현재 tools/PerformanceAudit/Program.cs를 복사해 같은 측정기를 사용한다.
dotnet run --project tools/PerformanceAudit -c Release -- create /tmp/create.json /tmp/absent.json /tmp/fixed-v5.json
dotnet run --project tools/PerformanceAudit -c Release -- v1.4.0-fixed /tmp/before.json /tmp/fixed-v5.json
# v1.5 worktree에서 같은 파일을 읽는다.
dotnet run --project tools/PerformanceAudit -c Release -- v1.5.0-vector /tmp/after.json /tmp/fixed-v5.json
```
