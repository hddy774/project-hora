# v1.6.0 성능 측정

2026-10-05 UTC. Linux .NET 9.0.20, 동일 컨테이너·SDK·입력·하네스로 v1.5.0(`3cfb67e`)과 v1.6.0(`8a13215`)을 순차 측정했다. 두 실행 중 다른 빌드·에뮬레이터·장기 분석은 실행하지 않았다. 측정 전 별도 168시간 실행으로 JIT 경로를 예열했다. 고정 입력은 v1.5 시드 20261004의 168시간 상태이며 SHA-256은 `f4a8952a5b1e5de7d98b4537f25b6542f839bc85ec97081a3fc8c2007d9fee02`다. 양쪽 하네스 파일의 SHA-256은 `7529aba5e9ba1c4abd09d312b2f1a4cb73165d198982b1549e0184941134015a`다.

[원본 전](baseline.json) · [원본 후](optimized.json) · [전체 비교 CSV](comparison.csv) · [재현 하네스](../../../tools/PerformanceAudit/Program.cs). 각 시간/할당 측정은 예열 1회 후 9회(전체 저장·5년 조회는 5회)이며 모든 시간 표본을 보존했다. 최초 비교 [전](pilot-baseline.json)/[후](pilot-optimized.json)와 고평가 은행 수정 중간 단계 [측정](bank-stage.json)도 보관한다. 중간 단계의 5년 조회는 568ms로 흔들렸으며 마지막 전/후를 연속 실행해 다시 측정했다. 좋은 표본만 선택하지 않고 전체 경과를 남긴다. 은행 수정 후 [전](bank-baseline.json)/[후](bank-optimized.json)의 중앙값은 시뮬레이션 약11% 증가였다. 마지막 가격 안전·급여 예산·과잉 현금 정기 검토 수정 후 다시 연속 측정한 결과가 아래 최종 표다.

같은 금융·주식 상태에 성장·직원·기간·규칙 필드를 추가한 체크포인트는 5,880,808→5,970,102바이트(약1.5% 증가)다. 새 기능의 복사·직렬화·저장 비용이 증가한 것도 기록한다. 호가 집계와 화면의 중복 작업을 줄였으나 전체 엔진 처리량이 더 빨라졌다고 주장하지 않는다. 이 측정으로 저장 전체가 더 빠르다고 주장하지 않는다. 대량 직렬화는 기존처럼 분리 복사 후 단일 백그라운드 작업자가 처리한다.

위 표는 `8a13215`에서 측정한 원자료다. 이후 `a8e7d9d`/`c1d9e063`에서 은행의 고평가 기준과 관측 매도 호가 집행을 보정했다. 통계/호가/저장 알고리즘은 동일하지만 새 게임의 매매 경로는 다시 바뀌었다. 아래 720시간 값은 측정 당시 경로이며 최종 배포 소스의 처리량 수치로 사용하지 않는다. 최종 소스의 16시즌 CI 관찰값은 [전체 검증](../../../VERIFICATION.txt)에 따로 남긴다.

## 시뮬레이션 경로와 화면 작업

두 버전은 같은 시드로 새 게임 720시간을 진행하지만 기관의 판단·유동성 규칙이 달라 실제 매매 경로가 다르다. 시간당 p50 2.310→2.184ms(약5% 감소), p95 4.137→4.106ms, p99 5.533→5.757ms다. 체결도 124,400→142,938건으로 달라지므로 동일 주문 경로의 최적화 수치로 해석하지 않는다.

전체 포트폴리오를 판단했으면 주문 후보로 선택되지 않은 보유 종목도 다음 검토 시각을 갱신한다. 안정된 장기 포트폴리오가 매 시간 전체 분석을 반복하지 않는지와 중요한 뉴스가 즉시 재검토를 유발하는지를 별도로 검사했다. 종목/분야 가치 단일 집계, 제한된 후보 배치, 예약이 없는 주문 취소 생략, 분야 매핑 재사용을 적용했다.

화면은 상태/시간/원장/기업행동/호가 변경을 키로 순위와 잔량을 재사용한다. 한 글자씩 반복 측정하던 줄바꿈을 Paint.BreakText로 바꾸고 터치 영역의 RectF 객체 할당을 줄였다. 틱100ms와 프레임250ms, 최대 대기8시간/틱 작업 예산14ms를 규칙에서 조정한다. 한 시간 진행은 원자적으로 끝내므로 단일 시간이 예산을 넘을 수 있다. 지연 시 실제 진행 속도를 낮추고 수락한 대기 시간은 저장한다. 완료한 게임 시간의 통계를 버리는 방식은 사용하지 않는다.

## 한계와 후속 개선 기록

- 중앙값·최대 표본은 GC·JIT·공유 호스트·디스크 영향이 있다. 전체 원자료를 보존했고 작은 차이를 확정적인 개선으로 표현하지 않는다.
- 할당은 현재 스레드의 누적 할당량이며 프로세스 RAM·Android FPS가 아니다. 소프트웨어 에뮬레이터 확인도 물리 기기의 성능을 증명하지 않는다.
- 직원/규칙/보유 기간이 추가돼 저장 크기·전체 쓰기·최대 직렬화 지연은 증가했다. 향후 규칙의 불변 표현, 델타 체크포인트, 더 긴 저장 간격을 회계·복원 정확성과 함께 검토할 수 있다.
- 5년 자료는 저장 부하를 위해 생성한 통계이며 5년간 경제 시뮬레이션 결과가 아니다. 이번 버전은 해당 SQLite 조회 알고리즘을 바꾸지 않았다.
