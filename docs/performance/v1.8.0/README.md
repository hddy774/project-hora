# v1.8.0 성능 검증

기준은 main `0ed09dc`, 최적화 코드는 `437a1af`이다. 같은 시드 20261004, 168시간 진행한 30개 회사·100개 기관·200명·개미 10000집단의 **동일 저장 입력**을 두 코드에서 읽었다. [입력 출처와 해시](input.json), [기준 원자료](baseline.json), [최적화 원자료](optimized.json), [비교 CSV](comparison.csv)를 제공한다. Linux/.NET 9.0.20 Release, 공유 4 CPU 환경이다. 아래 비교 동안 이 작업의 다른 빌드 프로세스는 멈췄다.

720시간 뒤 전체 GameState JSON SHA-256은 양쪽 모두 `9C5521907CAB16760871A4EF64A1A7B35BF533256D69DDC0319758C8479077E5`다. 체결 365052건, 난수 3836019562도 같다. 인구·규칙·완료 분·계획 순서와 원장을 바꾸지 않았다.

저장 쓰기의 현재 스레드 할당은 **35238112 → 23593896바이트로 33.0% 감소**했다. UTF-8 바이트를 바로 만들어 같은 바이트로 구조 검증·해시·압축을 수행한다. Json을 요청하는 호출자만 UTF-16 문자열을 만든다. record의 Json 교체는 바이트 캐시도 새로 만들며 원래 체크포인트는 변하지 않는다. 원시 JSON 표현·체크섬 의미·트랜잭션 내구성은 유지한다.

개미 능력 검사에서 10000개의 임시 배열을 없앴고, 희소 포지션 기록은 값이 모두 0인 행을 SIMD 검사로 건너뛴다. JSON 문자열 직렬화 할당은 **11781288 → 11141288바이트로 5.4% 감소**했다. 음수 0을 포함한 비영 비트와 비어 있지 않은 보유·원가·예약을 그대로 기록한다. 기관 투자 계획은 매 재검토 시 현재 회사 식별자로 버퍼를 채워 반복 전체 탐색을 줄인다. 경쟁 기관의 계획과 저장 목록 순서를 보존하며 보고서·집행 직원 탐색의 클로저 할당도 없앴다.

가상 36초의 100배속으로 43200게임분을 수락하고 20게임시간마다 실제 저장한 시나리오는 **8772.696 → 8029.766ms로 8.5% 단축**, 처리량은 **4924 → 5380게임분/초로 9.3% 증가**했다. 양쪽 모두 완료 43200분, 대기 0분, 원시간 기록 연속성 검사를 통과했다. 저장을 뺀 720시간 총 처리 시간은 3139.149 → 3213.618ms로 오히려 2.4% 늘었다. 모든 경로가 빨라졌다고 주장하지 않는다.

공유 호스트의 GC·JIT·스케줄링 편차가 있다. 별도 [첫 최적화 표본](optimized-first.json)은 같은 최종 상태에서 저장 포함 8077.926ms, 엔진 총 2847.562ms였다. 일부 통계·호가·저장 중앙값과 p95는 느려졌고 그대로 공개한다. 할당 바이트는 앱의 최대 RAM이 아니며 Linux 처리량은 실제 휴대전화 FPS를 뜻하지 않는다. 긴 범위 조회와 UI 프레임 경로는 이번에 변경하지 않았다.

## 동작 검증

- 전체 16시즌: 41247123개 검사, 5058975건 체결, 미확정 대기 0. 현금·주식·담보·수익/현금흐름·구형 저장/ZIP·파산/기업행동 검사를 통과했다.
- 새 저장 검사: 실제 디스크 쓰기와 4개 JSON 읽기 작업을 동시에 실행하고, live 게임을 먼저 진행해도 저장된 분과 원장이 같음을 확인했다. record Json 교체와 원본 재사용도 확인했다.
- 느린 CI 실행에서 v1.6의 프레임 검사가 분 단위 진행에도 한 프레임에서 완성된 시간이 있어야 한다고 가정한 오류를 발견했다. 분 진행·작업량 상한·완료/대기 분 합계와 저장 후 정확한 재개를 검사하도록 수정했다. 실제 프레임 예산과 시계 구현은 변경하지 않았다.
- Python 39개 검사와 200명 그림 무결성 검사를 통과했다.
- 합성5년 저장: 원본 시간별 기록43201행, DB91164672바이트, 조회107점, 체크포인트 복원·전체 ZIP 내보내기를 통과했다. [원자료](../../verification/v1.8.0/storage-load.txt). 기존 검사 도구가 시간만 옮기고 분 시계와 선거 예정 시간을 남겨 둔 오류를 수정했다. 실제 경제5년 시뮬레이션을 뜻하지 않으며 게임의 체크포인트 검증 조건은 완화하지 않았다.
- Android API26 x86_64 네이티브: 구형 통계 177행의 해시 보존, 200명 그림/확대, 백그라운드 중 정지, 화면 재생성, 세 높이의 모달 스크롤/버튼, 100배속 재개를 통과했다. [네이티브 원자료](../../verification/v1.8.0/native-smoke.json), [Actions](https://github.com/hddy774/project-hora/actions/runs/38128439828).

## 재현

```sh
git worktree add --detach /tmp/hora-baseline 0ed09dc1d42572541d7c75668de4faa006009fe9
cd /tmp/hora-baseline
dotnet run --project tools/PerformanceAudit -c Release -- input /tmp/hora-input-report.json --max /tmp/hora-input.json
dotnet run --project tools/PerformanceAudit -c Release -- baseline /tmp/hora-baseline.json /tmp/hora-input.json
cd /path/to/optimized/project-hora
dotnet run --project tools/PerformanceAudit -c Release -- optimized /tmp/hora-optimized.json /tmp/hora-input.json
```

메트릭은 워밍업·강제 GC 후 9회, 쓰기와 장기 조회는 5회 표본의 중앙값이다. 입력 생성 실행의 시뮬레이션 결과는 고정 입력 비교의 분모로 쓰지 않는다. 원본 입력의 RunId는 생성 시마다 다르므로 전후 같은 파일을 사용해야 전체 상태 해시를 비교할 수 있다.
