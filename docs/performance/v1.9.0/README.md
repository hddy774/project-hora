# v1.9.0 성능 검증

같은 최대 인구 체크포인트에서 경제 동작을 유지하며 모바일 표시·순위·통계 비용을 줄였다. 모든 최종 실행의 720시간 뒤 전체 상태 SHA-256은 `9C5521907CAB16760871A4EF64A1A7B35BF533256D69DDC0319758C8479077E5`, 체결은365,052건, 난수 상태는3836019562로 기준 버전과 일치한다. 저장을 포함한100배속 시나리오는43,200분을 모두 완료하고 대기0과 전체 이력 범위를 확인했다.

## 동일 실행 파일로 3회 비교

Linux/.NET9.0.20, 4 CPU, 시드20261004, 168시간 상태의100개 기관·10,000개 개미 집단·30개 회사·200명 인물을 사용했다. 같은 측정 실행 파일에서 기준 Core DLL과 변경 Core DLL을 각각 읽었다. 각 버전을 독립 프로세스로3회, 기준/변경 순서로 번갈아 실행했다. 로컬 빌드·다른 검사를 병행하지 않았다. 각 미세 경로는 최소500ms 준비 후9회(쓰기·범위·누락은5회) 측정했다. 표는 실행별 중앙값의 중앙값이며 원본 표본은 모두 보관한다.

| 항목 | v1.8 기준 | v1.9 | 변화 |
|---|---:|---:|---:|
| 전체 재무·시장 통계 | 1.644ms | 1.476ms | 10.2% 감소 |
| 엔진720시간 총 시간 | 3.361s | 3.204s | 4.7% 감소 |
| 저장 포함100배속43200분 | 10.285s | 9.621s | 6.5% 감소 |
| 저장 준비 | 9.551ms | 9.897ms | 3.6% 증가 |
| JSON 직렬화 | 53.420ms | 57.695ms | 8.0% 증가 |
| 준비·압축·검증·디스크 쓰기 | 103.897ms | 102.112ms | 1.7% 감소 |
| 합성5년 최초500점 조회 | 201.294ms | 226.135ms | 12.3% 증가 |
| 합성5년 캐시 조회 | 2.700ms | 2.965ms | 9.8% 증가 |

통계는 주가를 한 번 캡처하여 가격/소수점 여부 조회를 줄인다. 소수점 평가에는 기존 decimal midpoint rounding을 유지한다. 저장과 SQL 조회의 관리 할당은 거의 동일하다. 직렬화·조회는 더 빠르다는 주장을 하지 않는다. 특히 기준 직렬화의 실행 중앙값은49.9~153.6ms로 변동했고, GC·계층 JIT·공유 호스트·파일 I/O의 영향을 함께 고려해야 한다. ## 공통 표시 코드

[공통 코드 측정](client.json)은 v1.8의 참고 알고리즘과 최종 공통 코드를 한 프로세스에서 비교한다. 경로별 최소500ms 준비와11개 표본을 사용했다. 차트는500점 입력1,000회, 순위는100기관 순위100회이다. Android Canvas 호출과 화면 문자열 생성은 포함하지 않는다.

| 항목 | 참고 시간 → 변경 시간 | 현재 스레드 할당 |
|---|---:|---:|
| 차트 복사·최솟값·최댓값 | 1.491ms → 1.163ms | 4,024,000B → 0B |
| 화면 순위 계산·정렬 | 0.779ms → 0.423ms | 1,001,600B → 245,600B · 75.5% 감소 |
| Core 현재 시즌 순위 | 3.932ms → 0.716ms | 3,490,400B → 331,200B · 90.5% 감소 |

차트는 준비된 버퍼와 .NET의 vectorized Min/Max를 재사용한다. 실제 화면의 LINQ 입력에는 열거자·투영 등의 작은 할당이 남을 수 있으며 전체 프레임 할당0이라는 뜻이 아니다. 순위는 UI의 별도 계산을 제거하고 Core의 값 계산과 struct 행을 사용한다. 과거 조회용 람다 캡처와 현재 순위의 임시 재무 스냅샷을 제거했다. 변하지 않은 화면의 순위·호가 캐시는 기존 동작을 유지하고 명시적인 갱신 기준을 공통화했다.

기존 짧은 준비로 얻은 [초기·중간 결과](exploratory)는 계층 JIT에 따른 편차를 확인한 근거로 남긴다. 이 숫자를 최종 개선율로 사용하지 않는다.

## Android 자원·검증과 한계

초상화 캐시는 기존 전체 해상도4개에서 실제 밀도·표시 크기별 최대8개/6 MiB로 바꿨다. 1536×1024 RGB565 아틀라스의 픽셀 메모리는 샘플1에서3,145,728B, 샘플2에서786,432B, 샘플4에서196,608B, 샘플8에서49,152B이다. 확대는 필요한 해상도를 유지한다. 캐시에서 빠진 Bitmap을 즉시 recycle하지 않으므로 이 예산은 캐시 소유 메모리이며 프로세스 PSS의 상한은 아니다.

로비 이미지도 표시 밀도에 맞춘 RGB565로 백그라운드에서 읽는다. 차트 선·영역 Path와 초상화 Rect·Path를 재사용한다. Activity 종료에 그리기 자원을 해제한다. UI 입력에서 상태 복사·디스크 완료를 기다리는 동기 대기를 제거하고 저장 워커·새 시장 전환·파일 작업 장벽을 공통화했다.

[네이티브 원자료](../../verification/v1.9.0)는 API26 x86_64 에뮬레이터의 실제 앱 실행·PSS 샘플이다. 일부 기존 이력 화면의 최초 SQLite 조회는 동기로 남아 있다. 저사양 ARM64 물리 기기·FPS·배터리·장시간 열화는 아직 측정하지 않았고 이 결과로 추정하지 않는다.
