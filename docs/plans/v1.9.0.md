# v1.9.0 · 유지보수 구조와 Android 최적화

요청: 추가 성능 최적화, 전체 폴더·파일·코드·함수 구조의 리팩토링, 불필요한 구조 제거, 향후 개발 규격 명문화. 유지보수와 확장성을 우선하고 Android 모바일 실행에 집중한다.

기준 소스는 v1.8.0 main `7e81f9a8327eeef21734fc7c737f46cf6ab1ba0f`이다. Draft PR에서 다음 작업을 구현·검증한다.

1. Core를 모델, 시뮬레이션 기능, 조회, 저장, 규칙으로 정리한다. 큰 모델·SQLite 파일을 책임별로 분리하고 저장 타입·JSON 속성 순서·버전은 보존한다.
2. 플랫폼 독립적인 클라이언트 실행 코드를 별도 작은 .NET 프로젝트로 옮긴다. Android와 테스트의 중복 소스 컴파일을 제거한다. 실행/저장, 화면 탐색/입력, Canvas 렌더링을 분리한다.
3. Android의 반복 차트 배열/그리기 객체 할당과 이미지 디코딩 비용을 줄인다. 화면 크기에 맞는 샘플링, 한정된 이미지 메모리, 명확한 자원 수명을 사용한다.
4. 통계·랭킹의 중복 조회/계산을 정리하고, 측정으로 효과가 확인되는 비용을 개선한다. 난수·거래 순서·가격 평가·원장 공식은 유지한다.
5. 현재 가이드와 이전 개발 기록을 구분하고 참조를 갱신한다. 개발 규격과 AGENTS.md에 의존 방향, 파일/함수 책임, 모바일 스레드·캐시·메모리 예산, 저장 호환성, 검증·삭제 기준을 명시한다. 규격의 주요 경계를 자동 검사한다.
6. 같은 고정 입력과 시드로 전후 전체 상태·체결·난수를 대조한다. 회계/저장/복원·클라이언트 경계·합성5년·Android 실행 검사를 수행한다. 측정 원자료와 한계를 공개한다.
7. 버전은 1.9.0/코드10으로 올린다. 앱 ID와 v1.8.0의 서명키를 유지한다. 개인키와 빌드 결과는 개발/main 브랜치에 포함하지 않는다.

불필요한 의존 계층·가상 확장점·단일 구현 인터페이스·호환성 래퍼를 새로 만들지 않는다. 기존 저장을 읽는 이전 코드와 회계 검증·원시 기록은 필요한 호환성 근거이므로 무작정 삭제하지 않는다.
