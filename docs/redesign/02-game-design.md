> **"작은 가게 하나로 시작해, 살아 움직이는 3대륙 경제에서 나만의 기업 그룹을 키운다. 모든 가격과 위기에는 이유가 있다."**

## 2. 핵심 판타지와 디자인 기둥 `[F1]`

### 핵심 판타지
**"내 결정이 경제를 움직이는 것을 눈으로 확인하는 경영자."**
빵집 하나가 밀가루 값을 올리고, 공장을 지으면 도시 임금이 오르고, 경쟁사가 무너지면 시장을 차지한다.

### 디자인 기둥 (모든 기능은 최소 1개 기둥을 강화해야 한다)

| 기둥 | 의미 | 판단 질문 |
|---|---|---|
| **P1. 의미 있는 월간 결정** | 매달 2~3개의 실질적 선택이 있다. | "이번 달 플레이어가 고민할 거리가 있는가?" |
| **P2. 설명 가능한 경제** | 모든 변화에 원인을 보여준다. | "플레이어가 '왜?'에 답을 찾을 수 있는가?" |
| **P3. 성장의 쾌감** | 규모가 커지는 것이 보이고 새로운 도구가 열린다. | "10턴 전보다 더 큰 일을 하고 있는가?" |
| **P4. 짧고 가벼운 세션** | 한 턴이 빠르고(정산 ≤ 1초), 언제든 멈출 수 있다. | "지하철 한 정거장 안에 한 턴을 끝낼 수 있는가?" |

### 유지할 원칙 (현행 강점 계승)
- **보존 법칙**: 돈과 물건은 생산·거래·소비·폐기로만 생기고 사라진다. 치트성 보정 없음.
- **공정한 AI**: AI 기업도 플레이어와 같은 명령·같은 규칙을 사용한다.
- **결정론**: 같은 시드 + 같은 명령 = 같은 결과 (리플레이·버그 재현 가능).

## 3. 핵심 게임 루프

```
 ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
 │ ① 계획 (Plan) │ → │ ② 정산 (Run) │ → │ ③ 보고 (Read)│
 │ 시간 정지      │    │ ≤ 1초         │    │ 핵심 변화 3개 │
 │ 명령 2~5개     │    │ 진행바 표시    │    │ + 원인 설명   │
 └──────▲───────┘    └──────────────┘    └──────┬───────┘
        └──────────────── ④ 판단·학습 ◄───────────┘
```

| 단계 | 플레이어 행동 | 시스템 |
|---|---|---|
| ① 계획 | 생산량·가격·채용·건설·대출 결정. 알림이 "이번 달 할 일"을 제안. | 명령을 큐에 넣고 즉시 검증 (자금·재고 가예약 표시) |
| ② 정산 | "다음 달" 버튼 | 고정 순서 시스템 파이프라인 실행 (§7.2) |
| ③ 보고 | 월간 리포트: 손익, 변화 Top 3, 경고 | 원인 추적 로그를 사람이 읽는 문장으로 변환 |
| ④ 판단 | 다음 계획에 반영 | — |

### 장기 루프 (성장 단계)
| 단계 | 기간(목안) | 규모 | 새로 열리는 것 |
|---|---|---|---|
| 1. 창업 | 1~12턴 | 가게 1개, 직원 1~5명 | 생산, 가격, 채용 |
| 2. 성장 | 12~36턴 | 회사 1개, 시설 3~10개 | 건설, 대출, 공급 계약 |
| 3. 확장 | 36~84턴 | 여러 도시, 자회사 | 도시 간 물류, 연구개발, 주식 상장 |
| 4. 그룹 | 84턴~ | 대륙 단위 | 해외 무역, 인수합병, (확장) 정치 영향력 |

## 4. 목표·진행·난이도 `[F1][F4]`

### 4.1 게임 모드
| 모드 | 설명 |
|---|---|
| **커리어 (기본)** | 마일스톤을 따라 성장. 자유롭지만 다음 목표가 항상 보인다. |
| **시나리오** | 정해진 조건과 기한 (예: "곡물 파동: 24개월 안에 식량 가격 안정화"). 별 1~3개 평가. |
| **샌드박스** | 시작 자금·세계 크기·AI 난이도 자유 설정, 모든 기능 해금. |

### 4.2 마일스톤 (커리어)
예시 — 데이터(JSON)로 정의하여 코드 수정 없이 추가 가능:
1. 첫 흑자 달성
2. 직원 10명 고용
3. 두 번째 시설 준공
4. 다른 도시에 진출
5. 순자산 $1M 달성 (원화 보기 10억원)
6. 도시 시장 점유율 1위 품목 보유
7. 순자산 $1B 달성 → 커리어 "완료" 판정, 이후 자유 플레이

### 4.3 기능 해금 (점진적 공개)
처음에는 **메인·사업·시장** 탭의 기본 화면만 열려 있고, 마일스톤을 달성할 때마다 메뉴가 열린다. 잠긴 메뉴는 "무엇을 하면 열리는지" 표시한다.

### 4.4 실패와 재기
- 회사 파산 = 게임 오버가 아님. 개인 자산은 남고, 일정 기간 후 재창업 가능 (현행 R15 계승).
- 커리어 모드 "패배" 조건: 개인 순자산 음수 + 12개월 연속 무직 → 결과 화면 후 이어하기 선택.

### 4.5 난이도
| 설정 | 영향 |
|---|---|
| AI 공격성 | AI 기업의 가격 경쟁·진입 빈도 |
| 시장 변동성 | 원자재 가격·수요 충격의 크기와 빈도 |
| 시작 자본 | $50K / $250K / $1M |

## 5. 시뮬레이션 설계

### 5.1 세계 구조 (R09 유지)
```
세계 ─ 대륙 3개 ─ 국가 (대륙당 1~3) ─ 도시 (국가당 1~4)
```
- 기본 세계: 3대륙 · 6국가 · 12도시. 작은 세계: 3대륙 · 3국가 · 6도시.
- **도시가 최소 시장 단위**. 국가·대륙 지표는 하위 도시의 합계(별도 저장 없음).

### 5.2 상품과 생산 `[F2]`
- **v1 상품 수: 30개 내외, 3티어.** (원자재 → 중간재 → 최종재)
- 예시 체인: 밀 → 밀가루 → 빵 / 원유 → 플라스틱 → 생활용품 / 철광석 → 강철 → 공구·자동차
- 레시피 = 투입물 + 노동시간 + 전력 → 산출물 (부산물은 v2).
- 실제 단위(kg·L·kWh·개) 유지 (R22).

### 5.3 시장 (가격 결정)
- 도시·상품마다 **단순 호가 매칭**: 판매자는 판매 가격·수량을, 구매자는 최대 가격·수량을 제출 → 가격 순으로 체결.
- 체결되지 않은 수요/공급은 다음 달 가격 신호로 남는다 → 플레이어가 "품귀/과잉"을 볼 수 있음.
- 도시 간 거래는 운송비·운송 기간(월)을 더한 가격으로 비교.

### 5.4 인구와 노동 `[F3][P4]`
- **가계 = 도시별 코호트** (예: 소득 3계층 × 숙련 3단계 = 9코호트/도시). 개별 393명 시뮬레이션 대신 집계로 처리.
  - 코호트마다 인구수·소득·저축·소비 성향·숙련도를 가진다.
  - 소비: 필수재 → 일반재 → 사치재 순으로 예산 배분.
- **주요 인물(Named Person)**: 플레이어, 경쟁사 CEO, 은행장, (확장) 정치인. 도시당 5~15명. 이들만 개별 의사결정·대화 이벤트를 가진다.
- 노동 시장: 회사는 숙련도별 임금을 제시하고 코호트에서 고용. 임금 계약 보장(현행 보강 규칙) 유지.

### 5.5 건설 (R03, R04 유지)
- 타일 지도에 시설 배치 → 자재 + 시공 노동 + 최소 공기(월) 필요 → 준공 다음 달 가동.
- 공사 중단·재개·취소 지원. 자재 부족 시 지연 사유를 리포트에 표시.

### 5.6 금융 (v1 범위)
- 은행 예금·대출(원금·이자·연체), 회사 지분(비상장).
- v2: 주식 상장·유통, 채권. v3: 보험·외환.

### 5.7 AI 기업
- 전략 프로필(저가형·품질형·확장형·보수형)을 데이터로 정의.
- 매달 플레이어와 **같은 명령**을 생성 → 같은 검증기 통과.
- AI 계산 예산: 기업당 월 0.5ms 목표 (휴리스틱 + 캐시, 탐색 트리 금지).

### 5.8 설명 가능한 결과 `[F3]`
- 정산 중 주요 변화마다 **원인 레코드**(CauseRecord: 대상, 변화량, 원인 종류, 관련 ID)를 남긴다.
- 리포트 생성기가 변화량이 큰 순서로 Top 3를 문장화:
  > "빵 가격 +18% — 원인: 밀가루 공급 부족 (해솔 제분소 가동 중단, 전력 부족)"

## 6. UI/UX 설계 `[U1~U5]`

### 6.1 화면 구조 (R05, R06 유지 / 내부 탭 2단계로 축소)
하단 외부 탭 5개 + 오른쪽 끝 "확장". 내부 탭은 **최대 2단계**, 전체 말단 화면 약 18개.

| 외부 탭 | 내부 1단계 | 내부 2단계(필요 시) |
|---|---|---|
| **메인** | 이번 달 · 리포트 · 알림 | — |
| **사업** | 회사 · 시설 · 건설 | 회사: 개요/인력/재무 |
| **시장** | 상품 · 노동 · 금융 | 상품: 가격/거래 |
| **자산** | 개인 · 지분 · 부동산 | — |
| **확장** | 세계 · 연구개발 · 설정 | 설정: 저장/화면/정보 |

> 기존 해석(내부 3단계·51화면)에서 2단계·18화면으로 변경하는 것은 **제안**이다. 사용자 확인 후 확정한다.

### 6.2 메인(홈) 화면 원칙
1. 맨 위: 날짜 · 현금 · 이번 달 예상 손익 (지난달 대비 ▲▼)
2. **"이번 달 할 일"** 카드 최대 3개 (예: "밀가루 재고 1개월분 — 구매 필요")
3. 도시 지도 미리보기 (탭하면 지도 화면)
4. 고정: "다음 달 ›" 버튼 (외부 탭 위 별도 영역 — 현행 유지)

### 6.3 표시 규칙
- 금액: `$1.2M`, `$3.4B` 축약, 상세 화면에서 정확한 금액 (R25). 원화 보기 1$=1,000원 (R26).
- 모든 숫자 옆에 비교 기준(전월 대비, 도시 평균 대비) 중 하나를 표시.
- 색상: 증가=청록, 감소=주황, 위험=빨강. 색만으로 정보를 전달하지 않는다(▲▼ 기호 병기).
- 진행이 필요한 작업(정산·저장·건설·연구)은 진행바 + 단계명 (R24).

### 6.4 접근성
- 글자 크기 3단계, 고대비 모드, 최소 터치 영역 48dp, 안전 영역 대응.

## 7. 기술 설계 개요 `[T1~T7][P1~P5]`

### 7.1 아키텍처 원칙
1. **시뮬레이션 코어는 엔진과 독립된 순수 C# 라이브러리**다. UI 없이 테스트·벤치마크·밸런스 실험이 가능해야 한다.
2. 상태(데이터)와 로직(시스템)을 분리한다. 상태는 강타입 구조체 배열, 로직은 단계별 시스템 클래스.
3. 모든 상태 변경은 **명령(Command)** 또는 **시스템(System)** 을 통해서만 일어난다.
4. 모듈 간 의존은 단방향: `Client → Simulation → Domain`.

```
┌─────────────────────────────────────────────┐
│ Hora.Client (엔진: 화면·입력·애니메이션)          │  ← 엔진 의존
├─────────────────────────────────────────────┤
│ Hora.Simulation (월 정산 파이프라인, AI, 명령)     │  ← 순수 C#
├─────────────────────────────────────────────┤
│ Hora.Domain (ID·Money·상태 구조체·정의 데이터)     │  ← 순수 C#
└─────────────────────────────────────────────┘
  Hora.Data (JSON 정의)   Hora.Tests   Hora.Tools(밸런스 CLI)
```

### 7.2 월 정산 파이프라인 (고정 순서)
| 순서 | 시스템 | 역할 |
|---|---|---|
| 1 | `CommandApplySystem` | 검증된 플레이어·AI 명령 적용 |
| 2 | `ConstructionSystem` | 공사 진척·준공 |
| 3 | `ProductionSystem` | 레시피 실행 (투입 소비 → 산출) |
| 4 | `LaborSystem` | 임금 지급·고용 변동 |
| 5 | `MarketSystem` | 도시별 호가 매칭·가격 갱신 |
| 6 | `LogisticsSystem` | 도시 간 화물 이동 |
| 7 | `HouseholdSystem` | 코호트 소득·소비·저축 |
| 8 | `FinanceSystem` | 이자·상환·연체 |
| 9 | `StatisticsSystem` | 지표 집계·원인 기록 정리 |
| 10 | `AiPlanningSystem` | 다음 달 AI 명령 생성 |

각 시스템은 `ISimulationSystem.Execute(WorldState, MonthContext)` 하나만 구현한다. 순서는 데이터가 아닌 코드에서 명시적으로 고정한다(결정론).

### 7.3 성능 목표 (Performance Budget)
| 지표 | 기본 세계 | 큰 세계 | 측정 환경 |
|---|---|---|---|
| 월 정산 | **≤ 300ms** | ≤ 1,000ms | 중급 Android (예: Snapdragon 7 계열) |
| 정산 중 GC 할당 | ≤ 1MB/월 | ≤ 4MB/월 | 벤치마크 도구 |
| 메모리 | ≤ 250MB | ≤ 400MB | 앱 전체 |
| 저장 파일 | ≤ 2MB | ≤ 8MB | 120개월 진행 후 |
| UI 프레임 | 60fps (최소 30fps) | — | 화면 전환·지도 스크롤 |

달성 방법 요약 (상세는 `docs/standards/coding-conventions.md` §8):
- 정수 ID + 배열(Struct of Arrays) 저장, 문자열 키 조회 금지 `[P4]`
- 세계 깊은 복사 금지 → 명령 검증은 읽기 전용, 적용은 정산 시 한 번 `[P2]`
- 원인 기록·이벤트는 최근 N개월 링버퍼, 장기 데이터는 월 요약 통계만 `[P3]`
- 불변식 전수 검사는 Debug/테스트 빌드 전용 `[P5]`
- 핫 패스에서 LINQ·박싱·클로저·문자열 연결 금지

### 7.4 데이터
- 정의 데이터(상품·레시피·건물·AI 프로필·마일스톤)는 JSON + JSON Schema 검증.
- 로드 시 한 번 검증 후 불변(immutable) 정의 객체로 변환. 실행 중 문자열 ID 대신 정수 인덱스 사용.
- 저장 파일: 버전 헤더 + 바이너리(MessagePack 등) 직렬화, 구버전 마이그레이션 함수 체인.

## 8. 기술 스택

### 8.1 엔진 결정 (결정 필요 ⚠️)
| 후보 | 장점 | 단점 |
|---|---|---|
| **Unity 6 LTS (권장)** | C# 1급 지원, Android 빌드·프로파일러·UI Toolkit 성숙, 자료 풍부 | 라이선스 정책 확인 필요, C# 9 / .NET Standard 2.1 제약 |
| Godot 4 .NET | 기존 에셋·경험 재사용, 오픈소스 | C# Android 내보내기의 성숙도·도구 지원이 상대적으로 약함 |

> 코어(`Hora.Domain`, `Hora.Simulation`)는 **엔진과 무관한 .NET Standard 2.1 / C# 9** 로 작성하므로 어느 엔진을 선택해도 그대로 사용 가능하다. 엔진은 `Hora.Client`만 결정한다.

### 8.2 도구
| 용도 | 선택 |
|---|---|
| 코어 테스트 | NUnit (Unity Test Framework와 호환) |
| 벤치마크 | BenchmarkDotNet (`Hora.Tools`) |
| 코드 스타일 | `.editorconfig` + `dotnet format` + Roslyn 분석기 |
| 직렬화 | MessagePack-CSharp (저장), System.Text.Json (정의 데이터) |
| CI | GitHub Actions: 포맷 검사 → 빌드 → 테스트 → 성능 회귀 검사 → APK |
