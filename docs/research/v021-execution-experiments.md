# EX-01·02·04 비교 실행 소스

이 문서는 측정 진입점과 비용 범위다. 이번 변경에서 측정·대량 인구·성장·장기 실행은 하지 않았다. Release 빌드와 두 시조의 짧은 EX02 생사 초기조건 1/1, 실제 EX04 backend 선택 기능 검사 1/1을 확인했다. 실제 수치·속도 채택·회귀 예산은 별도 결과가 나온 뒤 판단한다. EX03·05·06은 별도 담당자의 소스로 연결한다.

테스트 assembly의 명시적 진입점은 `ExecutionMeasurements.Run(new ExecutionMeasurementRequest(outputPath, populations, repetitions, selectedExperiment))`다. 마지막 값은 `EX-01`/`EX-02`/`EX-04` 하나 또는 세 실험 모두를 뜻하는 null이다. 자동 기능 발견은 이 메서드를 호출하지 않는다. 지원 규모는 기존의 명시 합성 초기조건 2/100/1,000/10,000명이며, 반복은 같은 프로세스의 독립적인 새 세계다. 다른 프로세스·PC/Android 반복으로 주장하지 않는다. 앞선 기능 검사/JIT·공유 캐시의 영향 가능성을 환경에 적는다.

| 실험 | 실제 비교 |
| --- | --- |
| EX01 | 동일한 초기 합성 fixture를 원본 Person 배열/스칼라와 실제 hot columns·due heap·검증 배치 경로에서 각각 12개월 진행한다. 별도 세계로 전체 12개월을 예열한 뒤 원래 입력의 새 측정 세계를 사용한다. 매 월 전체 hash·RNG·사건 digest·생사·슬롯 digest를 비교한다. |
| EX02 | 같은 규모에서 별도로 명시한 생사 경계 초기조건을 사용한다. 두 실제 시조의 임신 명령, 첫 시조의 실제 수명 종료, 공개 입장으로 해당 슬롯 재사용, 저장된 임신의 실제 출생을 12개월 안에 처리한다. 원본/새 경로를 모든 월·명령 경계에서 비교한다. |
| EX04 실제 경계 | 각 규모의 실제 `PeopleAptitude` 전체 출력을 스칼라·Vector 후보·부분 출력 실패/미지원 후 스칼라 대체로 비교한다. cold의 입력 캡처/계산/검증/게시와 warm 캐시·동적 현재 표현을 서로 다른 label로 기록한다. 세계 hash가 변하지 않고 전체 재능/인지 출력이 같아야 한다. |
| EX04 직접 커널 | 같은 실제 초기 인물의 재능 요청 수 0/1/벡터 폭 앞뒤/24/2,400을 비교한다. 요청 index가 정본 24재능을 반복하며 사람 수는 아니다. 입력 복사·fingerprint·pool·계산·정본/범위/현재 입력 검증·결과 전체 게시를 포함한다. |

EX02의 추가 선언은 `birth.enabled=1`, `birth.fertility=100`, 첫 시조의 현재 수명=현재 나이+1개월이다. 이 선언은 과거 사망이나 성장 이벤트를 만들지 않는다. 실제 수명 종료·사망·영혼/유산·임신/출생·슬롯 세대 전이가 실행되어야 한다. 다른 인물의 AI·노동·생존 처리는 그대로 활성화한다. 이 생사 작업 fixture는 작업을 생략하기 위해 인물을 죽이는 기존 인구 기준선의 변경이 아니며, 정본의 기본 합성 인구 비용/장기 안정성 결과를 대체하지 않는다. 작은 기능 검사는 실제 임신·아버지 사망·입장·출생·계보와 중간 복원을 원본/새 경로에서 먼저 비교했다.

실제 `PeopleAptitude` 비교의 backend 선택은 internal 검증 옵션뿐이다. 일반 앱 명령·세이브·선천값·학습·수행 권한을 추가하지 않으며, 제품 기본 backend는 스칼라다. 모든 후보 출력은 기존 배치의 정본 검증과 현재 source/인물/몸/영혼/슬롯/생사/revision 검사를 거친다. 실패/미지원의 표본은 스칼라 대체까지 지불한 실제 비용이며 실패한 숫자를 적용하지 않는다.

측정 시작 시 Release·수정/미추적 파일 없는 실제 git commit을 검사한다. 제품 fingerprint는 기존 릴리스 검증기의 `fingerprint --commit`에서 가져온다. 새 출력 경로만 허용하여 옛 실패·부분 결과를 덮어쓰지 않는다. 각 완료 실험 직후 pending 파일을 원자 교체하고 예외가 있으면 `failure`와 `complete:false`를 보존한다. 요청 규모 일부만 끝난 결과는 `requested_complete`로 구분하며 네 규모 전부가 없으면 `complete:true`가 되지 않는다. 선택 실험은 `requested_experiments`, 세 실험·네 규모 모두의 완료는 별도의 `all_owned_experiments_complete`로 구분한다.

월 진행/명령 표본은 실제 권위 호출 전체와 내부 열·큐·캐시·fingerprint·배치 검증·게시 비용을 포함한다. fixture/restore, 별도 예열, 관찰용 clone/hash/digest, 최종 불변식·GC·보고는 표본 밖이다. 직접 커널의 요청 index 배열 생성도 제외한다. 상위 전체 시간은 소스 확인·fixture·예열·GC·앞선 보고 쓰기를 포함하고 마지막 보고 쓰기만 제외한다. 반환값 비교의 비용과 측정 밖 준비를 숨기지 않는다.

원시 시간은 `Stopwatch.GetTimestamp`의 실제 차이를 정수 ns로 변환한다. thread 할당은 같은 동기 호출 전후의 `GC.GetAllocatedBytesForCurrentThread` 차이며 다른 스레드·네이티브·RSS가 아니다. 보유 메모리는 full GC→finalizer→full GC 후 실제 세계를 참조한 전체 프로세스 관리 힙이다. 공통 fixture·런타임/공유 캐시·이전 결과와 JIT 수명이 남은 현재 반환 출력을 포함할 수 있으며 세계별 귀속값으로 해석하지 않는다. 마지막 full clone을 만들기 전에 채집한다.

모든 raw 표본과 operation label을 남긴다. 월 진행·서로 다른 공개 명령·cold/warm을 별도 그룹으로 나누고 각 그룹의 실제 n 및 nearest-rank p50/p95/p99를 기록한다. 소량 n은 반복을 가정해 부풀리지 않는다. 같은 프로세스/JIT·변형 순서·작은 표본·전체 경계 overhead·유지비를 검토하기 전에는 `revisit` 상태다. 숫자만 빠르다고 자동 채택하지 않는다. 실제 최종 측정과 원시 근거를 저장한 뒤 H06/H09 수용 및 채택/기각/재검토를 닫는다.
