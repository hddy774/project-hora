# H04·H06·H09 실행 인프라와 비교 준비

이 변경은 정본 revision 6의 EX-01~06 및 슬롯·버퍼·사건·실패 배치 계약을 구현하기 위한 소스와 짧은 기능 검증이다. 기준 소스는 `8745eb4440498f7aff3d0b70a3c09eb2004a908e`다. [정본 원문 보관](../plans/revisions/v021-notion-revision6-source.md)과 [111개 작업 수용 조건](../plans/v021-tasks.json)을 따른다. 성능·프로파일링·대량 인구·성장·장기 실행은 하지 않았다. 속도 향상·최종 측정 통과·SIMD 또는 네이티브 채택을 주장하지 않는다.

기존 제품에는 Person/item/owner/place/dependent 색인과 안정 ID·활성 슬롯 세대가 있다. 실행은 월마다 살아 있는 Person 참조 배열을 만들고, 현재 인물 목록 순서로 유지·위험·완료·관찰·AI를 처리했다. `legacy/windows-pre-v021`의 이전 고정 SoA와 결정 큐는 현재 제품에서 컴파일하지 않으므로 현재 H04 구현 근거에 포함하지 않는다.

Step의 다른 월 정산과 RNG 순서는 바꾸지 않았다. 식량·회복·기분·인지 만료·관찰·생태·세금·재난 등의 의미가 있으므로 다음 Due로 시간을 건너뛰지 않는다. 월 시작 스냅숏의 원래 Person 객체 참조도 보존한다. 앞 인물이 뒤 인물을 같은 달 사망시키거나 이동/참여를 바꾸면 기존 참조가 보던 변경을 그대로 보며, 현재 상태를 이유로 월 시작 참여자를 임의로 건너뛰지 않는다. 이번 묶음 계산은 같은 시점의 부작용 없는 24선천값에 한정한다.

힙 재구축은 현재 유효 토큰의 기존 key를 그대로 보존한다. 재구축 전후 다음 key·ready 순서가 같고 오래된 토큰이 실행되지 않는 기능 검사가 있다. 현재 `max(32, active*2)`를 넘는 힙을 정리하는 조건은 결정적인 임시 메모리 상한이다. 정본이 요구하는 측정 기반 최종 정리 조건은 최종 EX-01 계측 후 확정해야 한다.

실제 제품 배치 backend는 스칼라 C#이다. Vector 후보는 같은 `AptitudeCatalog`의 가중치로 계산하며 0~10,000 입력과 합계 10,000의 가중치에서 정수 합을 100,000,000 이내로 제한한다. 벡터 폭과 무관하게 나눗셈은 정본과 같은 마지막 정수 단계에서 수행한다. 기능 미지원이면 대체 계산을 한다. 외부 패키지·네이티브 ABI·Unity API는 추가하지 않았다.

`tests/Chronicles.Game.Tests/Features/ExecutionInfrastructureScenarios.cs`는 작은 구획/슬롯·재대여·재배치·반복 예약/취소·힙 재구축·빈 입력/벡터 경계·부분 실패/미지원·낡은 입력/출처·중복 게시를 검사한다. 실제 세계에서는 같은 명령열을 internal 검증용 원본 순회와 새 경로에 적용해 매 월 전체 hash·사건열·RNG·출생/사망·슬롯을 비교한다. 공개 탐색/이동/취소/무도·실제 임신/출생, 공동 전수에서 교사가 뒤 학습자의 작업을 바꾸는 경계, 실제 수명 사망 후 공개 입장으로 재사용한 슬롯, 중간 저장 복원을 포함한다. 기본 앱에는 검증 전략을 선택하는 명령이나 무료 수행 훅이 없다. 실제 열/힙/배치 사용 카운터도 검사하므로 미호출 라이브러리만 통과시키지 않는다.

H06의 현재 실제 비교 코드는 `tests/Chronicles.Game.Tests/Experiments/ExecutionComparisonHarness.cs`다. 8명 이하·24개월 이하의 기능 fixture로 제한하며 시간 계측은 없다. EX-01의 실제 두 실행 전략과 EX-04의 스칼라/Vector/실패 후보 출력 비교가 구현되어 있다. EX-02는 작은 실제 출생/사망·슬롯 수명과 구획 기능 검증만 있다. EX-03·05·06의 대체 후보 비용 비교와 EX-02의 2/100/1,000/10,000 확장 측정은 아직 구현·실행 결과가 없다. 중간 codec 복원은 정확성 근거이며 serializer 교체의 비용 비교로 세지 않는다.

`ExperimentEvidence.cs`는 EX-01~06의 서로 다른 범위와 후속 측정 근거를 명시한다. 제품 소스 fingerprint·fixture/hash·명령 hash·커널 버전·배치 길이·지원 기능·런타임/기기·예열/측정의 독립적인 동일 초기 hash·실제 작업별 원시 표본·채택/기각/재검토 근거가 필요하다. 원시 표본이 없는 준비/기능 결과를 측정 채택으로 검증하지 않는다. 최종 측정 코드는 입력 캡처·fingerprint·복사·대여·계산·스칼라/범위 검증·병합/게시 전체 비용을 포함하고, 준비 작업 제외 범위를 별도로 명시해야 한다. 기존 H01 보고서를 현재 구현의 측정 결과로 덮어쓰지 않는다.

최종 수용 전에는 이 소스의 통합 기능 검사와 EX-01~06 비교를 완료하고 원시 지연 표본에서 p50/p95/p99를 계산해야 한다. 독립 예열/측정 세계, PC/Android/향후 Unity 환경 구분, 임시 메모리 상한·캐시 fingerprint 및 검증 overhead, 소량 배치 악화와 유지비를 기록해 채택·기각·재검토를 결정한다. 이 문서와 소스 추가만으로 H06/H09의 측정 수용을 닫지 않는다.

현재 선택 기능 결과는 H04/H09 **6/6**, 조회 회귀 **12/12**, authority 회귀 **5/5**, 정적 제품 경계 self-test 통과다. [기능 근거 JSON](../evidence/0.2.1/execution-infrastructure-functional.json)에 실제 검사 이름·결과·소스 SHA-256을 저장했다. 전체 통합·최종 비용 측정은 이 선택 결과와 별도로 수행한다.
