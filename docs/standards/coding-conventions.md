# 선로만상록 코드 규칙

정확성·단일 권위·결정론을 먼저 지키고, 읽기 쉬운 코드와 측정 근거로 개선한다.
작업 범위의 새 코드와 변경 코드에 적용하며, 기존 전체 소스/legacy/raw의 서식을 일괄 변경하지 않는다.

## 실제 기술 기준

- SDK10.0.403은 `global.json`으로 정확히 고정한다. 현재 프로젝트는 net10.0,
  Desktop은 net10.0-windows, Android는 net10.0-android다.
- 언어·nullable·암시적 using·경고=오류·분석기는 `Directory.Build.props`가 정한다.
  이전 main의 .NET Standard2.1/C#9 가정은 현재 제품에 적용하지 않는다.
- [의존 그래프와 owner](../architecture/repository_manifest.json)를 지킨다.
  `Desktop/Android/Shell → Hosting → Game → Core`, `Game.Tests → Game/Hosting`이다.
- Game은 파일 경로·호스트·UI를 참조하지 않는다. 파일 슬롯/복구는 Hosting,
  버튼/네이티브 수명 주기는 해당 호스트의 책임이다.

## 읽기 쉬운 구조

- 한 문장에는 한 작업을 둔다. 중괄호는 새 줄, 한 줄 블록과 여러 문장 압축을 피한다.
  `.editorconfig`의 4칸 C# 들여쓰기·공백·using 순서·서식 설정을 사용한다.
- 이름은 영어 식별자, 설명/주석은 한글을 기본으로 한다. 타입/멤버 PascalCase,
  매개변수/지역 변수 camelCase, 인터페이스는 I 접두어를 사용한다.
- 새 파일은 책임 하나를 갖고, 타입/메서드가 다루는 권위와 데이터 단위를 이름으로 드러낸다.
  `GameWorld` partial은 실제 도메인 경계로 나누며 파일 분할을 새 권위 생성으로 바꾸지 않는다.
- 파일400줄·메서드40줄·중첩3단계·줄120자는 새 코드의 리뷰 목표다.
  초과하면 책임 분리나 필요한 이유를 PR에 적는다. 기존 파일을 이 수치만 맞추려고 광역 재작성하지 않는다.
- using·nullable·분석기 경고를 해결한다. 진단을 끄거나 테스트를 비활성화해서 통과시키지 않는다.

## 주석과 계약

- 새 파일은 책임을, 새 타입·public/internal API는 입력 조건·결과·단위·거부/예외 의미를 설명한다.
- 복잡한 전이는 순서의 이유, 예약/해제 시점, 보존식, alias 소유와 commit 이후 사용 제한을 적는다.
  공개 이름을 반복하는 주석 대신 호출자가 알아야 할 계약을 쓴다.
- 성능을 위해 복잡해진 부분은 실제 source/측정 근거와 경계를 연결한다.
  추측한 개선률이나 과거 소스의 결과를 새 코드의 수치로 쓰지 않는다.
- TODO/HACK에는 관련 이슈와 해결 조건을 남긴다. 죽은 구현은 현재 경로에서 제거하고 필요한 출처를 legacy에 보존한다.

## 값·시간·난수

- 금액·물량·월·비율은 현재 정수 모델과 명시된 단위를 따른다. USD 센트/환율 같은 다른 제품의 의미를 가져오지 않는다.
  범위/오버플로를 확인하고, 반올림·잔여 배분·정렬 동률 규칙을 계약으로 적는다.
- 사람/육신/혼/물품/명령 ID와 배열 슬롯을 혼동하지 않는다. ID 재사용·별도 세계/장부로의 이중 권위를 만들지 않는다.
- 세계 전이에 벽시계·`System.Random`·임의 GUID를 섞지 않는다. 현재 저장된 RNG 알고리즘·소비 순서를 보존한다.
  호스트 진단 시각과 테스트 입력 ID는 권위 상태의 난수와 구분한다.
- 결과가 순서에 의존하면 안정된 실제 ID/ordinal 순서를 명시한다. 사전/집합의 우연한 순서를 게임 규칙으로 쓰지 않는다.

## 전이·실패·저장

- 플레이/AI는 같은 실제 명령·권한 검증을 사용한다. 조회 DTO는 개인이 관측/소유/접근할 수 있는 정보만 전달한다.
- 예상 가능한 명령 거부는 현재 `CommandResult`/Try 계약으로 반환한다.
  불변식 파손·손상 입력·환경 오류는 원인과 보존 경로를 유지한다. 넓은 catch로 삼키지 않는다.
- 명령 실패 시 원본 세계·RNG·NextId·돈/실물·예약이 부분 변경되지 않아야 한다.
  후보 clone/검증/fingerprint/receipt를 성능 이유만으로 제거하지 않는다.
- 같은 ID 재전송의 무영향과 다른 payload 충돌 거부를 함께 확인한다.
  저장 봉투/본문 schema·원문/백업 보존은 [메모리/파일 계약](../architecture/v021-product-boundary.md)을 따른다.

## 검사와 측정

- 실제 기능 러너는 `tests/Chronicles.Game.Tests`의 실행형 프로그램이다. NUnit/`dotnet test`라고 바꾸어 적지 않는다.
  새 기능 시나리오는 `IFeatureScenario`의 정확한 Name/Run으로 등록하고 의미 있는 정상·실패/저장 경계를 검증한다.
- 기대값을 실제값에서 매번 만들거나 실패 사례를 지우지 않는다. 의도된 규칙 변경의 골든 갱신은
  독립 기준 실행→원문 보존→차이 원인→상수 채택 패치의 출처를 남긴다.
- 저위험 문서/템플릿 변경은 링크·형식·범위 검사로 확인한다. 구현을 그대로 복제한 테스트를 추가하지 않는다.
- 전인구 반복 읽기·JSON/clone·가변 alias는 검토하지만 실제 성능 주장은 승인된 최종 측정에서 한다.
  `LINQ 금지`·`clone 금지` 같은 일괄 규칙으로 실제 원자성/순서를 바꾸지 않는다.
- 현재 성능 예산·기간은 [정본 성능 계약](../development/v021-performance-gate-policy.md)을 따른다.
  과거 main의300ms/20%·옛100배 목표를 새 게이트로 넣지 않는다.
