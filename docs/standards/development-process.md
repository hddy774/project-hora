# 기획·명세·구현·리뷰 절차

## 역할과 작업 시작

| 역할 | 책임 |
| --- | --- |
| 사용자 | 제품 방향과 정책 결정·이미 승인된 개발/통합/게시 범위 |
| Claude | 기획·자기완결 명세·계약과 수용 기준 검토·리뷰 |
| Codex | 실제 구현·테스트·원문 보존·PR·리뷰 반영·승인 범위의 통합/릴리스 |

현재 사용자는0.2.1 전체 개발·병합·최신 릴리스/APK 게시를 승인했다.
새 외부 Claude 응답이나 ready 라벨은 작업 시작 조건이 아니다. 실제 담당자와 검토 방법을 기록한다.
기획·리뷰 역할을 Codex가 대행한 경우도 그 사실을 적으며 Claude 수신으로 계산하지 않는다.

## 작업 흐름

1. 정본 작업·사용자 지시·선행 상태를 확인하고 [작업 템플릿](../tasks/_template.md)에 목표/계약을 적는다.
2. 이슈와 작은 소유 범위를 정한다. 공유 파일/실측은 통합 담당과 조율하고 별도 worktree를 사용한다.
3. 실제 public 명령·후보 전이·권한/관측 경계로 구현한다. 새 보조 장부가 세계 권위를 이중 소유하지 않도록 한다.
4. 명세 수용 기준과 필요한 정상/거부·저장/재전송을 확인하고 정확한 명령·소스·결과를 남긴다.
5. PR에서 [리뷰 체크리스트](review-checklist.md)를 대조한다. 필수 결함을 수정하고 실제 미검증 범위를 기록한다.
6. 승인된 범위에서 통합한다. 정본 원장은 작업 자체 근거와 선행 마감이 모두 있을 때만 done으로 바꾼다.

명세가 실제 계약과 어긋나면 이유와 변경점을 같은 PR에서 정정한다.
일상 구현 선택은 기록해 진행하며, 새 정책을 임의로 사실처럼 채우지 않는다.
범위 밖의 개선은 별도 이슈로 남기고 기존 승인 작업을 마무리한다.

## 명세의 필수 내용

- 목표·관련 정본/사용자 지시·실제 소유 경로와 통합 API
- 입력/출력/단위·지식/접근권한·권위 소유·시간/RNG·실패 원자성
- 0/빈 값/중복/부족·예약경합·저장/재전송 경계와 관측 가능한 수용 기준
- 실제 검사 이름/명령·허용된 실행 예산·증거 보관 위치·선행 의존성

개발자가 다른 대화를 추측하지 않아도 구현할 수 있게 쓴다. API가 미정인 곳은 결정할 책임과
호환 조건을 적는다. [M0 기반 계약](../tasks/README.md)은 실제 프로젝트를 읽는 출발점이며 정본111개를 대체하지 않는다.

## 검증과 완료의 구분

| 범위 | 현재 도구/근거 |
| --- | --- |
| SDK/컴파일 | `dotnet --version`, engine-free Release 빌드·경고0 |
| 기능 | `dotnet run --project tests/Chronicles.Game.Tests -c Release`와 정확한 등록 Name |
| 원장/경계 | `validate-v021-plan.py`, `validate-v021-product-boundary.py`의 실제 결과 |
| UI/native | 같은 세션·실제 브리지/렌더/입력·플랫폼 source 근거 |
| 성능/성장/장기 | 기능 개발 후 별도로 배정된 최종 측정·동일 source/조건의 원문 |
| 릴리스 | 실제 owner/main/run/attempt·기능/성능·동일 retained APK/업그레이드·공개 byte 검증 |

명령은 작업에 맞게 선택한다. 매 문서 PR에서 전체Game·성능을 반복하지 않는다.
선택 검사 합격과 전체 합격, 정적 검증과 native 실행, 수집 완료와 목표 달성은 각각 구분한다.
실패·부분 원본을 남기고 [보관 규칙](evidence-retention.md)에 따라 출처를 연결한다.

## 결정과 문서

제품 요구/정책/111개 상태는 기존 정본 원장을 사용한다. 중요한 새 설계 결정은 관련 작업 문서에
문제·대안·결정·영향·대체한 출처를 남기고 정본에 연결한다. 똑같은 권위 상태표를 별도로 운영하지 않는다.
기획은 무엇을 만들지·왜 필요한지, 명세는 어떻게 판정할지, 실행 증거는 실제 무엇이 일어났는지를 적는다.
검증 한계는 결과에 한 번 명확히 기록하고 제품 설명을 방어적 문구로 채우지 않는다.
