# 실행 증거 원문·요약·해시 보관

## 현재 원형 유지

기존 `docs/evidence/` 원문·압축본·SHA·Git 이력을 보존한다. 큰 파일이라는 이유로 이동/삭제,
재포맷·개행 정규화·LFS 이력 변환을 하지 않는다. 기존 게이트가 읽는 JSON 경로와 해시 의미도 그대로다.
`.gitattributes`의 `linguist-generated`는 GitHub 표시 분류이며 검증/리뷰 면제나 본문 변경이 아니다.
[색인](evidence-index.json)은 복원 기준 source의 크기·해시·위치를 보여 주며 원문을 대체하지 않는다.

## 새 증거의 기본 배치

- Git에는 작은 읽기용 결과 요약, 입력 계획/명령, source/환경, 원문 자산 색인·SHA를 둔다.
  기존 검사기의 필수 JSON은 계속 해당 경로에 둔다.
- 큰 반복 raw·trace·영상/이진 파일은 Actions 아티팩트로 전달하고 내구성 있는 별도 증거 자산에 보관한다.
  5MiB 이상 또는 같은 데이터를 반복한 대형 원문은 이 배치를 우선 검토한다. 크기만으로 기존 파일을 옮기지 않는다.
- 영속 보관은 별도 **근거용 사전 릴리스** 또는 작업에 지정된 내구 저장소를 사용한다.
  source/tag·자산 URL·실제 바이트/해시를 고정하고 `latest` 제품 릴리스와 분리한다.
  공식 v0.2.1 릴리스에는 APK1개만 둔다는 계약을 유지한다.
- 정식 게이트 JSON을 외부 URI로 대체하려면 별도 구조 변경과 검증이 필요하다.
  이 보관 규칙은 검사기 경로/수용 의미를 바꾸지 않는다.

## 14일 만료 대비

현재 여러 workflow의 Actions 아티팩트는14일 뒤 만료한다. 임시 전달 수단으로 사용하고
수집 담당자가 실제 `expires_at`을 색인에 기록한다. 수집/검증 때 즉시 영속 보관하며 만료 전에
담당 통합 작업에서 다운로드·SHA 확인과 보관 URL의 접근 여부를 점검한다.
실패/부분 원문도 같은 정책으로 보관한다.

만료된 Actions URL만 있으면 재현 원문이 보존됐다고 표시하지 않는다.
미확보 상태와 영향을 기록하고 보존 사본을 찾는다. 새 실행이 필요하면 원래 원문과 다른 run/source로 구분한다.
source·SDK/런타임·입력 계획·법칙/fixture·명령을 Git에 남겨 같은 조건을 재구성할 수 있게 한다.
checksum만으로 사라진 원문을 복원할 수 있다고 쓰지 않는다.

## 자산 색인의 필수 필드

| 분류 | 기록할 값 |
| --- | --- |
| 출처 | 저장소·실제 source SHA/tree·제품FP(사용 시)·workflow/run/attempt/job·원래 경로 |
| 입력 | 정확한 명령·SDK/런타임/OS·seed·법칙·fixture·계획/기준선 SHA·비밀 없는 환경 범위 |
| 결과 | 성공/실패/부분·실제 완료 범위·원문 bytes/SHA256·요약/검증 경로 |
| 보관 | artifact ID/URL·실제 expires_at·영속 자산 URL/ID·보관 시각/담당·검증 시각 |
| 압축 | 형식·도구/버전·압축본 bytes/SHA·원문 bytes/SHA·복원 동일 확인 |

가능하면 gzip은 mtime0 등 결정적인 설정으로 만들고 압축본과 복원된 원문을 각각 검증한다.
원문에는 SDK·계수·실패 값을 고쳐 넣지 않는다. 번역/요약/portable 변환은 파생물로 따로 저장한다.
키스토어·비밀 값·접근 토큰은 어떤 자산에도 넣지 않는다.

## 수집 작업의 확인

1. 원래 run/source·파일 크기·SHA와 사본의 동일성을 확인한다.
2. 임시 Actions와 영속 자산을 구분하고 원본·파생물의 관계를 작은 manifest로 남긴다.
3. Git diff에 기존 raw/게이트 경로 변경이 없는지 확인하고 PR에서 요약·필요 원문 링크를 제시한다.

이 정책은 저장 방식의 운영 기준이다. 정본111개·기존 기능/성능/서명 게이트에 새 합격 기준을 추가하지 않는다.
