# 기획·구현 리뷰 체크리스트

검토한 source/명세·실제 수행자·방법을 기록한다. 항목의 완료는 실제 근거에 연결한다.

## 명세와 구현

- 정본 요구와 사용자 결정, 소유 경로, 이번 변경의 입력→결과가 명확한가?
- 공개 API의 단위·권한·실패/예외·소유/alias 계약을 호출자가 읽을 수 있는가?
- 다른 모듈의 권위를 복제하거나 AI 전용 우회·무료 정보/돈/실물을 만들지 않았는가?
- 기존 사용자의 승인 범위를 보존하고 외부 Claude 답변/새 승인 라벨을 장벽으로 만들지 않았는가?

## 정확성·보존·정보

- 0/빈 값/부족/중복·동률·예약경합에서 실제 결과가 일관적인가?
- 실패 시 상태·ID·RNG·돈/실물·예약이 부분 변경되지 않는가?
- 같은 명령 ID 재전송과 payload 충돌, 저장 중간상태/복원 속행을 필요한 경계에서 대조했는가?
- 조회·개인 관측·제어/AI 인계가 숨은 상태를 읽거나 시간/RNG를 바꾸지 않는가?

## 검증·가독성

- 실제 선택 Name·명령·source/SDK·원문 경로/SHA가 있는가? 선택/전체·host/native 범위가 맞는가?
- 골든 상수 갱신은 독립 기준·원문/차이 원인·채택 패치를 보존하는가?
- 여러 문장 압축·한 줄 블록·지나친 중첩·모호한 이름을 줄였는가? 주석은 이유/계약을 설명하는가?
- 분석기/불변식/저장 검증을 끄지 않았는가? 성능 주장은 실제 같은 조건의 측정에 근거하는가?
- 큰 원문은 기존 이력을 유지하며 새 자산은 만료 이후에도 요약·해시·재현 입력으로 추적할 수 있는가?

리뷰 기록은 `[필수] 문제/재현/위반 계약`, `[제안] 이득/비용`, `[질문] 필요한 사실`로 쓴다.
실제 외부 Claude 검토가 없으면 `Codex 자체 검토`라고 적는다. 기존1/1 수신 원문은 별도로 유지한다.
