# 중간 규모 저장의 기존 이진 봉투 선택

- 관련: 성능 진단 [이슈233](https://github.com/hddy774/project-hora/issues/233), 메인 PR84
- 구현 담당: Codex 통합 담당. 외부 Claude의 후속 리뷰를 수신했다고 표시하지 않는다.
- 기준: `b15992b6150afb8e4f3348501c51051a7f7733d0`; 실제 진단 제품 소스는 `df7240556a260202a248e57b1f9868e372b9d995`다.
- 소유: `GameCodec.cs`의 기본 JSON 선택 상한·주석, 새 기본 경계 기능 검사, 이 문서와 작은 진단 색인.

## 문제와 근거

기존120개월의100명 저장은65,047,350B로 고정 예산45,658,311B를 초과했다. 원문은
[장기 실패 보존](../evidence/0.2.1/stability-4fe-41120935546/README.md)에 있다.
진단에서는1,000명 개시 본문14,868,179B가 JSON 문자열 봉투에서23,035,239B로 늘어났고,
기존 내부 경계 인자0으로 강제한 이진 봉투는14,868,243B였다. JSON 이중 escaping의
추가8,166,926B는 실제 따옴표와 역슬래시 수로 설명됐다. 이1,000명 개시 fixture 자체는
16MiB 미만이므로 새 기본에서도 JSON을 사용한다. 형식 선택이 바뀌는 대상은 이후16MiB를
넘는 본문이다. 진단값은 장기100명 본문의 실제 크기나 최종 예산 통과를 대신하지 않는다.

기존128MiB 기준은 JSON writer의 큰 문자열 한도를 피하기 위해 도입됐다. 그보다 작은 본문에서도
이중 escaping·UTF16 임시 문자열·출력 복사 비용이 발생하므로 기본 선택 경계를16MiB로 낮춘다.
16MiB 이하의 기존 작은 저장 바이트를 유지하고, 큰 본문은 이미 지원하는 이진 schema3를 사용한다.
16MiB는 writer의 절대 한계가 아닌 개발 중 메모리/저장 비용 관리 기준이다. 최종100명 장기 저장
예산 충족 여부는 새 실제120개월 결과로 판정하며 예산 자체를 올리지 않는다.

## 보존 계약

- canonical JSON 본문·논리 체크섬·비음수 순번·세계/RNG·공개 API·저장 schema는 변경하지 않는다.
- 이전 JSON schema2와 이진 schema3의 읽기·혼합 backup/pending·손상 원본 보존을 유지한다.
- 내부 명시적 경계 인자는 기존처럼 그 인자의 엄밀한 경계를 따른다. 기본 경로만16MiB를 사용한다.
- Hash 스트림 개선은 별도 PR이며, 이 변경에서 Hash/Clone/Decode/Hosting을 고치지 않는다.

## 수용과 검증

1. 실제 canonical 본문16MiB와16MiB+1의 기본 Encode 형식·원문·순번·hash/RNG를 확인한다.
2. 새 경계보다 큰 이전 JSON 원본도 읽고, 기본 GameSaveStore 경로의 이진 원자파일 왕복을 확인한다.
3. 기존 작은 schema2 고정 원본·명시 경계·손상·혼합 복구4개 사례를 실행한다.
4. Release 경고/오류0, 정적 제품 경계와 변경 범위를 확인한다. 새 검사 Name은 최종 불변식 맵에 연결한다.
5. 모든 성능 개선 통합 후 전체 기능과 원래 고정 예산/120개월을 다시 검증한다.

새 포맷·압축·역사 기록 삭제·예산/기간 조정·기본 게임 정책 변경은 범위 밖이다.
