# [M0-05] 실제 검사·SDK·워크플로 기반 계약

## 범위와 소유

현재 검사/도구 경로를 명세에 정확히 연결한다. workflow 수정은 지정 담당자가 맡는다.
main의 옛 csharp/economy workflow나 NUnit·net8·가상의 format/perf-guard job을 복원하지 않는다.

## 실제 명령

```text
dotnet --version
dotnet build tests/Chronicles.Game.Tests -c Release
dotnet run --project tests/Chronicles.Game.Tests -c Release
python3 scripts/validate-v021-plan.py --self-test
python3 scripts/validate-v021-product-boundary.py --self-test
```

SDK는10.0.403 정확 버전이다. 기능 선택은 `-- --filter '<등록 Name의 부분 문자열>'`를 명시하고
선택 건수·source·원문을 적는다. 전체 실행과 선택 실행을 혼동하지 않는다.
문서/도구 변경에서 필요 없는 Game/대량 검사를 반복하지 않는다.

## 수용 기준

- [ ] 정확한 SDK 설치와 `global.json` strict 선택을 확인한다.
- [ ] engine-free Release 경고0·필요한 실제 기능 경계를 검증한다.
- [ ] SDK 설치/실제 버전·실행 source·환경/원문·실패를 함께 보관한다.
- [ ] Android/Windows 패키지·렌더는 실제 플랫폼 별도 검증이며 host 결과로 대신하지 않는다.
- [ ] 최종 성능/성장/장기는 기능 개발 후 배정된 단계에서만 기존 계획·예산·raw 계약으로 실행한다.

[SDK workflow 대조](../standards/sdk-workflow-audit.json)는 이번 복원 기준의 설치 설정 차이를 기록한다.
global.json은 fingerprint 입력이므로 이전528 원문을 새 설정의 최종 근거로 재라벨하지 않는다.
선행: [M0-01](M0-01-solution-scaffold.md). 실제 제품/릴리스 게이트의 의미는 그대로다.
