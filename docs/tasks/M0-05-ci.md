# [M0-05] CI 워크플로 (format·build·test)

## 배경 (왜)
코드 규칙을 사람의 기억이 아니라 도구로 강제한다(피드백 D6). `main` 브랜치 보호의 필수 검사로 사용한다.
관련: [GitHub 규칙 §5](../standards/github-workflow.md), [개발 규칙 §5](../standards/development-process.md)

## 범위
- 포함: `.github/workflows/csharp.yml`, `tools/check-code-rules.sh` (커스텀 규칙 검사)
- 제외: 성능 회귀 검사 `perf-guard`(M1에서 기준 측정 후), APK 빌드(엔진 결정 후)
- 기존 `.github/workflows/monthly-economy.yml`, `release.yml` 은 수정하지 않는다.

## 동작 규칙
1. 트리거: `pull_request`, `push` (브랜치 `main`). 경로 필터: `src/**`, `tests/**`, `tools/**`, `data/**`, `*.sln`, `Directory.*.props`, `.editorconfig`, 워크플로 파일 자체.
2. job 3개, 이름은 브랜치 보호에 쓰이므로 정확히: `format`, `build`, `test`.
   - `format`: `dotnet format --verify-no-changes` + `tools/check-code-rules.sh`
   - `build`: `dotnet build -c Release -warnaserror`
   - `test`: `dotnet test -c Release --logger trx`, 결과를 아티팩트로 업로드
3. `actions/setup-dotnet` 으로 .NET 8 SDK 설치. NuGet 캐시 사용.
4. 권한: `contents: read` 만.
5. `tools/check-code-rules.sh` (bash, 주석 포함) — `src/`, `tests/`, `tools/` 의 `*.cs` 대상:
   - 파일 400줄 초과 → 실패 (파일명·줄 수 출력)
   - 한 줄 120자 초과 → 실패 (파일:줄 출력)
   - 이슈 번호 없는 `TODO`/`HACK` (`TODO(#123)` 형식이 아닌 것) → 실패
   - 파일 첫 줄이 `//` 로 시작하지 않음(파일 헤더 주석 누락) → 실패
   - `src/` 에서 `System.Random`, `DateTime.Now`, `Guid.NewGuid` 사용 → 실패
   - 위반이 없으면 종료 코드 0, 있으면 모두 출력 후 1.

## 수용 기준
- [ ] PR에서 3개 job이 실행되고 M0-01 상태의 코드로 모두 통과
- [ ] 규칙 위반 샘플(400줄 초과 파일, 120자 초과 줄, `TODO` 단독, 헤더 없는 파일, `System.Random`)을 임시로 넣었을 때 `format` job이 실패함을 로컬에서 확인하고 PR 본문에 출력 첨부 (샘플은 커밋하지 않음)
- [ ] 스크립트는 macOS·Linux bash에서 동작 (GNU 전용 옵션 금지)
