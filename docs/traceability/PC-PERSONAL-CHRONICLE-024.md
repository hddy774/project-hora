# PC 0.0.24 개인 영구 연대기 보존 수직 계약

## 요구사항과 권위 owner

- 비관심 인물의 세부 영구 연대기는 최근 100건을 상한으로 한다.
- 100년 구간이 완결되면 세부 사건을 먼저 종합본에 집계하고, 그 종합본과 중복되는
  세부 행을 삭제한다.
- 관심등록 인물은 세부 기록을 삭제하지 않는다. 관심 해제 시 일반 정책을 즉시 적용한다.
- 개인 100년 종합 연대기는 관심 여부와 무관하게 최근 100권을 상한으로 한다.
- 세부 기록 권위 owner는 `CompactChronicleStore`, 종합·작성 중 누계와 보존 정책 owner는
  `PersonalChronicleArchiveStore`다. Desktop은 Application/Runtime 명령과 query DTO만
  사용한다.

## 전이와 보존 순서

1. `World.AddChronicle`이 사건을 압축 세부 저장소와 현재 100년 누계에 같은 순서로 기록한다.
2. 사건의 나이가 다음 100년 구간으로 넘어가면 이전 누계를 완결 종합본으로 먼저 추가한다.
3. 비관심 인물만 완결본의 `LifeNumber + ObservedThroughAgeYears` 이하 상세 행을 제거한다.
4. 상세 기록은 별도로 최근 100건 상한을 유지한다. 관심 인물은 이 상한과 중복 제거를
   모두 건너뛴다.
5. 종합본이 100권을 넘으면 가장 오래된 권을 제거하고, 상세·종합·작성 중 누계 어디에도
   남지 않은 전생 이름 참조를 회수한다.

## 저장·이전·hash

- 내부 checkpoint schema 32는 `PreserveDetailedChronicle`, 완결 종합본과 작성 중 누계를
  저장한다. 외부 SQLite `WorldSchema 25`는 유지한다.
- schema 31 이하는 기존 세부 연대기를 시간순으로 재생해 종합본을 만든다. 명시적 runtime
  관심 목록을 합쳐 이전하므로 저장된 관심 인물과 현재 관찰 설정을 잃지 않는다.
- 종합본은 compact tuple JSON converter로 기록하고 이름은 안정 Life/Person ID에서
  조회 시 결합한다.
- 상세 보존 여부는 관찰자의 저장 정책이므로 schema 32 게임플레이 상태 hash에는 넣지
  않는다. 같은 seed에서 관심등록 유무가 RNG·전투·수행·공식 통계를 바꾸면 실패다.

## query·UI·메모리

- `PersonalCenturyChronicle` section이 열린 때만 종합 DTO를 만든다. 최근 개인·세계·디버그·
  성능 로그도 정확한 내부 탭이 열린 동안만 최근 100행을 query하고, 닫히면 UI 참조를 비운다.
- 비관심 상세 저장소는 반환 블록을 free-list에서 재사용한다. 종합본 목록은 4권에서 시작해
  100권까지만 단계적으로 확장해 첫 100년 경계의 10,000개 × 100칸 선할당을 피한다.
- 저장·복원 뒤 heap 768MiB 또는 fragmentation 256MiB 이상에서만 LOH를 한 번 압축한다.
  이 경계는 `PC_TEMP_REVIEW-024`이며 정상 저장에서 강제 GC를 호출하지 않는다.

## 자동 검증

- 세부 100건, 100년 중복 제거, 관심 인물 무제한, 관심 해제 정리, 종합본 100권
- 생별 이름과 schema 31→32 이전, checkpoint codec, 저장 후보 복원
- 관심 목록 변경 전후 상태 hash·RNG·관찰 무영향
- 73개 전체 회귀, 구조·XAML·238개 이식 원장
