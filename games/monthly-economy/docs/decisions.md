# 결정 기록과 실험 데이터

기준: 사용자 기획 버전 0.1, 2026-10-25. 미정 항목을 테스트 코드의 값으로 대신 확정하지 않는다. 이 문서의 기술 선택은 이번 검증 빌드를 위한 것이며 최종 플랫폼·상품 밸런스·출시 규격의 승인 기록이 아니다.

## 이번 기술 실험

Godot 4.6.3과 GDScript로 UI와 독립된 월 정산 코어, 세로 화면, Android 실행 경로를 함께 검증한다. 시뮬레이션은 장면을 열지 않고 headless로 실행 가능해야 한다. 월 처리는 렌더 프레임·카메라·앱 대기 시간에 의존하지 않는다.

| 후보 | 이번 목적에 유리한 점 | 검증할 비용과 위험 | 이번 판단 |
|---|---|---|---|
| Godot 4.6.3 + GDScript | 타일/도시 표현·세로 UI·터치와 Android 내보내기를 한 프로젝트에서 실험할 수 있다. SceneTree 없이 사용할 도메인 코드를 분리할 수 있다. | 대규모 인물/주문 처리·타입 실수·복합 저장 호환·성능은 실측이 필요하다. 노드 수나 프레임을 경제 시간으로 사용하지 않도록 설계한다. | 이번 실험에 사용한다. 최종 엔진 확정은 성능·저장·기기 검증 이후다. |
| TypeScript + 웹 UI | 코어 단위 시험·정적 타입·브라우저 접근·빠른 UI 반복과 headless 실행이 쉽다. | Android 제품 포장·오프라인 저장의 원자성·파일 복구·제스처/안전 영역과 큰 지도 표현을 별도 확인해야 한다. JS `number` 금액 정밀도와 직렬화도 설계해야 한다. | 비교 후보로 유지한다. 웹 시안이 네이티브 기기 성능을 입증하지 않는다. |
| Kotlin + Android UI | Android 파일·수명주기·접근성·배포 체계를 직접 다룰 수 있다. JVM의 정수·도메인 시험 도구를 사용할 수 있다. | 타일 렌더러·게임 제작 도구·다른 플랫폼 대응을 직접 준비할 부분이 커진다. 순수 코어와 Android 종속 코드를 분리해야 한다. | Android 전용 제품 확정 시 재평가한다. 현재 출시 플랫폼은 미정이다. |

위 비교는 설계 판단이다. 세 후보의 동일 규모 벤치마크를 수행했다는 의미가 아니다. 저장소의 기존 APK 릴리스는 별도 제품의 결과이므로 이 게임의 호환성과 서명·성능의 증거로 사용하지 않는다.

## Android 검증 빌드 계약

다음은 패키징 담당자가 확인한 이번 실험 설정이다. 최종 게임의 지원 기기와 배포 서명 정책은 아직 미정이다.

| 항목 | 실험 설정 |
|---|---|
| 도구 | Godot 4.6.3 + 같은 버전 export templates, OpenJDK 21 |
| 설치 SDK | Android command-line tools 11076708, platform-tools, build-tools 35.0.0, platform 35 |
| 내보내기 | Gradle 없는 Godot APK 템플릿. 템플릿의 minSdk 24 / targetSdk 36이며 설치 platform 35로 직접 네이티브 코드를 컴파일한 결과는 아니다. |
| 앱 식별 | `org.hora.monthly.experimental`, `0.1.0-experimental` |
| ABI / 표시 | `arm64-v8a` + `x86_64`, portrait |
| 네트워크 | 인터넷 권한 없는 로컬 실험 |
| 서명 | Godot 로컬/CI debug 키. 기존 알파 익스체인지의 정식 키와 무관하다. 빌드 환경마다 인증서가 달라질 수 있어 서로 다른 빌드 간 덮어쓰기 업데이트를 보장하지 않는다. 삭제/재설치의 로컬 저장 보존은 별도 확인이 필요하다. |
| 라이선스 | Godot 엔진 MIT. 프로젝트 코드/콘텐츠의 배포 라이선스 선택과 별개이며 포함한 제3자 고지를 확인한다. |

프로젝트 디렉터리에서 Linux용 검증 빌드는 `bash tools/build.sh linux`, Android는 `ANDROID_HOME=<SDK경로> bash tools/build.sh android`로 준비한다. 명령의 실제 성공과 최종 파일은 [validation.md](validation.md)에 기록한다.

예상 산출물은 `build/monthly-economy-experimental.apk`, `build/APK-VERIFICATION.json`, `build/BUILD-MANIFEST.json`, `build/SHA256SUMS.txt`다. 경로가 정해졌다는 것과 해당 게임의 최종 빌드가 검증됐다는 것은 다르다. 기존 제품의 워크플로와 분리된 `.github/workflows/monthly-economy.yml`을 사용한다.

## 실험 값 등록부

실험 데이터는 테스트 경계와 동작을 관찰하기 위한 입력이다. 필수 필드는 명시적으로 검증하고 누락값을 침묵하는 임의 기본값으로 메우지 않는다. 실제 적용된 파일·변경 이력·시험 결과를 함께 남긴다.

| 값/집합 | 분류 | 용도 | 한계와 변경 영향 |
|---|---|---|---|
| seed `42` | experimental | 같은 초기 상태와 명령의 재현 비교 | 특정 시드의 성공이 여러 세계 생성 성공률을 입증하지 않는다. |
| `3대륙 × 대륙당 1국가 × 국가당 1도시` | experimental 규모 | 세계 계층·국경 교역의 작은 검증 세계 | 정확히 3개 대륙만 사용자 확정이다. 국가·도시 수와 출시 규모는 미정이다. 국내 도시 간 거래는 별도 fixture가 필요하다. |
| 시작 현금·재고·인물·시설 | experimental 개시 자산 | 생산/구매/급여/건설의 연결 시험 | 개시 장부와 물량 출처에 한 번만 기록한다. 진행 중 부족분을 같은 초기화 코드로 보충하지 않는다. |
| 품목·레시피·가격·임금·공기 | experimental 콘텐츠 | 코드 경로와 제약을 검증 | 전체 상품 목록이나 밸런스가 아니다. 단위·공급 연결·운전자금·구매력에 영향을 준다. |
| 내부 계산 단계·시간 단위 | experimental 실행 방식 | 인과 순서와 결정적 월 정산 시험 | 월말 매출로 월초 지급 불능을 소급 해소하지 않도록 시점별 가용량을 검사해야 한다. |

구체적인 콘텐츠 값은 [experimental-data.md](experimental-data.md)에 단위·선택 목적·변경 영향별로 기록했다. 정의 원본은 `data/experimental.json`이며 품목/레시피/건물/parameters를 내용 해시에 포함한다. 아직 코드를 대조하지 않은 숫자를 이 문서에서 새로 만들어 넣지 않는다.

## 코어를 UI와 분리하는 계약

- UI는 읽기 전용 조회와 검증된 명령을 사용한다. AI도 같은 명령 경로를 사용한다.
- 인물·가계·법인·정부 계정과 대표 권한을 분리한다. 직위 변경은 소유권 이전이 아니다.
- 통화별 금액은 최소 화폐 단위 정수로 처리한다. 이번 CR 표시는 100최소단위=1 CR이며 데이터의 정수와 화면의 CR 표시액을 구분한다. 물량과 시간은 품목·직무별 명시 단위를 사용한다.
- 직렬화에서 정수 정밀도·범위·반올림·형식 버전을 검증한다. GDScript 정수와 JSON 왕복이 동일하다고 가정하지 않는다.
- 작업 상태에서 월을 계산한 뒤 불변식 검사 성공 시에만 교체한다. 실패는 정상 월로 저장하지 않는다.
- 공개/내부/계약/유료 정보와 관측 시점을 구분한다. 엔진의 전체 상태를 AI의 무료 정보로 전달하지 않는다.
- 같은 시드·상태·명령의 결과를 비교하고 UI 동작이 난수를 소비하지 않게 한다.
