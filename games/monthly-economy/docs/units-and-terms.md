# 금액·상품 단위와 쉬운 용어

USD·M/B 축약·1달러=1,000원 표시 환율은 사용자 확정 조건이다. 품목 대표 규격과 환산에 필요한 질량·공정 계수·타일 척도는 실험 데이터다. 단위는 실제 차원을 사용하지만, 가격·생산량·인구·건설 기간이 현실 통계에 맞게 보정되었다는 뜻은 아니다. 모든 금액 숫자를 일괄 확대하거나 기존 상품 수량에 숨은 배수를 곱하지 않는다.

## 달러와 원화 표시

- 기본 금액은 미국 달러(USD)다. 입력창과 보고서는 달러로 읽고, 내부 장부는 정수 센트로 저장한다. **$1.00 = 100센트**다. 예를 들어 $12.34를 입력하면 1,234센트를 저장한다.
- 기존 가격·임금·잔고의 정수 숫자는 그대로 유지한다. 화면에 달러를 표시할 때만 100으로 나눈다. 금액 단위 정리는 실제 시세로 가격을 맞추는 재조정이 아니다.
- **M = 1,000,000달러**, **B = 1,000,000,000달러**다. $1M은 100만 달러이고 $1B는 10억 달러다. M/B는 표시 축약일 뿐 장부의 별도 통화나 저장 단위가 아니다.
- 원화는 **$1 = 1,000원**으로 고정 환산해 보여준다. 따라서 **$1M = 10억원**, **$1B = 1조원**, $0.01 = 10원이다. 이 표시는 실제 환전·국가별 환율·외환 계좌를 바꾸지 않는다.
- 시급은 $/시간, 상품 단가는 $/해당 품목 단위, 월 예산은 $/월처럼 기준을 붙인다. 서로 다른 통화의 실제 계약은 해당 통화 ID를 유지하며 원화 표시로 결제하지 않는다.

## 물량과 기간

- 수량은 각 상품의 `unit`에 적힌 kg, L, m³, kWh, 개, 대, 벌 등으로 읽는다. 톤이나 MWh로 자동 재해석하지 않는다. 1t = 1,000kg, 1m³ = 1,000L, 1kWh = 1,000Wh다.
- 레시피는 **공정 1회**의 투입·산출이다. 예를 들어 곡물 4kg → 밀가루 3kg은 원료 수요 4kg와 완제품 3kg이며 4개와 3개가 아니다. `quantity_units`에 각 투입·산출 단위를 함께 둔다.
- 노동은 시간이다. 3명과 12시간을 직접 비교하지 않는다. 장비 대수와 장비 가동시간도 구분한다. 건설 기간은 개월이며, 인력·장비를 늘려도 최소 기간을 없애지 않는다.
- 월 번호(예: 제12월)와 남은 기간(예: 3개월)은 다르다. 실제 달은 사용자가 다음 달을 실행할 때만 진행한다.
- 교육의 시간은 **수강생 1명이 받는 교육시간**, 수리·전문 업무·개발 업무는 **작업시간**이다. 강사의 근로시간과 여러 수강생의 교육시간을 같은 수량으로 합치지 않는다.
- 가축은 마리다. 마릿수와 생육에 필요한 개월 수를 곱한 값을 재고 마릿수로 사용하지 않는다. 대표 축종을 한 품목으로 다루는 현재 생물 모델의 한계는 아래에 남긴다.
- 인터넷은 회선의 월 이용, 창고 보관 서비스는 kg의 월 보관이다. `service_period: month`가 있는 상품은 단가를 $/회선·월 또는 $/kg·월로 표시한다. 소프트웨어는 좌석 수이며 영구·구독 기간은 개별 계약에서 정한다.
- 진료·운송·판매 중개는 건, 외식은 인분, 숙박은 박으로 센다. 서비스의 미사용 당월 능력은 다음 달의 실물 재고가 되지 않는다.

## 운송·창고는 질량으로 계산

이번 물류 모델은 **질량 하나만** 한도로 사용한다. 부피·축중·차량 종류별 법정 적재·거리별 연비는 아직 계산하지 않는다.

- 모든 실물 상품에는 `cargo_mass_g_per_unit`이 있으며 기존 `cargo_size`와 같은 정수 값이다. 두 이름 모두 **상품 1단위당 g**를 뜻한다. 무차원 적재 점수가 아니다.
- 예를 들어 철광석 3kg은 3 × 1,000 = 3,000g, 컴퓨터 2대는 2 × 5,000 = 10,000g이다. 함께 싣는 무게는 13,000g = 13kg이다. 3kg + 2대를 그대로 5라고 더하지 않는다.
- 우유 1L는 실험 대표 밀도 1.03kg/L로 1,030g이다. 천연가스는 0°C·101.325kPa의 실험 기준 상태에서 1m³당 720g으로 둔다. 기기·가축 등의 단위 질량 역시 현재 콘텐츠가 정한 대표 규격이며 모든 실제 제품에 같은 질량이 있다는 뜻은 아니다.
- 노선의 월 적재 한도와 사용량, 현장·창고의 한도와 보관량은 내부에서 모두 g다. 화면은 kg 또는 t로 환산한다. 서비스·디지털 사용권은 운송 질량 0이며 실물 화물 재고에 넣지 않는다.
- 승인된 실험값은 노선 120,000,000g/월(120t), 기본 현장 2,000,000,000g(2,000t), 창고 증설 1,000,000,000g(1,000t)다. 실제 지원 규모나 현실 물류의 적정 용량을 확정한 수치가 아니다.
- 운송 연료 처리 계수는 12,000,000g/L, 노동 처리 계수는 12,000,000g/시간이다. 이는 현재 게임의 월간 처리 계수이며 실제 주행 거리별 연비를 뜻하지 않는다. 운임은 센트/t 기준 총액을 계산한 뒤 화폐 최소 단위로 반올림한다.

## 토지와 자원

지도 칸은 타일로 배치하되 면적은 m²로 읽는다. **실험 기본값은 타일 한 변 10m, 한 칸 100m²**다(`parameters.tile_side_m = 10`). 이는 사용자 확정값이 아니며 향후 설정으로 교체할 수 있는 지도 물리 척도다. 면적은 타일 수 × 한 변 길이²로 계산한다. 예를 들어 2×2칸 부지는 400m²다. 이 길이에서 실제 건축 공법·용적률·운송 거리까지 자동으로 추론하지 않는다. **기존 토지·건물 가격은 필지 총액을 그대로 유지하며, m²당 가격으로 재해석하지 않는다.** 직물·가죽 상품의 m²는 각 상품의 면적이며 지도 타일과 구별한다.

매장량과 채취량은 산출물과 같은 단위를 쓴다. 광산은 광석 kg, 유정은 원유 L, 가스전은 천연가스 m³, 어장은 수산물 kg, 숲은 생산 가능한 목재 kg, 채석장은 석재 kg, 수원은 m³다. `resource_units`에 대응 상품과 단위를 적었다. 광물·원유·가스의 현재 공정은 주산물 4kg/L/m³를 만들 때 같은 단위의 자원 4를 사용하며, 어획 5kg은 어장 자원 5kg을 사용한다. 초기 기본 자원 수치는 20,000이며 실제 도시별 설정 계수와 자원 단위를 함께 읽어야 한다. 자연 성장·어군 회복은 별도 환경 과정이다.

## 쉬운 말과 필요한 전문용어

| 화면에서 읽는 말 | 필요한 전문용어와 의미 |
|---|---|
| 출자금 | 회사를 만들 때 넣고 지분을 받는 돈. 매출이 아니다. |
| 지분 | 회사의 소유권. 대표 직위와 구별한다. |
| 대표 | 회사 운영 권한을 맡은 직위. 회사 돈이 개인 돈이 되지 않는다. |
| 매출 | 실제 상품·서비스 제공으로 번 금액. 주문·대출·선불금과 구별한다. |
| 비용·원가 | 당월 활동에 쓰인 비용과 상품 생산·취득에 든 원가. 현금 지출 시점과 항상 같지 않다. |
| 받은 선불금 | 아직 제공해야 할 의무가 있는 돈(계약부채). 제공하기 전 매출로 전부 잡지 않는다. |
| 따로 보관한 주문 자금 | 미체결 매입 주문용 예약금(에스크로). 다른 명령에 중복 사용할 수 없다. |
| 회사 정리 | 남은 자산과 채무를 처리하는 청산. 돈을 새로 만들어 채권자에게 지급하지 않는다. |
| 못 받은 돈·갚을 돈 | 채권·채무. 미지급과 법적으로 소멸한 부채는 다르다. |
| 공공 구매·납품 제안·납품 확인 | 조달·입찰·검수. 계약만으로 납품 실적이 생기지 않는다. |
| 실제 남긴 생산가치 | 부가가치. 원료·부품·완제품 매출을 모두 더해 중복 계산하지 않는다. |
| 세율·금리 | 화면은 %, 내부 계산은 bp. 100bp = 1%, 10,000bp = 100%다. |
| 품질·숙련 | 게임 점수·단계. kg, 시간, 화폐 같은 물리량과 구별한다. |

## 물리 검증이 남은 공정

단위를 실제 차원으로 정리했다고 모든 레시피의 질량수지까지 맞춘 것은 아니다. 이번에는 제분 투입을 곡물 4kg로 바로잡고 밀가루 산출 3kg을 유지했다. 잔여 1kg은 껍질·수분 등 제분 손실이며 현재 별도 판매 재고로 만들지 않는다. 자원 추출도 자원과 주산물의 단위를 맞췄다. 다른 공정은 기존 정산·고용·예산의 광범위한 재조정을 피하기 위해 `physical_validation: experimental_unverified`로 남긴다.

| 확인된 과제 | 현재 드러나는 차원·질량 문제 | 후속 보강 방향 |
|---|---|---|
| 사료 | 곡물 2kg + 채소 1kg → 사료 6kg | 수분 등 추가 투입 또는 산출량을 명시적으로 보정하고 축산 공급을 회귀 검사 |
| 제철 | 광석 2kg + 석탄 1kg → 강철 3kg + 회수 원료 1kg | 광석 품위·회수율·부산물을 함께 보정 |
| 유리 | 규사 2kg → 유리 3kg | 다른 광물 투입 또는 산출량 보정 |
| 정유 | 원유 2L(1.7kg) → 연료 3L(2.25kg) + 플라스틱 1kg | 투입 원유·수율·부산물을 실제 질량 기준으로 보정 |
| 화학·비료 | 기체·액체의 부피와 고체 산출 질량을 검증하지 않은 계수 사용 | 밀도·조성·추가 원료를 정의한 뒤 공정별 질량수지 검증 |
| 완제품·기계 | 몇 kg의 소재·부품에서 수십~수천 kg의 대표 기기 1대를 만드는 기존 소량 레시피 | 필요한 부품·철강·제조 규모를 보강하고 운전자금·필수공급에 미치는 영향 검사 |
| 가축·산란 | 하나의 가축 품목이 번식·우유·산란·육류의 공통 촉매로 사용됨 | 소·양·산란계 등 축종·개체의 단위와 성장·먹이·산출 규격 분리 |
| 내구재 회수 | 품목 개수·벌·대를 폐기물 kg로 바로 바꾸면 부정확 | 마모 수량 × 단위 질량을 기준으로 회수율·재질을 구분 |

부패한 재고의 회수는 이미 질량 기준으로 처리한다. 회수 가능한 g = floor(부패 수량 × `cargo_mass_g_per_unit` × 회수율 / 100), 유기성 폐기물 kg = floor(회수 가능한 g / 1,000)이다. 1kg 미만의 나머지와 회수하지 못한 질량은 손실로 기록한다. `waste_mass_balance` 사건에서 원래 질량·회수 질량·미회수 질량·반올림 손실을 g로 확인할 수 있다. 로트별 정수 반올림 때문에 로트를 나눈 방식에 따른 회수량 차이는 허용하되 기록한다.

위 항목은 현실 공정을 검증했다고 주장할 수 없는 구체적인 한계다. 레시피 숫자를 단위 이름만으로 숨기거나 상품별 서로 다른 물량을 직접 더해 해결하지 않는다.

## 저장 호환

새 규칙 ID는 `experimental-0.2-usd`다. 기존 0.2 저장은 화폐명뿐 아니라 상품 규격·운송 질량·일부 생산식이 다르므로, 금액만 바꿔 새 물리 단위로 자동 덮어쓰지 않는다. 호환되지 않는 원본 파일은 보존하고 새 게임이 필요하다고 안내한다. 호환되는 현재 저장을 내보내고 다시 읽을 때도 달러 입력·센트 정수 저장 규칙은 같다.
