# 09. 요구사항·후속 계획

> 0.1.0 작성 시점의 설계·검토 기록입니다. 0.2.0 구현과 달라진 사항은 [현재 구현 기준20](20-v0.2.0-implementation.md)과 [실측19](19-balance-v0.2.0.md)를 우선합니다.

PR #29 이후 권장 개발 순서·진행표는 [14](14-development-plan.md), 사용자 지정 고서 목판과 새 배치는 [15](15-ui-ux-improvement.md)를 본다.

상태: 현재 구현의 추적표와 **미승인 후속 제안**. 최초 요청은 PR #28 개발 완료·APK 한 개 배포였고,
이번 요청은 클로드 피드백용 전체 문서 작성이다. 문서화 중 발견한 항목을 자동으로 개발 범위에 넣지 않는다.

## 2. 다음 단계의 우선순위 제안

아래 순서는 작성자의 제안이다. P1은 다음 안정화에서 우선 평가, P2는 그다음 개선 후보를 뜻한다.
시간·인력 추정이나 오너의 착수 승인은 포함하지 않는다. 재현 사실과 기획 선택은 [12](12-open-questions.md)를 본다.

| 제안 | 우선순위 | 목적·의존 | 제안 수용 기준 |

| F-02 보상·등급 경계 | P1 | OQ-02·04, 좋은 보상이 역효과를 내는 상황 해소 | 전 등급 보상에서 기존 공법 하락 없음, 최고 공법의 의도·획득 경로·한계 설명 일치 |

| F-08 장기 메모리·저장 | P2 | OQ-10·12 | 합의한 장기 연도·인구별 메모리/파일/로드·저장 p95 측정, 보관 정책 결정 |
| F-09 모바일 가독성·접근성 | P2 | OQ-09, 기기 기준 결정 | 작은 화면·큰 글자·IME·제스처·명도 대비·터치 영역 기준을 정해 실제 통과 |

같은 시드의 미래가 바뀌는 수정은 기준 소스·입력·지표를 함께 갱신한다. 기존 결과를 무조건 유지하는
것과 결함을 수정하는 것 사이의 저장·재현 정책을 먼저 정한다.

클로드 검토(2026-10-29)는 위 F-01~F-11을 작업 명세 XO-03~XO-10으로 옮겼다. 대응표와 권장안은 [13 §5](13-claude-review.md)를 본다.

## 4. 향후 명세 작성 형식

클로드 피드백을 받으면 다음 작업마다 **문제·사용자 효과 → 확정된 동작 → 변경 파일 범위 → 입력/경계 →
수용 기준 → 검증 명령 → 저장·난수 영향 → 제외 범위**를 남긴다. 개발 에이전트가 모호한 밸런스나
제품 정책을 임의 확정하지 않도록 수치와 실제 예를 포함한다.

멀티플레이·새 종문·외교·모딩·클라우드·상점·수익화 등은 현재 요청의 자연스러운 후속 구현으로
가정하지 않는다. 별도 제품 결정과 명세가 필요하다.
