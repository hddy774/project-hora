# 10. 클로드 검토 요청문

아래 본문을 전체 문서 묶음 또는 통합 검토본과 함께 클로드에게 전달한다.
코드 접근이 가능한 환경에서는 고정 소스를 확인하고, 접근할 수 없으면 문서 기반 검토의 한계를 명시하도록 요청한다.

---

선로만상록 프로젝트(Xianxia Observer)의 기획·기술 전반을 검토해 주세요. 현재 구현을 설명한 검토용 문서이며,
제안 항목은 프로젝트 오너가 아직 승인하지 않았습니다. 검토 결과를 다음 개발 명세로 옮길 수 있는
구체적인 피드백과 결정 요청으로 작성해 주세요.

**검토 기준**

- 저장소/PR: https://github.com/hddy774/project-hora/pull/28
- 문서 기준 코드: `17b48ad1bfcb58a9d32a8def0e74caa2027cb7f0`
- 고정 소스: https://github.com/hddy774/project-hora/tree/17b48ad1bfcb58a9d32a8def0e74caa2027cb7f0/games/xianxia-observer
- 현재 APK 소스: `f8838425f6a3303d11171605abba47008862491c`.
  기준 커밋과 게임 소스·테스트·공통 프로젝트 설정은 동일하고 게시 도구·문서가 후속 변경됐습니다.
- 게임은 **1틱=1년, 기본 인구1,000명의 오프라인 관찰 시뮬레이션**입니다.
  저장소 루트의 호라경제연구실(1턴=1개월)과 별개입니다.
- 공개 버전은 v0.1.0, APK 한 개가 최신 안정 릴리스에 배포됐습니다. PR은 미병합 상태입니다.

**읽을 자료**

문서 홈의 상태 표기를 먼저 읽어 주세요. 제품·규칙·수치는 01~03, 화면은04, 기술·저장은05~06,
빌드·검증은07~08, 요구 추적과 제안은09, 원본 비교는11, 우선 재검토할 관측은12에 있습니다.
부속 자료에는 실제 상수/모델 JSON, 28종 데이터 사전, 소스·테스트 색인, 저장 JSON 발췌,
3시드×3만 년 측정 원문과 다섯 격리 실험 재현 도구가 있습니다.

**우선 확인할 쟁점**

1. 관찰의 재미와 플레이어 역할: 관심 표시가 세계 결과를 바꾸는 현재 동작을 허용할지,
   정보 탐색·천기 개입·윤회 기록만으로 첫 세션과 장기 관찰 동기가 충분한지 판단해 주세요.
2. 규칙의 정확성: 공법 보상 하락, 신품 획득 경로, 사건 영기 보정 중첩, 최초 도달·우승 횟수·좌화
   집계 의미를 실제 코드와 대조해 주세요. 문서의 수식·단위·처리 순서 오류도 찾아 주세요.
3. 밸런스: 3시드30,000년에서 비승0, 정도3승/마도6승이라는 작은 표본을 과장하지 말고,
   목표 경지 분포·첫 도달·비승 빈도·종문 회복성·영석 흐름의 **권장 목표와 이유**를 제안해 주세요.
4. 저장·결정론: 잘못된 RegionId의 로드 예외, 무제한 기록, 단일 RNG와 로그 분기,
   double 연산, 실패한 해의 부분 변경, 정지 중 자동 저장 계약을 검토해 주세요.
5. Android UX·기술: 일곱 탭의 정보량·글자·터치·알림·safe area, 공유 잠금과 압축,
   백그라운드 저장·실기기 수용 기준을 평가해 주세요.
6. 검증과 배포: 자동49검사, API34 x86_64 실행, 서명·소스·재다운로드 증빙이 실제로 무엇을 보장하는지
   판단해 주세요. 런처 ANR로 가려진 탭 입력과 ARM64/최소 API 미검증을 완료로 간주하지 말아 주세요.

검토 순서는 저장소 가이드에 맞춰 **정확성·수용 기준 → 결정론·보존 → 성능 → 가독성**으로 해 주세요.
현재 동작, 재현된 결함, 제품 의도 확인이 필요한 사항, 개선 아이디어를 구분해 주세요.
문서의 OQ 목록을 그대로 승인하기보다 근거와 반례를 다시 확인해 주세요.

**원하는 피드백 형식**

1. 가장 먼저 결정하거나 수정할 **상위5개**와 그 이유.
2. 항목별 표: `ID | 유형(결함/기획결정/검증공백/개선) | 우선순위(P0/P1/P2) | 근거 파일·수식·관측 |
   사용자 영향 | 권장 동작 | 재현 입력 | 수용 기준 | 저장·난수 영향`.
   확인하지 못한 내용은 추정이라고 표시하고, 가능한 대안과 트레이드오프를 적어 주세요.
3. 오너에게 물어야 할 결정과 권장안. 미결정 수치를 확정 사실로 서술하지 말아 주세요.
4. 다음 안정화 작업을 3~5개 명세로 나눠 제목·변경 범위·완료 기준·검증 방법을 제안해 주세요.
5. 문서 자체의 오류·누락·서로 다른 설명을 별도 목록으로 알려 주세요.

P0는 진행·저장에 광범위하고 치명적인 문제가 입증된 경우, P1은 다음 안정화에서 우선 해결할 문제,
P2는 이후 개선 후보로 사용해 주세요. 기능 수를 늘리는 제안은 해결할 사용자 문제와 최소 범위를 함께 적어 주세요.
근거 없는 출시 준비 완료 판정이나 비공개 실기기 검증 가정은 피하고, 판단에 필요한 추가 실험을 제안해 주세요.
