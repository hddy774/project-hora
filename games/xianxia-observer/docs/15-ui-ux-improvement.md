# 15. 고서 목판 UI·UX 배치 개선안

현재 실행 승인과 범위는 [17 전체 구현 승인](17-implementation-acceptance.md)을 따른다.

상태: **테마는 사용자 지정(2026-10-29), 배치와 구현은 검토용 제안**. 현재 구현은 [04](04-ui-ux.md)에 보존한다.
사용자 이미지 `1000014419.jpg`를 [원본 그대로 보관](design/woodblock-reference.jpg)했다.
[조작 가능한 배치 시안](design/woodblock-prototype.html)은 가상 데이터로 화면 흐름을 보여 주는 검토 자료다.

## 1. 시각 방향과 현재 문제

레퍼런스의 한지·먹색 목판 표제·이중 테두리·산수화·한자 표식을 계승한다. 정보 위계와 터치 영역은 모바일에 맞춰 조정한다.
실제 화면은 상단에 상태·속도6개·도감·설정이 함께 있고, 하단7탭과 인물 상세7분류가 작은 글자로 배치돼 있다.
현재 버튼12·칩11·탭 보조10 논리 단위와 헤드리스 화면을 대조했다. 실사용 성공률은 아직 측정하지 않았다.

| 참조에서 유지 | 개선 제안 | 이유 |
|---|---|---|
| 한지색·먹색 표제·얇은 판곽 | 질감은 저대비, 숫자·본문 아래는 단색 | 고서 분위기와 가독성 양립 |
| 수묵 산수 | 표제/종문 배너에만 장식, 데이터 위 장식 제거 | 정보·그래프와 장식 분리 |
| 청운 청색·천마 적색 | 이름·문양·범례도 함께 제공 | 색만으로 구분하지 않음 |
| 한자+한글 표식 | 한글 이름을 항상 표시, 터치 영역48 이상 | 처음 보는 이용자도 의미 파악 |
| 7개 콘텐츠 화면 | 주요5탭+더보기 진입으로 전체 기능 보존 | 자주 쓰는 탐색에 폭 확보 |

이미지의 영맥진+6%·우승·사상자 등의 수치/문구는 테마 근거로만 사용한다. 규칙은 현행 코드와 XO-08을 따른다.
예를 들어 실제 수련 보정은 단계당4%다. 이미지의 긴 연도·인물·그래프도 밸런스 기준으로 사용하지 않는다.

## 2. 토큰과 공통 배치

아래는 제안 색상이며 이미지에서 정밀 측색한 값은 아니다. Avalonia에서는 논리 단위(DIP)를 쓴다.

| 토큰 | 제안 | 적용 |
|---|---|---|
| Paper / Surface | `#F3E8CC` / `#FAF3DF` | 바탕 / 읽는 면 |
| Ink / Muted | `#202A2B` / `#655A46` | 본문 / 보조 |
| Wood / Line | `#805B25` / `#B5A47A` | 선택·인장 / 판곽 |
| Orthodox / Demonic | `#2F5B79` / `#914740` | 청운 / 천마 |
| 제목 / 본문 / 보조 | 20 / 15 / 13 | 기존 Noto Serif KR Regular/Bold 재사용 |
| 간격 | 바깥16, 항목8, 카드 안12 | 정보 영역 공통 |
| 터치·대비 | 최소48×48, 일반 텍스트4.5:1 | 아이콘·칩도 투명 hit 영역 포함 |

레이아웃은 `safe area → 헤더 → 스크롤 본문 → 진행 바 → 하단 탐색 → safe area` 순서다.
기본 헤더80·진행 바48·탐색64를 시작값으로 잡되 글자가 커지면 높이가 늘어난다. 고정 높이로 잘라내지 않는다.
360×640 기본 글자·상하 safe area 각24에서 본문 높이360 이상, 130%에서는280 이상을 목표로 한다.
safe area는 루트에서 한 번만 적용한다. 배경 그림은 영역을 채워도 글자·터치는 시스템 영역 밖에 둔다.

```text
┌─ 먹색 목판 표제 · 은은한 산수 ────┐
│ 선로만상록 프로젝트           366,710년    │
│ 태평성대 · 휴전         천기 6   │
├────────────────────────────────┤
│ 현재 탭의 핵심 정보              │
│ 관심 인물 / 사건 → 상세          │
│ 나머지 정보는 세로 스크롤        │
├────────────────────────────────┤
│ [정지/진행]     20년/초 [속도]   │
│ 천하 · 종문 · 인물 · 사기 · 더보기│
└──────── 시스템 하단 여백 ────────┘
```

속도는 현재 값만 상시 표시하고 누르면 1/5/20/100/500/최대를 3열×2행 패널로 선택한다.
정지·재개는 어느 주 화면에서도 한 번에 접근한다. 상세에는 현재 진행 상태와 정지 조작을 함께 제공한다.
주요 사건은 본문 상단의 한 줄 요약/카드로 읽고, 토스트는 최대1개로 제안한다. 상세·키보드 중에는 토스트 표시를 보류한다.

## 3. 탐색 구조와 복귀 계약

| 기존 | 새 위치 | 접근 비용 |
|---|---|---|
| 천하·종문·인물·사기 | 같은 이름의 주요 탭 | 1번 탭 |
| 업적·현황·기록 | 더보기의 첫 세 항목 | 2번 탭 |
| 기록의 최근 사건 | 천하의 `기록 전체` 바로가기 | 1번 탭 |
| 도감·설정 | 더보기, 위험 상태의 복구 바로가기 | 일반2번, 복구1번 |

360폭에서 하단 셀은7개일 때 약51, 5개일 때72 논리 단위를 확보한다. 저빈도 화면의 접근이 한 번 늘어나는 비용이 있다.
기존7개 Page의 데이터·필터·상세 링크를 보존하고, 탭 번호를 세계 데이터나 저장 ID로 쓰지 않는다.
뒤로 가기는 `최상단 상세 닫기 → 더보기 하위면 더보기 → 다른 주 탭이면 천하 → 플랫폼 종료` 순서다.
복귀 시 검색어·필터·정렬·페이지·스크롤을 유지한다. 새 세계/불러오기 성공 때만 세계가 바뀐 상태를 명시하고 목록을 초기화한다.

## 4. 화면별 배치와 조작

| 화면 | 위→아래 정보 순서 | 핵심 동작·완료 기준 |
|---|---|---|
| 천하 | 시대·전쟁 요약 → 관심 인물/추천 → 최신 주요 사건 → 종문 비교 → 지도·경계 | 상세는 카드 한 번으로, 첫 화면에 관찰 시작점과 다음 사건 상태 |
| 종문 | 두 종문 선택 → 종주·전력/금고 요약 → 영지 → 시설 → 직위·녹봉 → 역사 | 시설은 효과·현재 단계 동시 표시, 긴 숫자는 줄바꿈/단위 축약+원값 확인 |
| 인물 | 검색48높이 → 소속/관심 필터 → 정렬 단추 → 20명 목록 → 페이지 | 8정렬은 선택 패널, 선택값 유지. 검색 중 IME가 입력/결과를 가리지 않음 |
| 인물 상세 | 이름·경지·소속 →4분류 → 해당 본문 → 관심/천기 조작 | 첫 화면에서 생존·윤회·진행 상태와 대상 확인 |
| 사기 | 연대기/천하 기록/전쟁/대회/비승/경매 선택 → 세로 이력 | 연도·종류·인물·결과를 분리. 사건 하나에서 관련 상세로 이동 |
| 기록 | 종류·관심 필터 → 최신 사건40건 → 페이지/보관 범위 | 누계와 보관600건을 구분, 필터 후 결과0건 안내 |
| 업적·현황 | 분류 선택 → 순위/주요 지표 → 그래프·범례 | 색+이름 구분, 압축 통계는 실제 연도 축, 현재값과 누계의 단위 표시 |
| 설정 | 저장 상태·복구 안내 → 저장/불러오기 → 새 세계 위험 영역 | 저장 동작과 세계 교체를 시각 분리. 오류면 저장/재개 비활성, 복구 행동 제시 |

인물 상세 분류는 `개요 / 수행 / 인연 / 생애` 네 개다. 개요에서 전투력 항목을 펼치고, 수행에 소지·기예·아이템을 둔다.
생애에는 현생/전생 선택을 둔다. 기존7분류의 모든 필드를 옮기고 삭제하지 않는다. 선택한 분류와 스크롤은 복귀 때 유지한다.
관심은 무료 관찰, 기연은 천기2점 개입으로 버튼 문구·색·확인 흐름을 다르게 한다.
기연은 대상명·현재 경지·효과·비용·사용 후 잔액을 확인한 뒤 실행한다. 잔액 부족·대상 소멸은 이유와 함께 비활성화한다.

## 5. 첫 관찰·빈 상태·알림

관심 인물이 없을 때 `인물 찾기`와 `주목할 인물`을 보여 준다. 추천은 현재 세계에 있는 인물의
최근100년 **이미 보관된** 돌파·대회 사건에 연결된 ID를 중복 제거하고 최신 연도 내림차순·ID 오름차순으로 최대3명 제안한다.
후보가 없으면 현재 전투력 내림차순·ID 오름차순 3명과 그 이유를 표시한다. 별도 난수·역사 백필은 사용하지 않는다.
오래된 기록이 보관 한도 밖이면 추천에 없을 수 있다. 관심 자동 등록·시간 자동 건너뛰기·새 보상은 추가하지 않는다.

빈 상태는 `관심 없음 → 인물 찾기`, `검색0명 → 검색/필터 초기화`, `기록 없음 → 조건 설명`,
`대상 없음 → 사기/비승 기록 확인`, `저장 오류 → 불러오기/새 세계`로 다음 행동을 제시한다.
중요 사건을 토스트만으로 전달하지 않고 보존된 사기/기록으로 연결한다. 토스트 보류가 세계 난수·관심 상태를 바꾸지 않게 한다.

## 6. UI-QA 수용 시나리오

| 검사 | 통과 조건 |
|---|---|
| 탐색 회귀 | 주5탭+더보기의 업적/현황/기록+도감/설정, 기존 상세7종을 실제 입력으로 확인 |
| 작은 화면·큰 글자 | 360×640·412×860, 글자100/130/200%. 수평 잘림·겹침 없음, 세로 스크롤로 핵심 조작 접근 |
| 터치·접근성 | 모든 조작 hit 영역48 이상, 일반 글자 대비4.5:1, 아이콘 이름·포커스 순서·선택 상태 제공 |
| IME·safe area | 검색창·확인 단추가 키보드에 가리지 않음, 노치/제스처 영역에 조작 없음 |
| 복귀 | 검색/필터/정렬/페이지/스크롤과 상세 분류 유지, 더보기 하위의 뒤로 경로 정상 |
| 개입 | 확인 전 천기 불변, 부족·소멸·중복 차단, 실행은 코어 Can… 계약 사용 |
| 관찰 무영향 | 추천·정렬·본문 탐색·토스트 보류로 세계 RNG/상태가 달라지지 않음 |
| 오류·저장 | faulted에서 재개·저장 차단, 정상 저장 불러오기/새 세계로 복구 가능 |
| Android | API24/34 입력 로그+화면, ARM64 실기기 결과. 같은 인증서 업데이트와 저장 유지 확인 |

시안은 브라우저 배치 검토이며 Avalonia·Android의 수용 완료 증거와 구분한다.
테스트 장비·글자 배율·판정 화면·입력 로그를 구현 PR에 첨부하고, UI-QA를 통과한 뒤 새 배치 완료로 표시한다.
