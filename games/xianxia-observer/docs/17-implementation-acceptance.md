# 17. 전체 구현 승인과 실행 기준

2026-10-29 사용자 지시: “개발 전부 진행하고. 최신릴리스 APK 배포까지 진행해줘.
클로드의 모든 피드백을 받아들이고. 개발을 진행해줘.”

이 지시로 XO-03~13·UI-QA와 클로드 검토13의 권장안을 승인한 것으로 기록한다.
D-01~09를 재질문하지 않고 구현한다. 이미 배포된 v0.1.0을 유지하고, 안정화와 새 UI를 포함하는 다음 버전을 v0.2.0으로 게시한다.
APK 최신 릴리스 게시와 태그 생성은 이번 지시로 승인됐다. 사용자의 후속 지시로 완료 PR도 병합한다. 대표 PR과 서브 PR 운영은 [18](18-github-delivery-workflow.md)을 따른다.

| 결정 | 적용 |
|---|---|
| D-01·09 | 관심은 순수 관찰, 수정 뒤 같은 시드 미래 변경 허용. 구 저장은 계속 불러오기 |
| D-02 | 자연 비승이 관찰 가능한 희귀도. 1,000명·3만 년 10시드 중앙값1~3회·첫 비승15,000~30,000년 목표 |
| D-03 | 이념 비대칭 유지, 승률30~70%·연속3패 비율20% 이하를 측정해 회복성 조정 |
| D-04·05 | 신품 예약 표기, 계산을 유지하고 우승 생·입세·개벽 이후 돌파·경지 하락으로 표시 정정 |
| D-06 | 단일 저장·정상본1세대·손상본3개·디스크 flush |
| D-07 | API24 유지, API24/34 입력·ARM64 검증. 실기기와 에뮬레이터 결과를 구분 |
| D-08 | 사용자의 전체 개발 요청에 따라 안정화와 UI 개선을 v0.2.0으로 함께 배포 |
| 본산 개입 | XO-05의 권장안 채택: 본산0·4 차단, 비용 차감 전 검증 |
| UI | 사용자 고서 목판 테마·5탭·인물4분류·큰 글자·48 터치·대비4.5:1 |

XO-10은 버그 수정 뒤의 분포·성장 기여·저장/질의 성능을 측정한다.
그 결과를 기준으로 XO-14에서 수련/요구 영기/종문 회복성 계수를 조정한다. 추정치를 실측값으로 소개하지 않는다.
상한 없는 기록은 먼저10만 년·3,000명에서 측정하고, 필요할 때만 보관 정책을 바꾼다.
UI 질의 잠금도3,000명 측정 후 필요한 범위에서 줄인다.

연결된 ARM64 실기기는 현재 발견되지 않았다. 사용자는 “연결할 실기기 없음”이라고 답했다.
실기기 미검증을 기록하고 개발·자동 검증과 요청한 APK 배포를 계속한다. 실제 실행하지 않은 기기 항목은 완료로 표시하지 않는다.

실행 보드는 대표 PR #32, 상태 원본은 `docs/tasks/xianxia-progress.json`이다.
신규 작업은 밸런스 XO-14와 게시 RELEASE-02를 더해14개다. 단계별 검사·근거를 붙여 갱신한다.
