## 클로드에게 전달하는 순서

1. [검토 요청문](10-claude-review-request.md)을 먼저 전달한다.
2. 전체 기획을 검토하려면 01 → 02 → 03 → 04를 읽는다.
3. 기술 검토는 05 → 06 → 07 → 08 순서로 읽는다.
4. 12의 관측을 재검증하고, 09의 후속 계획에 대해 우선순위와 수용 기준을 제안한다.
5. 코드를 읽을 수 없는 환경에서는 문서에 근거가 있는 내용만 평가하고 확인하지 못한 부분을 명시한다.

## 문서의 상태 표기

- **구현**: 기준 커밋에서 실제 코드로 확인한 동작이다. 자동 테스트나 실기기 검증의 완료를 뜻하지 않는다.
- **실측**: 명시된 입력·환경·명령으로 이번 문서 작성 또는 기존 CI에서 관찰한 결과다.
- **해석**: 코드와 장르를 토대로 복원한 의도이며 오너가 확정한 기획과 구분한다.
- **제안 / 결정 필요**: 앞으로 검토할 변경이다. 현재 기능으로 소개하지 않는다.

숫자가 주석·화면 문구와 다르면 실제 계산식을 기준으로 쓰고 차이는 12에 기록했다.
`reference/catalog.json`은 코드에서 추출한 문서용 스냅샷이며 실행 시 읽는 설정 파일이 아니다.
이 게임은 저장소 루트의 **호라경제연구실 / 1턴=1개월** 프로젝트와 별개다.
