# 11. 원본 비교·설계 결정

> 0.1.0 작성 시점의 설계·검토 기록입니다. 0.2.0 구현과 달라진 사항은 [현재 구현 기준20](20-v0.2.0-implementation.md)과 [실측19](19-balance-v0.2.0.md)를 우선합니다.

상태: 보존된 React 원본·기존 측정·현재 코드를 대조한 기록이다. 과거 작성자의 의사결정 회의록이
남아 있지 않은 부분은 **구현으로 복원한 선택**으로 표시한다. 이 문서를 소급 승인된 ADR로 취급하지 않는다.

## 1. 원본과 현재 구현의 관계

원본은 [legacy/original-app.js](../legacy/original-app.js)에 보존된 React 단일 파일이다.
현재 앱은 관찰 게임의 한국어 용어·세력·경지·양피지 시각 스타일을 이어받아 C# 코어와 Avalonia 화면으로
구현했다. 원본 저장 파일을 새 gzip JSON으로 가져오는 마이그레이션은 없다. 동일 시드도 같은 세계가 아니다.

| 영역 | 원본 측정·코드에서 확인한 점 | 현재 구현 |
|---|---|---|
| 실행 | React와 시뮬레이션이 한 소스에 밀집, Math.random 사용 | UI·순수 코어·플랫폼·도구·검사 분리, PCG 상태 저장 |
| 전쟁 승점 | 측정된 모든 승점이 첫 종문에 배정, 실제 승자와 불일치 사례 존재 | 실제 승자 진영에 점수, 회귀 검사 |
| 입문·직위 | 16세 새 인물의 고위직 배치, 남은 직위·종주 불일치 관측 | 신규는 외문/잡역, 재편 시 정원과 종주 재계산 |
| 전투력 | 원본 표본의 평균 항 비중 재능 약45%, 경지 약14% | 경지 2.8배 기준에 재능·장비 등을 곱함 |
| 성장·돌파 | 3만 년 후 반선경 약36~38%인 원본 표본, 일부 확률 .99 이상 포화 | 영기·수명·실패 손실·공법 한계 재구성, 현재 표본의 고경지 희소 |
| 좌화 | 보존 원본 보고서에는 수명종료만 집계 | 자연 좌화와 경지 붕괴 좌화를 구분 |
| 이력 | 최고 단계 필드에 경지 값이 들어간 표본 존재 | BestRealm/BestStage 구분, 범위 검사 |
| 기록 | 현재 스냅샷의 표시 종류 편중과 긴 목록 처리 부담 | 분류 누계, 최신600 링 버퍼, 연대기·상세·페이지 |
| 사건·연결 | 원본의 관찰 테마와 기록 | 시대·대회·비경·수조·경매·호칭·개입을 독립 시스템으로 연결 |
| 앱 | 브라우저 UI 원본 | 네이티브 패키지의 Avalonia UI, 기기 저장·수명 주기·아이콘·내장 폰트 |

현재 제도가 바뀌었다는 설명은 모든 밸런스·UX 문제가 해결됐다는 뜻이 아니다.
특히 후속 발견 사항은 [12](12-open-questions.md)를 따른다.

## 2. 원본 실측의 구체적 근거

[보존 JSON](measurements/legacy-30k-seeds-1-2-3.json)은 시드1/2/3·30,000틱의 도구 측정이다.
원본의 Math.random 대신 측정용 sfc32를 주입하며, 원본 파일 자체를 변경하지 않고 VM 문자열에 훅을 넣는다.
`analyze-legacy.mjs`의 기본 UI 묶음과 같은 5틱 단위 색인 재구축을 포함한다.

| 시드 | 첫 종문 승점 / 모든 승점 | 실제 승자 불일치 | 새 인물 고위직 | 잘못된 최고 단계 | 반선경 인구 |
|---:|---:|---:|---:|---:|---:|
| 1 | 6,736 / 6,736 | 3,181 | 35 | 474 | 376 |
| 2 | 6,911 / 6,911 | 3,627 | 31 | 485 | 365 |
| 3 | 6,646 / 6,646 | 3,380 | 26 | 495 | 367 |

위는 원본 계측 결과이며 새 C#의 결함으로 읽으면 안 된다. 비교 도구와 현재 회귀 검사의 의도를
설명하기 위한 자료다. 두 구현의 시간 값은 동일 환경 paired benchmark가 아니므로 속도 개선 배수를 제시하지 않는다.

## 3. 구현으로 복원한 기술 선택

| 결정 ID | 현재 선택·상태 | 근거·장점 | 비용·후속 질문 |
|---|---|---|---|
| ADR-XO-01 | C# 순수 시뮬레이션 + Avalonia 공유 UI. 구현됨, 문서상 승인 이력 없음 | Android·데스크톱·헤드리스에 규칙 공유, 코어 검사 가능 | UI 프레임워크·워크로드 의존, 실제 모바일 최적화 필요 |
| ADR-XO-02 | 1년 정수 tick와 고정 순서. 구현됨 | 고속 장기 관찰·재현·통계에 단순 | 해 내부 즉시 입력·중단·부분 실패 롤백 없음 |
| ADR-XO-03 | 공개 mutable 모델과 정적 시스템. 구현됨 | 직접 갱신·직렬화·낮은 추상화 비용 | 소유권 규약, 입력 의미 검증, 잠금 범위 검토 |
| ADR-XO-04 | 단일 저장 가능한 PCG32. 구현됨 | 같은 코드·입력으로 이어가기 용이 | 로그/관심·시스템간 RNG 결합. 스트림 분리는 미결정 |
| ADR-XO-05 | 단일 gzip JSON 슬롯. 구현됨 | 서버 없이 작고 단순한 저장 | semantic validation·백업·버전별 마이그레이션 미흡 |
| ADR-XO-06 | 컴파일된 C# 밸런스 표. 구현됨 | 타입·직접 참조·의존성 단순 | 수치 변경마다 재빌드·배포, JSON 모딩 없음 |
| ADR-XO-07 | 영석 장부와 추상 시장. 구현됨 | 생성/소멸/이전을 정수 합계로 검증 | 가격·유통·실물 보존을 완전 모델링하지 않음 |
| ADR-XO-08 | 고정 인구와 영혼/현생 분리. 구현됨 | 인구 폭증 없이 윤회 서사·장기 업적 | 영혼 기록 누적 증가, BornYear 등 의미 정밀화 필요 |
| ADR-XO-09 | 진행 스레드·세계 잠금·4Hz UI. 구현됨 | UI 전체 재생성 줄이고 동시 변경 방지 | 긴 Step·조회·압축 지연, 정지 자동 저장 공백 |
| ADR-XO-10 | 공식 서명 APK 한 개·출처 검증 게시. 이번 사용자 배포 지시로 실행 | 같은 APK 검사/재사용·업데이트 인증서 연속성 | CI secret·artifact 수명·버전 동시 갱신 필요 |

이 표에서 “구현됨”은 선택이 코드에 존재한다는 뜻이다. D-01~08에 대한 오너 결정과 실제 승인 날짜는
[09](09-requirements-and-roadmap.md)에 추후 기록해야 한다.

## 4. 저장소 공통 규칙과의 적용 경계

루트 AGENTS.md의 역할·Git·비밀정보·검사·코드 품질 원칙을 따른다. 이번 문서 작성은 사용자가
Codex에게 명시적으로 요청한 작업이다. 경제 게임의 기획·Money·월별 모델을 선협 기획으로 옮기지 않는다.

| 루트 Hora 설계 항목 | 선협 실제 상태 | 검토 시 주의 |
|---|---|---|
| 1개월 턴·경제 경영 | 1년 tick·관찰 시뮬레이션 | 제품 목표가 다름 |
| Hora.Domain·Standard2.1/C#9 | Xianxia.Simulation net10.0·현재 언어 | 타입/빌드 제약을 실제 프로젝트 기준으로 확인 |
| Money/Quantity 전용 값 타입 | 영석 long, 성장·확률 double | 실수 중간 가격 계산 존재. 현재 구현을 숨기지 않음 |
| JSON 정의 데이터·schema | 컴파일된 C# Data | 문서 catalog.json은 추출 결과이며 런타임 입력 아님 |
| 시스템별 RNG 스트림 설계 | 세계 단일 PCG | 관찰 입력·로그 순서 결합 재검토 필요 |

이 차이는 자동 예외 승인이나 새 표준 수립을 의미하지 않는다. 적용할 공통 불변식과 장르별 예외를
확정하려면 별도 ADR에 근거·대안·수용 기준을 남기는 것이 좋다.

## 5. 결정 기록에 남길 내용

제안이 채택되면 문제와 실제 예, 선택한 동작, 검토한 대안, 저장·난수·성능 영향,
승인자·날짜, 수용 증거를 함께 기록한다. 과거 소스 주석의 의도와 새로 합의한 정책이 다르면
주석·도감·문서·검사를 한 작업에서 갱신한다.
