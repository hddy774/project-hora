# 18. 대표 PR과 서브 PR 운영

사용자는 2026-10-29에 완료 PR 병합, GitHub 이슈 활용, 불필요한 이슈 정리,
다음 버전 대표 PR과 병렬 작업용 서브 PR 구성을 지시했다. 이 지시는 루트의 사람 전용 병합 제한보다 우선한다.
기존에 승인한 개발·태그·APK 최신 릴리스 배포도 계속 유효하다.

## 브랜치와 병합

- 대표 브랜치 `codex/30-release-v020`에서 `main` 대상 Draft 대표 PR을 유지한다.
- 독립 작업은 대표 브랜치에서 별도 `codex/<이슈>-<작업>` 브랜치를 만들어 서브 PR로 제안한다.
- 서브 PR의 대상은 대표 브랜치다. 선행 작업이 필요한 경우 해당 서브 PR 병합 후 최신 대표 브랜치에서 시작한다.
- CI와 명세 검증을 통과한 서브 PR은 merge commit으로 병합한다. 의존 브랜치가 같은 변경을 다시 제안하지 않도록 이력을 보존한다.
- 대표 PR은 모든 수용 기준을 확인한 후 squash로 main에 병합한다. main 직접 push는 하지 않는다.
- 최종 APK는 대표 PR 병합 후 main의 고정 SHA로 빌드·서명·에뮬레이터 검증한다.
  태그와 최신 릴리스도 같은 SHA를 가리키며 첨부물은 APK 하나다.

서브 PR별 검토 가능한 변경은 800줄 이하를 유지한다. 대표 PR은 이미 검토한 서브 PR의 집계이므로
전체 변경량 제한 대신 서브 PR 목록·수용 기준·최종 통합 검증을 제공한다.
서브 PR은 여러 개를 동시에 열 수 있으며 개수 제한을 두지 않는다. 독립 모듈은 각 브랜치·작업 폴더에서 동시에 진행한다.
선행 관계는 작업별 DAG로 관리하며 모든 작업을 하나의 직렬 체인으로 만들지 않는다.
공유 계약·저장 스키마·진행 원본은 한 조정자가 변경하고, 같은 파일 변경은 담당 범위와 통합 순서를 명시한다.
서브 PR의 CI는 pull_request에서 실행하고 main 병합은 push에서 다시 검증해 중복 실행을 줄인다.
출시 실행은 별도 동시성 그룹으로 두어 개발 검사 때문에 서명·배포 작업이 취소되지 않게 한다.

## 이슈와 진행 상태

버전 마일스톤과 대표 이슈에 작업 이슈를 연결한다. 작업 이슈는 명세, 의존 관계, 서브 PR, 검증 근거를 담는다.
진행 원본은 `docs/tasks/xianxia-progress.json`, 게시 대상은 파일의 `tracking_pr`에 지정한 대표 PR이다.
진행표 갱신은 하나의 조정 작업에서 직렬 수행한다. 서브 PR의 오래된 진행 파일로 다른 작업의 상태를 덮어쓰지 않는다.
병합 전 ID별 변경을 확인하고 대표 브랜치의 최신 상태를 보존한다.

서브 PR 병합만으로 전체 작업을 완료하지 않는다. 실제 수용 기준과 검증 증거가 갖춰졌을 때 이슈를 완료로 닫는다.
중복은 원본 이슈 링크와 함께 닫고, 폐기는 사유를 남긴다. 유효한 미해결 작업은 유지한다.
소스 변경 완료와 APK 배포 완료를 구분한다.

## 검증 한계

사용자는 연결할 ARM64 실기기가 없다고 답했다. API 24·34 에뮬레이터와 서명 APK 검증을 수행하고,
물리 기기에서만 가능한 검사는 미검증으로 기록한다. 이를 실기기 통과로 표시하지 않는다.
