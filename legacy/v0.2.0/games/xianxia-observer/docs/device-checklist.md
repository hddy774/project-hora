# Android 실기기 점검표

2026-10-29 사용자 확인: 연결 가능한 물리 ARM64 기기가 없음. 아래 실기기 항목은 미실행이다.
API24/34 x86_64 에뮬레이터 결과와 실기기 결과를 구분한다. 사용자 지시에 따라 에뮬레이터·서명·업데이트 검증 후 APK를 배포한다.

기기 모델: 미제공 / Android·API: 미제공 / ABI: 미확인 / APK SHA-256: 미기입.

| 항목 | 상태 | 메모 |
|---|---|---|
| 새 설치와 실행 | 미실행 | 실제 기기 없음 |
| 공개0.1.0 위 업데이트·저장 연도/인구/관심 유지 | 미실행 | 에뮬레이터에서 동일 인증서 APK로 별도 확인 |
| 5개 주 탭과 더보기의 업적/현황/기록으로7개 데이터 화면 | 미실행 | 기존7탭 데이터 접근 보존 |
| 인물·종문·지역·전쟁·대회·설정·도감 시트와 상세4분류 | 미실행 | 뒤로 복귀 때 검색/쪽/스크롤 유지 |
| 검색 중 IME와 입력/결과 접근 | 미실행 | 키보드 뒤로 → 시트 뒤로 → 더보기 → 천하 → 종료 |
| 시스템 글자100%·130%·200%에서 글자·48dp 조작·스크롤 | 미실행 | 화면 전체 축소 금지 |
| 제스처 하단 영역·3버튼 탐색·노치/상단 여백 | 미실행 | 루트 안전 영역 한 번 적용 |
| 기연 미리보기·취소·정상1회·잔액 부족·윤회 뒤 재확인 | 미실행 | 정상1회 천기2, 취소/거부0 |
| 수동 저장·백그라운드·강제 종료·재실행 | 미실행 | 정상본과 백업 유지 |
| 30분 연속 진행의 발열·크래시·전력 | 미실행 | 공유 Linux/에뮬레이터 시간으로 대체하지 않음 |

자동 수용은 `tools/emulator-smoke.py`를 사용한다. 각 입력 전 실제 포커스, 현재 렌더의 조작 좌표,
입력 직전 로그를 비운 뒤2초 안의 새 전환, 화면 PNG를 함께 보관한다.
런처로 이동한 상태가 반드시 실패하는 음성 대조,60초 연간 진행의 UI 전환 로그0줄,
시스템 글자 배율과 IME, 이전 공개 APK 저장을 보존한 업데이트를 포함한다.

선택적인 ARM64/x86_64 결정론 비교는 같은 빌드·시드7·인구300을 정지 상태로 시작하고 정확히1,000년 후 정지한 저장을 비교한다.
인증서·APK 해시·버전·명령/개입 순서와 두 저장 SHA-256을 기록한다. Release 저장은 보안상 `run-as`로 꺼낼 수 없으므로,
권한이 있는 테스트 기기 또는 별도 계측 빌드에서만 파일을 추출한다. 해시가 다르면 압축을 풀어 실수값과 RNG 상태를 먼저 비교한다.
현재 이 비교는 미실행이며 ARM64와 x86_64가 같다고 주장하지 않는다.
