# PC 0.0.18 수행·돌파 수직 계약

## 범위와 정본

- 사용자 확정값을 최우선으로 적용한다. 모든 대경지는 1층부터 9층·대원만까지가 한
  수행 기간이며, 선천 수행자질 종합 50.00에서 그 기간은 해당 대경지 최대 수명의
  3분의 1이다.
- Alpha 1.1.3 수행체계 종합 상세 명세의 Work, Gate, 사전검증, Attempt Snapshot,
  Typed Result, 안착과 `삼도축기요결` 5단계 계약을 PC 권위 상태로 이식한다.
- 승인되지 않은 수치나 효과는 승인값처럼 사용하지 않는다. 필요한 임시 수치는 아래
  `PC_TEMP_REVIEW` ID와 revision을 가진다.

## 권위 계약

- `World.Cultivation`만 수행 상태를 변경한다. Work 축적, 돌파 준비, 사전검증,
  확률 시도, 결과와 안착은 서로 다른 월 행동 경계다.
- `RealmRules`의 9개 층 가중치 합은 1,000이다. 기준 월 Work 1,000일 때 각 대경지의
  총 Work는 `최대 수명 × 4 × 1,000`이고, 12개월 기준 정확히 최대 수명의 1/3년이다.
- 일반 층, 3→4·6→7 병목, 9층 완성, 대원만, 대경지 돌파를 별도 Typed Attempt로
  다룬다. 일반 이월은 전부, 병목 이월은 25%, 9층과 대경지 이월은 0이다.
- 표시 확률은 승인된 Concrete Attempt Effect만 반영한다. 현재 승인 Effect 정의는
  0개이며 미등록 후보는 `Unapproved`로 표시하고 확률을 바꾸지 않는다.
- 승인 실패 효과가 없으므로 실패는 `CleanFailure`다. 숨은 Work·구성요소·자원 손실,
  부상, 육신 상실과 전역 재시도 대기는 모두 확정 0으로 기록한다.
- `ActualZero`, `NotCalculated`, `NotApplicable`, `Unavailable`, `Unapproved`,
  `Blocked`를 구분해 0과 미구현·미승인을 혼동하지 않는다.

## 공법·환경·삼도축기요결

- 월 Work는 선천 수행자질 종합, 공법 품질, 현재 지점의 영맥 환경, 육신 상태와
  명시적 임시 효과를 순서대로 적용한다. 영맥 품질은 지점별 캐시를 사용하며 공급이
  소진된 지점만 다시 계산한다.
- 연기→축기 사전검증은 공법 내용 존재, 숙련 5.00, 이해 5.00과 실제 Source 가용성을
  확인한다. 두 수치는 장기 정체 회귀를 막기 위한 임시 calibration이다.
- 삼도축기요결은 성취 수렴 → 경로 결박 → Source 정렬 → 형성 시도 → 결과 확정의
  5단계를 가진다. 인도는 육신·영근, 지도는 현재 지점 영맥, 천도는 고품질 산맥의
  현현 또는 제2층천 환경을 Source로 사용한다.
- 성공 시 경로·Source 종류·Location Ref·Atlas revision·동결 tick·가용성과 당시
  잔여 공급을 불변 Snapshot으로 저장한다. 축기 형성 결과는 10개 품질 요소와 함께
  state hash, schema 25 payload, query와 UI까지 연결된다.
- 대경지 돌파 뒤에는 최소 한 번의 안착 평가를 수행한다. 구성요소 평균 30.00 미만이면
  안정화 행동을 계속하고 기준에 도달해야 `Stable`이 된다.

## 관찰 UI와 스크롤 정책

- 인물 상세는 `개요·행동`, `수행·자질`, `전투·장비`, `관계·기억`, `기록·윤회`
  내부 탭으로 분리하고 현재 탭의 DTO·문구만 갱신한다.
- 수행 탭의 Formula Trace와 축기 형성 결과는 접힌 동안 계산하지 않는 토글이다.
  토글 내용은 일반 레이아웃이며 내부 `ScrollViewer`를 두지 않는다.
- 통계는 요약·랭킹 변동·분포, 도시는 재정·거래·임무·생산·광맥·재고 내부 탭으로
  분리한다. 지도와 시장의 짧은 상세 탭에서도 중첩 스크롤을 제거했다.
- 기록, 수선자 100명 페이지, 시장 거래처럼 목록 자체를 탐색하는 경우에는 가상화된
  스크롤을 유지한다.
