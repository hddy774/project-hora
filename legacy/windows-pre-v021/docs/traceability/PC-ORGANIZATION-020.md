# PC 0.0.20 조직·세이브·로그·지리 수직 계약

## 사용자 확정 계약

- 모든 신규 자동·수동 로그는 종류와 인물별 폴더에 분리하고 파일당 정확히 5MiB
  (`5,242,880`바이트) 이하에서 회전한다. 기존 루트 로그는 이동·수정·삭제하지 않는다.
- 세이브는 `default`, `slot-02`~`slot-09`의 고정 9개 카드로 제공한다. 기존
  `world.cmip`은 호환 불가로 표시할 뿐 읽거나 바꾸지 않는다.
- 종문·가문·왕조는 공통 Organization Core를 사용하며 종류별 활성 소속 하나씩을
  허용한다. 서로 다른 종류에는 동시에 소속될 수 있다.
- 하천대륙은 10×10 주 타일이고, 현재 상세 구현 주는 오천주 한 곳이다. 오천주는
  제1·2층천 각각 10×10 지점을 가지며 두 층천은 같은 물리 좌표의 다른 세계 묘사다.

## 권위·명령·저장 계약

- `OrganizationStore`가 안정 Organization ID, 종류·상태, 창시자·지도자, 구성원·역할·
  충심, 영석, 실제 Atlas 권리, 외교, 전략축과 조직 전용 역사를 소유한다.
- 창설·가입·탈퇴·역할·충심·재정·외교·분열·병합·해산·윤회 재연결은 typed
  `OrganizationCommandResult`로 성공/거부를 반환한다. 실패 전이는 권위 상태를
  부분 변경하지 않는다.
- 지도자 사망은 결정론적 승계 점수로 후계자를 선택한다. 후보가 없으면 공석→쇠퇴→
  해산으로 진행한다. 동일 Soul 재연결은 명시적 전이에서만 허용한다.
- 내부 checkpoint schema 26은 조직 권위와 역사를 상태 hash에 포함한다. schema 25는
  빈 조직 상태로만 26에 이식한다. UI용 집계·필터·행 cache는 저장하지 않는다.
- 외부 WorldSchema는 25를 유지한다. 슬롯 manifest v2의 카드 요약은 같은 safe boundary의
  비권위 표시 정보이며 `world.db`가 정본이다. manifest v1도 읽되 관찰만으로 다시 쓰지 않는다.

## 성능·관찰 계약

- 조직 후보는 현재 위치·희소 관계·혈통·현재 소속 index와 결정론적 분산 cursor로
  제한한다. 인물×조직 전수 비교를 하지 않는다.
- 조직·저장 화면과 내부 상세 탭은 보일 때만 query와 행을 만든다. Desktop은
  Application/Queries의 불변 DTO만 사용한다.
- 9개 세이브 카드 목록은 manifest와 SQLite header만 검사한다. 자동 회귀에서 80회
  p95 50ms 예산을 강제한다.
- 개인 자동 로그는 사용자가 켠 인물만 기록한다. 성능·상태 표본과 개인 최근 로그는
  메모리에서 최근 100개까지만 유지한다.

`DataUnavailable`로 표시한다.

## 후속 이식 경계

M09의 전승/서적 연결, 별도 사회 자질, 가문 준비집단→정식 승격, 왕조 존속 조건 재검증,
10,000명 조직 분포/성능은 아직 `Gap/Deferred`다. M11~M12 콘텐츠·서적 권위를 만든 뒤
연결해야 하는 요구를 0.0.20 완료로 주장하지 않는다.

## 자동 검증 진입점

- `조직 Core·창설 Gate·중복 소속·승계·병합·schema 25→26`
- `schema 25→26 SQLite 다중 슬롯·후보 원자 복원`
- `모든 로그 파일 5MiB 상한·기존 part 재검사·UTF-8 분할`
- `로그 종류·자동 수동·인물별 출력 경로 계약`
- `하천대륙 10×10 주·오천주 1·2층천 10×10 지점`
- `관찰 조회 무영향`
- `활성 UI 구역 선택 조회 성능`
