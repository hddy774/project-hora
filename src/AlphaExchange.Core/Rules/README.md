# 투자자 전용 시장 규칙

`institution-v1.json`과 `market-v1.json`은 앱에 포함하는 오프라인 데이터다. C# 엔진이 범위를 검증하고 시장별 사본을 저장한다. 설정 변경은 새로운 시장부터 적용한다. 실행 중 네트워크·외부 AI API를 사용하지 않는다.

| 파일·영역 | 역할 |
|---|---|
| `CompanyCatalog.cs` | 기술, 산업·에너지, 바이오·헬스, 금융, 소비·미디어의 업종별 3개, 총 15개 고정 슬롯 |
| `market-v1.json` | 1조 시총, 기관별 10억, 개미별 5천만, 개미 10,000명, 결제 계정 초기 자금, 분석 주기와 개미 주문 반응 |
| `Representative` / `Rewards` | 투자자의 10개 초기 능력 50점, 100점 상한, 성과에 따른 포인트 배분과 신용 보너스 |
| `Horizons` | 초단기 1~23시간, 단기 24~239시간, 장기 240시간 이상; 가치·추세·뉴스·배당 분석 가중치 |
| `Investment` | 현금 목표 5~30%, 종목·업종 한도, 주문 크기, 손실·대출·공매도 판단 |
| `Performance` | 틱·화면 간격, 한 작업의 처리 시간 예산과 작업 분할 크기 |

기관은 공개 가격·실적·뉴스·호가와 개미의 추세 반응으로 15종목의 목표 비중을 함께 계산한다. 목표 합계와 현금 목표가 하나의 예산 안에 들어가며 종목·업종 상한도 적용한다. 신규 매수는 대기 주문의 현금·종목·업종 예약을 포함한다. 손절·익절·기한·예상 비용·확신도·손실 예산을 계획에 저장하고 약 15~30분마다 재평가한다. 판단 횟수가 늘어도 작은 비중 변화마다 매매하지 않는다.

매집 → 추격 수요 유도 → 분산 매도 → 철수의 단계는 기관마다 보유 자금·주식·시장 반응에 따라 진행된다. 수익 보장은 없으며 공매도도 실제 대여·담보가 필요하다. 개미는 가격·시장 추세·공개 뉴스만 사용한다. 실적·내부 계획·개인 매입가를 매매 신호로 사용하지 않는다. 초기 및 교체 상장의 주식 배정은 실제 납입이며 체결가·거래량을 만들지 않는다.

경영자·정치인·금융인·직원 AI와 선거·투표·고용·사업 프로젝트를 제거했다. 은행의 자동 호가도 없다. 기업·정책·금융·업종 이벤트는 시드 난수에 따라 90~360분 간격으로 발표되어 심리·매출 환경·금리·정책을 바꾼다. 월말은 회계 결산이며 기업행동은 별도 무작위 사건으로 선택한다. 주가는 호가 체결로 결정한다. 배당락·분할·합병은 거래 가격 변동과 구별되는 회계상 기준 조정이다.

상태 형식은 9, SQLite/현행 백업 형식은 6이다. 30종목 구형 저장은 `history-v5.sqlite` 등 원래 파일에 그대로 보관한다. 현재 엔진이 구형 배열을 임의로 재배분하지 않는다. 로비와 기록 화면에서 이전 원본·WAL·체크섬 목록을 ZIP으로 내보낼 수 있으며 이 보관본은 현행 시장 복원 파일과 다르다. 앱 삭제 전에 내보낸다.

규칙 변경 후 버전과 계획을 갱신하고 `dotnet run --project tests/AlphaExchange.Checks -c Release -- --design-only`, 전체 게임 검사, Android 네이티브 검사를 실행한다. `MaximumCatchupHours`는 수락 시간의 폐기 한도가 아니라 작업 분할 크기다. Android 작업자는 매 분 잠금을 반환하며 이력과 대기 시간을 모두 보존한다.
