# 기관 규칙 스크립트

`institution-v1.json`은 앱에 포함하는 오프라인 데이터 스크립트다. Python/외부 API 없이 C#의 검증된 실행 엔진이 값을 읽는다. 새 시장은 파일 전체를 복사하여 상태 JSON에 보관한다. 기존 시장은 저장된 규칙으로 이어져 이후 파일 조정이 실행 도중의 투자 기간·보상·급여를 바꾸지 않는다.

조정 후 `Version`을 갱신하고 `dotnet run --project tests/AlphaExchange.Checks -c Release -- --v16-only`와 전체 회귀를 실행한다. 알 수 없는 필드·잘못된 범위·누락된 보상 단계·단일 S급 직원이 대표보다 높은 기본 능력·잘못된 기간 경계는 읽기 때 거부한다. 재배포에는 앱의 minor 버전도 올린다.

| 영역 | 값의 뜻 |
|---|---|
| Representative | 같은 초기 점수/100점 상한, 기관 능력에 대표가 미치는 비중, AI 포인트 배분 우선순위, 신용 보너스 상한/유지율 |
| Rewards | 순위 오름차순으로 해당되는 첫 단계 하나만 적용. 1/2/3/5/10/20/30/40/50위 구간의 능력 포인트·신용 보너스 |
| Employees | S/A/B/C/D의 기본 능력·월급·채용비, 인원 상한·월 급여 예산, 전문 역할 외 공통 기여, 조직 기본 운영과 팀 한계 효용 |
| Horizons | 실제 보유 기간 분류: 1~23h/24~239h/240h 이상. 계획 기간별 재평가·주문 유효기간·예상 보유/회전 비용·가치/추세/뉴스/배당 가중치. 최대 보유 기간에 따른 강제 매도 없음 |
| Investment | 현금 목표의 5~30% 경계, 성향·위험 보정, 종목/산업 한도, 주문 크기·급한 집행·상환/공매도/뉴스 재판단 |
| Liquidity | 실제 은행 현금 완충·호가 수·잔량·스프레드·재고 편향. 고평가 기준/매수·매도 할인과 급락 시 매수 스프레드. 실제 주식/자금 범위 안에서만 주문 |
| Performance | 시뮬레이션 틱, 화면 갱신 간격, 처리 대기 상한과 한 틱의 시간 예산. 입력·스크롤은 즉시 다시 그림 |

기관 능력의 각 항목은 `대표 × 0.5 + 조직 × 0.5`다. 조직 항목은 `기본 운영 + (상한 − 기본 운영) × 역할별 인력 / (역할별 인력 + 포화 계수)`다. 전문 역할 인력은 직원 등급 능력 × 인원, 다른 역할은 `OtherRoleWeight`만큼 기여한다. 같은 인원이라도 역할 구성이 다르면 능력이 다르고 인원이 늘어도 효과가 무한히 선형 증가하지 않는다.

기존 v2~v6는 금융 잔액·실소유 주식·확정 원기록을 유지한 채 v7 상태로 이전한다. 이전 대표의 원래 능력은 `LegacyAbilities`에 보관하고 성장 포인트/직원은 새 체계부터 적용한다. 과거에 주지 않은 시즌 보상·기록이 없는 매수 시점은 만들어내지 않는다. DB/ZIP 형식은 기존 5의 확장을 사용한다.

## v1.7 인물·경제 규칙

`world-v1.json`은 초기 시총/자금, 개미 집단 수/유입 재원,200명 이름·직무별 능력명,8가지 직원 직무 가중치,6분야 분석 주기,투자 기간/가격 범위,사업 단계/투자 비중,선거 간격,3가지 정책 대안,시즌1~10포인트와 종합 점수 비중을 정의한다. 게임 상태에는 검증된 사본을 저장한다.

신규 시장은1조 시총·투자사10억·개미1000집단에서 출발한다. 구형 저장은 초기 투자/개미 자산의 중앙값으로 향후 재출자 규모도 보존해 작은 기존 시장에10억 재출자를 갑자기 적용하지 않는다. 기존 은행 호가 크기와 금융 장부는 유지하고 새 개인 지갑은0원부터 보수를 받는다. 상태 버전8은 버전2~7 및 초기v8 행 저장을 읽으며, 개미 저장은 `retail-columns-1` 열/희소 배열 형식이다.

Performance의MaximumCatchupHours는 `AdvanceFrame`의 한 작업 분할 크기이며 받아둔 시간의 폐기 상한이 아니다. Android는 화면에서 시간을 큐에 넣고 별도 작업자가 상태 잠금을 분마다 해제하며 실행한다. 자동 저장 준비도 작업자에서 수행하고 쓰기는 순서대로 처리한다. 완료 시간 통계와 분 대기는 생략하지 않는다.
