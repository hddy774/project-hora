# 저장·시뮬레이션 성능 측정

```sh
dotnet run --project tools/PerformanceAudit -c Release -- baseline /tmp/baseline.json
dotnet run --project tools/PerformanceAudit -c Release -- optimized /tmp/optimized.json
dotnet run --project tools/PerformanceAudit -c Release -- --client /tmp/client.json
```

`--client`는 500점 차트 1,000회와 순위 계산 100회의 플랫폼 공통 CPU·관리 메모리 할당을 측정한다. v1.8 알고리즘을 측정 도구 내부의 참고 구현과 비교하며, 게임 코드에서는 Core의 단일 순위 계산을 사용한다. 실제 Android Canvas/Path·Bitmap 네이티브 메모리·FPS·배터리는 이 결과에 포함하지 않는다. 새 제네릭 정렬/버퍼의 계층 JIT도 준비되도록 각 경로를 최소500ms 워밍업하고 11개 시간·할당 표본을 기록한다.

같은 Linux/.NET Release 환경, 시드 20261004, 168시간 진행한 15개 회사/100개 기관/10,000명 개미으로 재무 집계·저장 준비·직렬화·쓰기 시간과 현재 스레드 할당량을 측정한다. 워밍업/강제 수집 후 9회(쓰기/범위/누락 검사는 5회)의 중앙값·최대값과 시간 원본 표본을 JSON으로 기록한다. 캐시 재조회가 아닌 실제 집계 비용을 재기 위해 측정 시 `cachedStats`만 비운다.

720시간 시뮬레이션의 총 처리 시간·분/초·p50/p95/p99와 실제 매칭 수를 기록한다. 장기 조회 데이터는 경제 시뮬레이션과 구분한 합성 5년(360일/년)의 시간별 원기록 43,201행이다. 720행씩 원자적으로 저장하고 500점 이하의 최초 조회(캐시 비움)와 반복 조회·경계·누락 검사와 원본 파일 크기를 확인한다. 실행 종료 시 임시 DB를 지운다.

`prepareSave`는 저장용 상태 분리 비용이며 실제 JSON 인코딩/디스크 완료 시간이 아니다. `writeSnapshot`에는 상태 준비·인코딩·압축·검증·트랜잭션을 포함한다. 현재 스레드 할당량은 프로세스의 최대/상주 RAM이 아니다. 운영체제 스케줄링, GC와 JIT 때문에 시간에 변동이 있으므로 모든 지표와 표본을 함께 기록한다. 물리 Android FPS/메모리 성능으로 해석하지 않는다.

현재 도구는 세 번째 인자로 고정 저장 상태 경로, 네 번째 인자로 상태 출력 경로를 받습니다. v1.5 비교는 v1.4 커밋에서 만든 동일 168시간 상태를 두 버전에서 읽어 집계/저장을 측정합니다. 세 번째 인자가 없으면 각 버전의 새 시장으로 168시간 진행합니다. 고정 입력을 제공하면720시간도 같은 체크포인트에서 시작하며 최종 전체 상태의 SHA-256을 기록합니다. 합성5년은 거래 성능과 구분한 저장 전용 시나리오입니다. [v1.5 결과](../../docs/performance/v1.5.0/README.md).

고정 입력을 읽는 경우 측정 대상과 별개의 새 엔진을 168시간 진행해 양쪽의 동일 경로를 워밍업합니다. 입력을 읽지 않고 생성하는 경로와 단순 복원의 JIT 워밍업이 달라 생길 수 있는 비교 오차를 줄입니다. 체크포인트의 인코딩 바이트 수도 기록합니다. v1.5 최종 준비 단계의 0 배열 검사는 SIMD 바이트 스캔을 사용합니다.

v1.10의 새 시장은 기본 10,000명이다. 구형 시장과는 저장/게임 규칙이 다르므로 같은 체크포인트를 양쪽에서 읽지 않는다. 참가자 수·초기자금을 맞춘 시나리오 비교 조건을 결과에 명시한다. 같은 버전 내 최적화는 네 번째 인자로 저장한 고정 상태를 다시 제공해 비교한다. `fiveYearRangeCold`와 `fiveYearRangeCached`는 별도 지표이며 캐시 조회 시간을 최초 SQL 조회와 혼동하지 않는다.

`recorded100x`는 가상36초×100배속의43200게임분을 수락하고 대기 시간을 모두 처리한다. 시간별 기록 생성과20게임시간마다 실제 저장을 포함한다. 완료 분/대기0/시간별 전체 범위의 연속성이 맞아야 통과한다. 실제 총 처리량은 UI 프레임/휴대전화 기한의 보장이 아니며 엔진만의 처리량과 구분한다. [v1.7 결과](../../docs/performance/v1.7.0/README.md).

현재 도구는 시장 RunId를 고정해 같은 버전의 반복 실행 해시를 비교할 수 있다. 시뮬레이션 출력에는 종목 수와 총 포트폴리오 재평가 횟수도 포함한다. 다른 버전의 규칙 변화는 같은 시드여도 다른 난수 경로와 결과를 만들므로 속도 수치만으로 AI의 수익성이나 지능 배수를 주장하지 않는다.
